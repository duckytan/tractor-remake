# 24 · AI 逻辑三版对比（原版 tractor / smallnest / 我们）

> 原版 = `tractor/tractor.exe`（PE 逆向，结论见 docs/12 §3.6）；
> smallnest = `reference/smallnest-Tractor`（C# 复刻，**逻辑照抄原版**，可直接读源码）。
> 我们 = `src/ai/policy.ts` + `src/ai/enumerate.ts`。
>
> 结论先说：**原版系是「决策树专家系统」，我们是「打分优化器」。**
> 差别不在谁更先进，而在原版系把人类经验逐条写死，我们把选择权交给候选集 ——
> 而我们的候选集太窄，这才是弱的原因。

## 1. 两种形态

### 原版系：按局面分支的决策树

```
ShouldSendCards（首出）            ShouldSendedCardsAlgorithm.cs
  ① 副牌有拖拉机？        → 出（带 2 张配牌 = 甩牌）
  ② 副牌有最大的对？      → 出（能甩就甩）
  ③ 有单张最大的牌？      → 出
  ④ 对家那门有最大的牌？  → 出该门最小的一张（递牌给队友）
  ⑤ 没有副牌可出？        → 调主（用主牌逼）
  ⑥ 还不能调主？          → 随便出一张非分副牌
  ⑦ 全剩主牌 + 分副牌     → 特殊处理

MustSendCards（跟牌）              MustSendCardsAlgorithm.cs（2554 行）
  先按「第几家出牌」分三个入口：
    WhoseOrderIs2 / Is3 / Is4
  每个入口内部再按 位置 × 缺不缺门 × 张数 × 对子数 × 能不能毙 分派到：
    SendOtherSuitNoScores / SendOtherSuitOrScores / SendOtherSuit
    SendThisSuitNoScores  / SendThisSuitOrScores  / SendThisSuit
    SendMasterSuitNoScores / SendMasterSuitOrScores / SendMasterSuit
  每个分支**直接指定出哪张牌**，不比较、不打分。
```

特征：
- **按位置分别设计**（第 2 家 / 第 3 家 / 第 4 家是三个独立入口，因为信息量不同）
- **每个分支只处理一种情况**，命中就 `return`
- 有 `protectPairs` 参数控制「别拆对子」
- 首出会甩牌（拖拉机 + 配牌）
- 首出会「递牌给队友」

### 我们：候选 + 特征 + 线性加权

```
enumeratePlays → 最多 60 个候选
  ├─ 首出：单张 / 对子 / 连对          ← 没有甩牌
  └─ 跟牌：最小的 / 最大的 / 只跟对子  ← 只有 2~3 个
scoreCandidate → 线性加权求和 → 取最高分（并列随机）
```

特征项：省牌、能否吃分、队友领先别抢、会不会被反压、赢墩分溢价、
主牌控制力损失、续庄溢价。

## 2. 逐项对比

| 维度 | 原版 / smallnest | 我们 |
|---|---|---|
| 决策形式 | 决策树，每支直接指定牌 | 线性打分，候选里挑最高 |
| **跟牌候选数** | 按 9 种情况各有一支，实际覆盖几十种出法 | **只有 2~3 个** |
| **甩牌（首出）** | 有：副牌拖拉机 + 配牌甩、最大对 + 甩 A | **完全没有** |
| **埋底** | 3 种策略，核心都是**扣绝一门**（制造缺门） | 按牌力扣最弱 8 张 |
| **亮主** | 级牌为 2/10/K/A 时见级牌就亮；否则要求「该门级牌数 > 该门平均张数」 | 持级牌 + 该门 ≥3 张 + **100% 必抢** |
| **反主** | 持该门**一对**级牌，且该门级牌数 > 四门平均 | 新主花色 **≥5 张** 就反 |
| **团队配合** | 首出时逐门检查「队友是不是有该门最大牌」→ 有就出小牌递过去 | 只有「队友已领先时我别抢」一条被动信号 |
| 前瞻（会不会被压） | 无。只看当前这一手 | 有：L2 比牌力、L3 看结构 + 看出牌顺序 |
| 信息假设 | 完美信息（能读别家手牌） | 完美信息（同） |
| 搜索 | 无 | 无 |
| 可标定 / 可测 | 无（阈值写死在 if 里） | 有权重常量 + 座位互换配对测量 |

## 3. 原版系做对了什么

### 3.1 埋底扣绝一门（而不是扣最弱的牌）

`Algorithm.Send8Cards`（Algorithm.cs:366）先统计四门副牌张数，
然后按 `BottomAlgorithm` 配置走三种策略：

- 算法 1：**扣绝一门**（把某门副牌扣光）
- 算法 2 / 3：扣「副牌张数最少的那门」

制造缺门是拖拉机埋底的第一原则 —— 缺门才能用主牌毙牌。
我们的做法（按牌力扣最弱 8 张）会：
- 把一门扣得七零八落但**不绝门**，等于白扣
- 把 5/10/K 这类低牌力的分牌扣进底牌 → 闲家拿末墩**翻倍**，主动送分
- 拆散对子结构

### 3.2 首出递牌给队友

`ShouldSendedCardsAlgorithm` 第 ④ 段：逐门检查
「对家在这门有没有最大的牌（另两家都比不过）」，有就出**该门最小的一张**。

这是**主动配合**：知道队友那门绝对大，就送他一手，让他继续首出。
我们只有「队友已经领先了别抢」，是**被动**的。

### 3.3 跟牌按位置分入口

第 4 家是最后一家，信息最全（知道前三家都出了什么），策略也最激进；
第 2 家信息最少，策略最保守。原版把三个位置写成三个独立函数。

我们的 `enumerateFollows` 完全不区分位置 —— 三个位置用同一套候选。

### 3.4 缺门时明确考虑毙牌

`WhoseOrderIs2` 一开头：`myTotal == 0`（缺门）时，分「单张 / 对子 / 甩牌」三种
情况判断「我的主牌能不能毙过当前最大」，能就毙。

我们的候选生成**不区分「毙牌」和「垫牌」** —— 缺门时垫牌候选只是
「从其他花色补最小的」，毙牌能不能赢靠打分里的 `canIWin` 事后判断，
而且候选里可能根本没有「用主牌毙」这个选项（`asc` 排序后补最小的，
主牌牌力最高反而排在最后）。

## 4. 我们做对了什么

### 4.1 前瞻（原版系完全没有）

原版系只看「这一手」，不考虑「我出完之后会不会被压」。
我们的 L2/L3 会判断，而且 L3 还能看结构（对子压不了单张）、
看出牌顺序（已经出过牌的人不再是威胁）。

### 4.2 可标定、可测量

原版系的阈值（比如「该门级牌数 > 平均」）是拍脑袋写死的，无法验证。
我们的权重是常量 + 座位互换配对测量，改一个数就能跑 600 次看净胜率。

### 4.3 框架通用

加一个特征只要在 `scoreCandidate` 里加一行；原版系要改决策树，
每加一条规则都可能和已有分支冲突（2554 行里已经很难改）。

## 5. 差距定位

**我们的问题不是选错了范式，而是候选集没做全。**

打分器要发挥威力，前提是「所有合理选择都在候选里」。现在：

- 跟牌候选只有「最小」「最大」两个 ⇒ 手里 4 张同花色跟 1 张，
  中间两张永远出不来
- 首出没有甩牌 ⇒ 整类战术缺失
- 缺门时没有「用主牌毙」的候选 ⇒ 想毙也选不到

**在这三处补齐之前，调任何权重都不会有质变** —— 因为选择空间本身是残缺的。
这也解释了为什么 L3 只比 L2 强 6%：两档在同一批残缺候选里挑，
打分再准也拉不开差距。

## 6. 可以借鉴 / 不该照抄的

### 值得借鉴

| 项 | 理由 |
|---|---|
| **埋底扣绝一门** | 制造缺门是硬道理，与决策范式无关 |
| **首出递牌给队友** | 团队配合的关键一环，我们现在完全缺 |
| **跟牌按位置分策略** | 第 4 家信息最全，应该更激进；我们可以做成「候选权重按位置调整」 |
| **缺门时优先考虑毙牌** | 我们的候选生成漏了这一整类 |

### 不该照抄

- **决策树本身**：2554 行 if-else，加一条规则就可能与已有分支冲突；
  而且它没有前瞻、没有可标定性
- **写死的阈值**：`该门级牌数 > 四门平均` 这类判断无法验证优劣
- **smallnest 自己的 8 处 bug**（见 docs/12 §4）：比如首出检查队友时
  `max3 = currentPokers[2].GetMaxCard(i)` 把下标 2 写了两遍（应为 3）

## 7. 一句话结论

原版系把「人类怎么打」逐条写成 if-else，覆盖得全但无法进化；
我们是「给候选打分」，框架能进化但候选没做全。

**下一步该做的是把候选集补成「人类会考虑的所有出法」，而不是照抄决策树。**
