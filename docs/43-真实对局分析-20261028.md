## 4. 结论

1. **两边水平接近，没有哪一方系统性更强。** 34% 分歧里，能判定的 31 手是 **AI 5 : 你 3**，
   差距集中在 5~15 分（一副牌满分 200）。打平 23 手说明**大部分分歧其实无关紧要**。
2. **分歧几乎全在「首出」和「对方领先时的跟牌」**（46/54）。跟牌且我队领先时只有 8 次分歧 ——
   说明「队友赢着怎么垫」这类判断你和 AI 基本一致（这也是 1.3.37 修过的那块）。
3. **AI 的首出偏好和你不同**：它更愿意出**对子/拖拉机**（局4 ♠7♠7、局7 ♣5♣5、局5 ♠6♠6），
   你更愿意出**单张大牌**（♠A、♣K、♣A）。推演里各有胜负 —— 这不是谁对谁错，
   而是**风格差异**（AI 偏爱"一手出完多张"，你偏爱"先兑现大牌控场"）。
4. **你 63% 胜率 + 场均闲家 92 分**：这个数字现在可以拿去跟后续版本比了（这就是"人类锚"的第一格刻度）。

## 5. 数据质量问题（下次导出前要知道）

| 现象 | 影响 | 处置 |
|---|---|---|
| 悔牌会留下多次尝试（同一墩 2~4 条） | 原始 169 条里 11 条是废记录 | 分析脚本按「与最终出牌一致的最后一条」去重 |
| 23/54 手无法推演判定 | 样本只剩 31 手 | 推演用 L3 打到底，若中途出牌被拒/未收敛就跳过 |
| 用 `seed` 重放会错（8 局里 3 局庄家/主牌不同） | 早期版本判定为 0 手 | 改为**用日志直接重建**（手牌+底牌+主牌+庄家都在日志里） |

> `seed` 只能重现"发到手的牌"，重现不了"谁坐庄、亮什么主" —— 那是当时的决策结果。

## 6. 附：网上有没有类似的真实对局数据？（2026-10-28 检索）

**结论：这个玩法没有公开牌谱数据集。**

| 来源 | 有吗 | 能用吗 |
|---|---|---|
| 升级 / 拖拉机 / 双升 牌谱数据集 | ❌ 没有 | — |
| 掼蛋开源项目（如 `zdhgg/Guandan-training`） | 有**项目**、无公开数据集；有博客提到「从线上平台获取匿名牌谱」（爬取，非公开） | 规则不同（掼蛋 = 跑得快 + 升级），不可直接迁移 |
| 桥牌公开牌谱（BBO vugraph / 世界赛 lin·pbn） | ✅ 大量、真人、高质量 | **玩法不同**（固定将牌、明手、叫牌），只能借「评测方法」不能借「数据」 |
| RLCard / Botzone（斗地主·麻将） | ✅ 有对局 | 玩法不同 |
| 原版 `tractor.exe` 存档 | ✅ 本机就有 `Game.dat`（200B 定长）/ `Game.sav` | 只是**单局状态**，不是多局牌谱；且是 AI 打 AI |

**为什么没有**：
1. 平台闭源（联众 / JJ / 多乐都是客户端，无开放 API 与真人池）
2. **规则地方化严重**（2 是否常主、甩牌怎么裁、连对多长）⇒ 就算收集到，口径也不统一
3. 学术关注度低（远不如斗地主 / 麻将）

**所以我们的数据只能自己积累** —— 而这恰恰是最稀缺的那种：**同一套规则 + 真人决策 + 可复盘**。

> 样本量提醒：8 局 5 胜 = 63%，但 95% 置信区间约 **[25%, 85%]** —— 与 50% 无法区分。
> 「胜率」要 30 局以上才有意义；「分歧率」（34%）这种逐手统计 8 局已够用（±8%）。
