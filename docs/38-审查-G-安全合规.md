## 1. 方法与证据边界

| 项 | 值 |
|---|---|
| 运行时 | Playwright Chromium（headless），本地 preview `127.0.0.1:4173` |
| 采集内容 | 全部网络请求、`localStorage` 实际内容、断网重放、存档篡改、SW 缓存 |
| 静态 | `grep` 全库扫危险 API + `git ls-files` 核对跟踪范围 |

### 威胁模型（先说清楚，否则会把风险判过重）

这是一个**纯前端单机游戏**：没有账号、没有服务端、不采集任何用户数据。
`localStorage` 只有本域可写 —— 攻击者要能篡改它，本身就得先有同源执行能力（另一个 XSS、恶意扩展、或用户自己开控制台）。

所以下面 G-1 的**实际风险是低的**，但它仍然是**代码级缺陷**：任何「状态里的字符串被拼进 `innerHTML`」都是同一个坑，将来只要新增一个用户可输入字段（玩家昵称、房间名）就会立刻变成真漏洞。

## 2. 发现清单

### G-1 [P1] 状态值直接拼进 `innerHTML`：篡改存档可执行任意脚本

**现象**：把 `localStorage['tractor.state.v1']` 里的数字字段改成 `<img src=x onerror="window.__XSS__=1">`，刷新后**脚本真的执行了**。

**证据**：
```bash
node .tmp/g-audit/audit.mjs   # → .tmp/g-audit/evidence.json + p3-tamper.png
```
```json
"inject": { "ok": true, "injected": ["round","tricksDone","defenderScore","bottomScore","levelRank"] },
"xss":    { "flag": true, "imgInDom": 4, "rawPayloadInHtml": true }
```
- `flag: true` = `window.__XSS__ === 1`，脚本执行成功
- `imgInDom: 4` = DOM 里真的插进了 4 个 `<img src="x">`
- `rawPayloadInHtml: true` = `#app` 的 innerHTML 里能看到未转义的 `onerror`

**根因**：`src/ui/render.ts:273` 起的模板字符串把状态值直接内插，例如
```ts
<span>第 <b>${s.round}</b> 局</span>
<span>闲家得分 <b>${s.defenderScore}</b> / 200</span>
```
`round` / `defenderScore` / `tricksDone` / `bottomScore` / `levelRank` 都是「理论上一定是数字」的字段，**但没有任何地方保证这一点** —— 存档加载时不做类型校验（见 G-3 与 `docs/33` C 维度的 `loadState` 结论）。

**第二个向量（未成功，但值得记录）**：把牌对象换成 `{id:'<b id="PWN">x</b>', suit:'S', rank:2}`，结果是 `pwn: 0, handCards: 0` —— 没注入成功，但**手牌一张都没渲染出来**，说明这条路径直接崩在更早的地方。

**建议修法**（两层，都要）：
1. **入口收口**：`loadState` 对所有标量字段做类型 + 范围校验（数字字段必须 `typeof === 'number' && Number.isFinite`），不合法就整份丢弃回落 `emptyState()`。这同时解决 G-3 与 C 维度的存档问题。
2. **出口兜底**：加一个 `esc(v)` 工具（`String(v).replace(/[&<>"']/g, ...)`），所有模板内插一律过一遍。**不要只依赖入口校验** —— 现在有 16 处 `innerHTML =`，将来一定有人忘记校验。

**验收断言**：把 `round` 改成 `<img src=x onerror=...>` 后刷新，DOM 里不出现 `img`，且 `window.__XSS__` 为 `undefined`。

### G-2 [P2] 项目没有 LICENSE 文件，但仓库是 public

**现象**：仓库根目录与 `docs/` 下都没有任何 `LICENSE` / `COPYING`。`package.json` 也没有 `license` 字段。仓库地址 `github.com/duckytan/tractor-remake` 是 **public**。

**证据**：
```bash
ls -1 | grep -i licen          # 无输出
ls -1 docs | grep -i licen     # 无输出
git ls-files | wc -l           # 140
```

**影响**：public 仓库但没有 License = **默认「保留所有权利」**。任何人都不能合法复制、修改、分发、甚至部署这个项目。这与「重制版开源给人玩」的意图直接冲突，也会让想参考的人不敢用。

**建议修法**：明确选一个 License 并加 `LICENSE` 文件 + `package.json` 的 `"license"` 字段。
- 想让人随便用 → **MIT** 或 **Apache-2.0**（后者与本项目参考过的 `DouDiZhu-ai` 一致）
- 只想让人玩不想让人抄 → 至少要写明「源码仅作学习参考」

**另需处理**：`reference/smallnest-Tractor` **无 License**，项目规则基准却以它为准（`docs/12`）。虽然只是「参考思路 + 重写实现」（见 G-4），仍建议在 README / LICENSE 附一段「第三方参考声明」，说明哪些结论来自它、我们未复制其代码。

### G-3 [P2] 篡改存档会抛未捕获异常，直接崩在渲染前

**现象**：篡改牌值后刷新，页面报 `PowerTable.get: 牌值越界 undefined`。

**证据**：`.tmp/g-audit/audit-run.log` → `phase3.errs`
```
"errs": ["pageerror: PowerTable.get: 牌值越界 undefined"]
```

**根因**：与 `docs/33-审查-C-健壮性.md` 的 P1 同源 —— `loadState` 只有 3 条校验、43 个字段裸奔。`PowerTable.get` 拿到 `undefined` 直接抛错，而它在渲染路径上，没有 try/catch 兜底。

**建议修法**：见 G-1 第 1 条（入口校验）。**修一处同时解决 G-1 的入口、G-3、以及 C 维度的存档问题** —— 这是本批性价比最高的一条。

## 4. License 判定（逐个给结论）

| 参考物 | License | 是否进 git | 是否有代码被搬进 `src/` | 判定 |
|---|---|---|---|---|
| `reference/smallnest-Tractor/`（C#，123MB） | **无** | **否**（`git ls-files` 命中 0，`.gitignore` 已列 `reference/`） | **未发现** | 参考思路合法，但需在声明里注明来源 |
| `reference/DouDiZhu-ai/`（6 个 AI 文件） | Apache-2.0 | **否** | **未发现** | 合规（Apache-2.0 允许参考，若复制需署名） |
| `tractor/`（原版二进制 + 逆向产物） | 商业软件 | **否** | **未发现** | 逆向仅用于理解行为，未分发二进制 |
| `docs/demo/*.pdf`（第三方曲谱） | 受版权保护 | **否**（`.gitignore` 已列） | — | 合规 |

**「未发现代码被搬」的判定依据**（不是拍脑袋）：

1. **C# 命名零残留**：
   ```bash
   grep -rn "GetSuit\|CompareTo\|GetScores\|IsSameSuit\|CurrentPoker\|TractorRules" src/
   # → 无输出
   ```
2. **`src/` 里提到 smallnest 的 8 处全部是注释里的「规则出处」**，不是代码：
   ```bash
   grep -rn "smallnest" src/
   ```
   ```
   src/app/game.ts:546:  * - **花色主**：必须持该门级牌（smallnest `Algorithm.cs:157-178`）。
   src/app/game.ts:547:  * - **无将**：必须持**一对王** —— smallnest `Algorithm.cs:211`
   src/core/types.ts:74:  * 必打集合对齐 smallnest `MainForm.cs:167` 的 `",3,8,11,12,13,"`
   src/core/types.ts:78:  * **例外：`twoAsPermanent: true` 是刻意偏离 smallnest、对齐原版。**
   …
   ```
3. **实现结构不同**：smallnest 是 `CurrentPoker` / `TractorRules` 这类「类 + 可变对象」的 C# 风格；本项目是 `core/` 下一组纯函数（`analyze` / `checkPlay` / `resolveTrick` / `levelsFor`），入参是 `RuleContext`，无类、无 this、无状态。函数划分对不上。

**结论**：属于「照抄规则结论、重写实现」，不构成对无 License 代码的复制。

### G2 · localStorage 实际内容

| Key | 大小 | 内容 | 敏感？ |
|---|---|---|---|
| `tractor.state.v1` | 4328 B | 完整对局状态（`version` / `phase` / 手牌 / 底牌 / 历史 / 计分…共 56 字段） | 否 |
| `tractor.prefs.v1` | 505 B | 偏好（AI 档位、牌面尺寸、动画、音乐主题、三个音量、`prefsVersion`） | 否 |

**无 token、无用户标识、无设备指纹、无位置。** 篡改后会导致崩溃（G-3）但不会泄露任何东西。

### G3 · PWA 检查

- `manifest.webmanifest`：`display: standalone`、`scope: /`、3 个图标（含 maskable）、`lang: zh-CN`。**没有任何权限申请字段**（manifest 本身也没有 permissions 概念），不过度。
- `sw.js`：导航请求 **network-first**（部署后立刻拿新 HTML，断网回落缓存）；其他同源 GET **cache-first**（构建产物带内容 hash，不会拿到过期同名文件）；`activate` 时清掉其它版本缓存；**只缓存成功响应**（`putIfOk`）。策略正确。
- `127.0.0.1` / `localhost` 上不注册 SW（避免 e2e 读到旧产物）—— 这是个很细心的处理。
- 实测：SW 注册成功、缓存 4 项、断网可从缓存拉起（`offlineFromCache: true`）。

## 6. 未验证

| 项 | 原因 |
|---|---|
| CSP（Content-Security-Policy） | 项目没有配 CSP；加 CSP 能直接缓解 G-1，但需评估 `unsafe-inline`（内联 SVG 与内联样式）的冲突 |
| 供应链（devDependencies 的已知漏洞） | 未跑 `npm audit` |
| 第三方 CDN 被投毒的风险 | Tone.js 走公网 CDN 且未校验 SRI（`integrity` 属性）—— 建议补 `integrity` + `crossorigin` |
| Vercel 部署的响应头（HSTS / X-Frame-Options） | 未检查线上响应头 |

## 7. 一句话结论

**安全底子是干净的（零外部请求、无 eval、无 cookie、无设备指纹、SW 策略正确、三份参考代码都没进仓库也没被复制），真正的缺口只有两条：状态值直接拼 `innerHTML` 导致「篡改存档即可执行脚本」（G-1，修 `loadState` 校验一处可连带解决 G-3 与 C 维度问题），以及 public 仓库缺 LICENSE（G-2）。**
