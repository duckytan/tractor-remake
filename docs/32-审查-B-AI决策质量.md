## 1. 方法与证据边界

| 项 | 做法 |
|---|---|
| 取证方式 | **四家全自动对局**（人类座位也交给 AI），跑完整局，逐墩记录 |
| 样本 | 12 局 / 237~286 墩（L1/L2/L3 各 12 局）；L2/L3 另跑 24 局复核 |
| 判据来源 | 「可机检失误」全部由**代码判定**，不靠人眼过牌谱 |
| 假阳性控制 | 每条判据都要求「本来有别的合法出法」，用 `enumeratePlays` + `trickStanding` 枚举 |
| 证据边界 | 只能证明「可机检的四类失误」与「首出分布」。**不能**证明「某手牌在全局上更优」—— 那需要完整搜索，不在本批范围 |

### 取证工具

新增 `scripts/dump-ai-round.ts`（**只读诊断脚本，不进运行时**）：

```bash
npx vite-node scripts/dump-ai-round.ts --rounds 12 --level 3          # 汇总
npx vite-node scripts/dump-ai-round.ts --seeds 1001,1007 --verbose    # 逐处失误明细
npx vite-node scripts/dump-ai-round.ts --json                         # 机器可读
```

输出：逐墩牌谱 + 每局底分/闲家得分/升级结果 + 五类可机检失误 + 首出分布 + 决策耗时 + 抢主统计。

### 工具自身踩过的坑（写在这里，避免下次重踩）

1. **`lastSettle` 未结算时是 `null` 而不是 `undefined`** —— `settle === undefined` 判空会漏掉 `null` 直接崩。
2. **空候选 `[]` 让「本可出 0 分牌」永远为真** —— `pointsOf([]) === 0`。实测把「手里只剩 ♠10 ♠5 ♥5（全是分牌）」误判成「本可出 0 分牌」。**必须过滤空候选。**
3. **「本队输 + 丢了分」≠ 垫分** —— 出大牌抢分结果被对手压过，也满足这个条件。必须加「出完之后自己没成为本墩最大」才是真垫分。
4. **`newGame` 一开局就把 `declareOptions` 填成整手牌的可亮花色**（`game.ts:229`），但此时 `declareTrump` 会以「这张级牌还没发到手」全部拒绝。自动化驱动必须判 `revealed >= DEAL_TOTAL`，否则无限重试。

## 3. 发现清单

### B-1 [P0] L3 首出王 11.8%：权重标定把「花王保墩」算成了划算买卖

**现象**：L3 在 0 分墩上反复用大王/小王首出（24 局里 57 次，占全部首出的 11.8%），甚至有「首出大王大王」这种成对甩王的回合。

**根因（可推导，非猜测）**。首出评分在 `src/ai/policy.ts:516-553`：

```
score  = -powerCost / (cards.length * 80)      // 省牌
        + min(slotCount, 10) * 0.05            // 长套
        - points * 0.02                        // 别急着甩分
        [- overLead / exactOver 如果会被压]     // L2: 0.5   L3: 1.15
        + followUp * leadFollowUp(...)         // 仅 L3: 0.35
```

代入同一手牌里的两个候选：

| 候选 | L2 得分 | L3 得分 |
|---|---|---|
| 首出大王（必赢，`leadFollowUp` 返回 1） | −0.75 + 0 + 0 = **−0.75** | −0.75 + 0.35 = **−0.40** |
| 首出 ♠3（会被对手压） | −0.04 − 0.50 = **−0.54** ✅ | −0.04 − 1.15 = **−1.19** |

- **L2**：−0.54 > −0.75 ⇒ 选 ♠3 ⇒ 首出王只有 1.6%。
- **L3**：−0.40 > −1.19 ⇒ 选大王 ⇒ 首出王 11.8%。

也就是说：**`exactOver = 1.15` 把「被压」的代价抬到「大王只值 0.75」的两倍以上，L3 于是宁可烧王也不肯冒被压的风险。** 这不是「L3 更保守」，是**王牌定价错了** —— `powerCost/(len*80)` 让一张大王只值 0.75 分，而一张 3 值 0.04 分，两者相差 18 倍，但真实牌力差是 60 倍。

**影响**：L3 是玩家默认对抗的档位，这个行为**肉眼可见**，直接构成「AI 太弱智」的主观感受。

---

### B-2 [P0] AI 永远不会甩牌

`src/ai/enumerate.ts:59-114` 的 `enumerateLeads` 只产出三类首出：单张、对子、连对（拖拉机）。**没有任何多组混出（甩牌）分支。**

后果：

- 人类玩家甩 5 张，AI 一张一张地出 —— 这是最容易被玩家看穿的「不会玩」。
- `enumerateFollows` 在 `lead.suitSlot === -1`（混槽首出）时直接 `return []`（`enumerate.ts:144`），即 AI **对甩牌没有任何候选集**，只能走兜底分支（见 B-7）。

同时确认：`checkLead` 允许人类甩牌且会逐组校验，所以这是**单侧能力缺口**，不是规则不允许。

---

### B-3 [P1] L1 首出「手里最小牌」占 53.2%：首出评分实际上只有「省牌」一项在起作用

首出分支里三项的**量级**：

| 项 | 取值范围 | 实际影响 |
|---|---|---|
| `-powerCost/(len*80)` | 单张 0 ~ −0.75 | **主导** |
| `+min(slotCount,10)*0.05` | 0 ~ +0.50 | 次要（且长套最多只值 0.5） |
| `-points*0.02` | 0 ~ −0.40 | 很弱 |

L1 没有 L2/L3 的「会被压」项，所以排序几乎完全由 `powerCost` 决定 ⇒ **永远出最小的那张**。53.2% 正是这个结论的直接读数（剩下 46.8% 是对子/连对/同牌力并列）。

这不是「L1 该弱」，而是 **L1 的首出策略退化成了一条固定规则**，没有任何局面判断。玩家在低档位对局时看到的就是「AI 一直出小牌」。

---

### B-4 [P1] L3 在「该毙不毙」上明显退化（12 处 vs L2 的 1 处）

判据：**缺门 + 手里有主牌 + 本墩已有 ≥10 分 + 却垫了非主牌**（严格条件，不含「毙了但没赢」的情况）。

24 局样本：L2 命中 1 次，L3 命中 12 次。与 B-1 同源 —— L3 的 `controlLoss`（`L3_WEIGHTS.control = 0.55`）只在 `!iAmWinning` 时计入，而「毙牌」在 L3 眼里属于「花主牌」，`controlLoss` 惩罚可能压过了「赢 10 分」的收益。

这是 L3 特有的退化，L2 没有。

---

### B-5 [P1] 算力预算只用了不到 1%

| 档位 | 决策 P50 | P95 | 最大 |
|---|---|---|---|
| L1 | 0.03ms | 0.10ms | 1.71ms |
| L2 | 0.03ms | 0.18ms | 2.43ms |
| L3 | 0.04ms | 0.26ms | 2.73ms |

人类感知阈值约 200ms，即使用掉 100 倍预算也察觉不到。**当前 AI 的瓶颈完全不是算力，而是策略表达力**（B-1/B-2/B-3 全是「想不到」而不是「算不动」）。

这条直接推翻了 `docs/28` 里「算力分档 = 候选广度」的隐含假设：候选从 2 个铺到 60 个，耗时仍只有 0.26ms，那么「低档看得少」并不是省算力的必要手段。

---

### B-6 [P2] 首出主牌 36%~45%，缺「清主 / 打副牌」的全局规划

四档都在 35% 以上，L3 达 44.5%。首出评分里没有任何「我方主牌还剩几张、对手还有几张主」的项 —— 主牌首出纯粹由 `slotCount(trump)*0.05` 和 `powerCost` 偶然决定。

真实牌局里「什么时候清主、什么时候打副牌送分」是**一级决策**，当前完全没有建模。

---

### B-7 [P2] `decide()` 的兜底分支是坏的

`src/ai/policy.ts:393-404`：

```ts
const slot = play.kind === 'follow' ? play.leadAnalysis.suitSlot : -1
const sorted = [...hand].sort((a, b) => {
  const sa = slot !== -1 && ctx.power.isTrump(a.value) === (slot === 4) ? 0 : 1
  const sb = slot !== -1 && ctx.power.isTrump(b.value) === (slot === 4) ? 0 : 1
  if (sa !== sb) return sa - sb
  return ctx.power.get(a.value) - ctx.power.get(b.value)
})
```

当 `slot === -1`（混槽首出）时，`sa === sb === 1`，比较器退化成纯牌力排序；而且**完全不校验对子/拖拉机结构**，直接 `slice(0, count)`。

目前触发不到，因为 AI 自己不甩牌（B-2），混槽首出只可能来自人类 —— 但一旦触发，`playCards` 会拒绝，AI 这一手就永远出不去。**这是一颗定时炸弹**，修 B-2 时必须一起处理。

### B-8 [P2] L2/L3 直接读对手手牌（偷看）

`src/app/game.ts:1007-1009`：

```ts
opponents: [0, 1, 2, 3]
  .filter((x) => x !== seat)
  .map((x) => s.hands[x] as readonly Card[]),
```

三家**真实手牌**被塞进 `opponents`，`canBeOverturned` / `exactBeatable` / `leadFollowUp` 全都直接读它。`docs/27` 里把它解释为「L2 的前瞻能力」，但从玩家视角这是**明牌作弊**。

两个后果：
1. 玩家感知到的「AI 总能压我」有一部分不是算得准，是看得到。
2. **强度标定失真** —— L2/L3 的胜率里含「信息优势」，一旦换成概率推断会掉。

`docs/28` 规划里的「对手手牌概率模型（HQ/ΔHQ）」正是这件事的正确做法，但尚未实现。

---

### B-9 [P3] `newGame` 的 `declareOptions` 与实际可亮校验不一致

`game.ts:227-230` 无条件执行 `declareOptions: humanDeclareOptions(base)`，而 `declareTrump` 的持牌校验用「已揭示前缀」（`declareOptionsIn`）。当 `animation === true` 时 `revealed = 0`，于是状态里 `declareOptions` 声称「你可以亮 ♠♥♣♦」，但真去亮会被全部拒绝。

UI 靠 `stillDealing && !s.dealPrompt` 挡住了，所以玩家看不到。但这让**任何自动化驱动 / 存档回放 / 未来的 AI 代理**都会踩（本次取证工具就踩了，见 §1 第 4 条）。

## 5. 修复建议（按性价比排序）

| # | 修什么 | 怎么修 | 风险 |
|---|---|---|---|
| 1 | **B-1 王牌定价** | 把 `powerCost/(len*80)` 换成按「牌力分位」计价，或给王/级牌单独加「留存价值」项（例如 `-0.35 * isJoker`）；并**重跑座位互换配对标定** | 中。必须重新标定 L3vsL2，否则可能只是把 11.8% 挪到别处 |
| 2 | **B-2 甩牌能力** | `enumerateLeads` 增加「同槽多组」分支：按组（单/对/连对）组合出 2~3 组，用 `checkLead` + 真实对手手牌校验 | 中。候选数会涨，但耗时有余量（B-5） |
| 3 | **B-7 兜底分支** | 与 B-2 一起改：兜底改为「调用 `checkPlay` 逐个试，取第一个合法」 | 低 |
| 4 | **B-3 L1 首出** | 给 L1 也加「会被压」的粗略判断（L2 的 `canBeOverturned` 很便宜） | 低。L1 会变强，需重新标定 L1vsL0 |
| 5 | **B-4 L3 该毙不毙** | 毙牌时把「本墩分」计入 `controlLoss` 的对冲项 | 中 |
| 6 | **B-8 偷看** | 短期：给 `opponents` 加显式开关，默认关，用于公平标定；长期：实现 `docs/28` 的概率模型 | 高（要新写模型） |
| 7 | **B-9 declareOptions** | `newGame` 里改成 `revealed >= DEAL_TOTAL ? humanDeclareOptions(base) : []` | 低 |

**不建议现在动的**：B-6 清主规划。它需要「主牌张数记牌 + 全局阶段判断」，属于 `docs/28` 的 HQ/ΔHQ 范畴，应作为独立批次做，不要塞进这次修 bug。

## 6. 复现

```bash
cd tractor-remake
npx vite-node scripts/dump-ai-round.ts --rounds 24 --level 2   # L2 基线
npx vite-node scripts/dump-ai-round.ts --rounds 24 --level 3   # L3 对照
npx vite-node scripts/dump-ai-round.ts --rounds 6  --level 3 --verbose   # 失误明细
```

判定「B-1 是否修好」的最小断言：

```
L3 的「首出王」占比 ≤ 3%       （当前 11.8%）
L3 的可机检失误率 ≤ L2 的失误率 （当前 5.2% > 3.9%）
```

这两条可以直接写进回归测试（见后续批次）。
