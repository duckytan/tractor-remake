# 02 · 需求规格说明书（SRS）

> 状态：`已定稿` ｜ 版本：v1.0 ｜ 日期：2026-10-22
> 规则依据：`rules/游戏规则规格书.md`（下称「规则书」）

## 1. 引言

### 1.1 目的

把「重制拖拉机大赛」拆成可独立验证的功能点，每个功能点都有明确的验收标准，
使开发、测试、验收有共同基准。

### 1.2 范围

覆盖单机对局全流程：发牌 → 定约 → 出牌 → 计分 → 升级 → 终局。
不含联网、不含账号、不含逐像素复刻（见章程 §4）。

### 1.3 读者

开发、测试、验收人。

### 1.4 约定

- 需求编号 `FR-xx` / `NFR-xx` 全局唯一，不复用。
- 「规则依据」列的 `§x.y` 均指规则书章节。
- 「验收」列必须可判定，不写「体验良好」这类无法验证的描述。

---

## 2. 用户场景

### 2.1 主要场景

> 用户打开网页 → 看到牌桌 → 选择新游戏 → 系统发牌 → 用户亮主 →
> 用户与 3 个 AI 对打出牌 → 一局结束看结算 → 继续下一局 → 某队打过打王 → 游戏结束。

### 2.2 关键体验诉求

| 诉求 | 来源 |
|---|---|
| 手牌一眼能看清点数和花色 | 原版 71×96 牌面在 2K 屏太小 |
| 一眼能看出「现在轮到谁」「谁是庄家」「主牌是什么」 | 原版信息展示分散 |
| 选牌后能知道「这手牌能不能出」 | 原版要点了才知道，且无提示 |
| 能看懂当前这一墩谁大 | 原版没有明显的赢家标识 |

## 3. 功能需求

### FR-01 牌与牌力表

| 项 | 内容 |
|---|---|
| 描述 | 提供 108 张牌的表示与查询；按 `mode / levelRank / trump` 构建 55 项牌力表 |
| 规则依据 | §1.1 §1.2 §4.1 |
| 验收 | ① 牌值域 0..53，52=小王、53=大王；② 主牌 power 全部 ≥ 52，副牌全部 < 52；③ `mode=1` 时四门 rank0 抬升，顺序为 大王 > 小王 > 主3 > 副3 > 主2 > 副2 > A > K > … > 4；④ 任意 `(mode, levelRank, trump)` 组合下 power 值域连续无重复（除同点不同花） |

### FR-02 发牌

| 项 | 内容 |
|---|---|
| 描述 | Fisher-Yates 洗牌 → 折叠为牌值 → **108 张全派**：4 家各 25 张，庄家再多拿 8 张（共 33 张，即将来的底牌，v1.3.3 起） |
| 规则依据 | §2.1 §2.2 |
| 验收 | ① 庄家 33 张、其余各 25 张，合计 108 个牌位（54 值 ×2）；② 同一牌值恰好出现 2 次；③ **禁止天然连对**：在 64 种（mode×2 队级牌×4 主花色×4 视角）组合下，任一家任一花色槽都不存在现成连对，否则重洗（庄家按 33 张校验）；④ 洗牌支持注入随机源，便于测试复现 |

### FR-03 定庄

| 项 | 内容 |
|---|---|
| 描述 | 开局随机确定庄家座位 |
| 规则依据 | §3.1 |
| 验收 | 庄家座位在 0..3 均匀分布；随机源可注入 |

### FR-04 亮主与反主

| 项 | 内容 |
|---|---|
| 描述 | 发牌后选择主牌（4 花色 + 无将）；支持反主 |
| 规则依据 | §3.2 §3.3 §3.5 |
| 验收 | ① 5 个选项（4 花色 + 无将）；② 反主必须持有**新花色**的级牌；③ 打王级强制无将，花色不可覆盖；④ `允许反无将` 开关为假时，无将不可被反；⑤ 亮主成功后立即重建牌力表并重排手牌 |

### FR-05 埋底

| 项 | 内容 |
|---|---|
| 描述 | 庄家从 33 张手牌里扣下 8 张作底牌（扣完 25 张；v1.3.3 起庄家发牌即 33 张，无「收底」步骤） |
| 规则依据 | `【标准】` 原版无，见 ADR-006 |
| 验收 | ① 庄家手牌 33 张；② 扣底阶段必须选满 8 张才能确认；③ 扣下的牌不出现在任何玩家可见区域；④ 非庄家手牌保持 25 张 |

### FR-06 手牌整理与分槽

| 项 | 内容 |
|---|---|
| 描述 | 把一手牌拆成 5 个花色槽，槽内按牌力降序；提供对子数、单张数、代表牌等语义查询 |
| 规则依据 | §5.1 |
| 验收 | ① 槽 4 恰好是全部 power ≥ 52 的牌；② 槽内排序稳定且按牌力降序；③ `analyze(cards, trump)` 返回 `{typeCode, pairs, singles, keyCard}`；④ 连对（任意长度）被识别为单一牌型而非甩牌 |

### FR-07 出牌合法性 · 首出

| 项 | 内容 |
|---|---|
| 描述 | 校验首出：张数、同花色、甩牌逐组最大 |
| 规则依据 | §6.4 |
| 验收 | ① 首出牌必须同属一个花色槽，混花色拒绝；② 单一牌型（单张/对子/连对）直接合法；③ 多组混出时，**每一组的每一个单位**都必须大于其他三家同花色同组型的最大牌（对子组**逐对**比较，不能只比最大一对）；④ 甩牌失败时按 ADR-008 裁剪为「失败组的最小单位」（单张组→1 张，对子组→1 对）并给出提示 |

### FR-08 出牌合法性 · 跟牌

| 项 | 内容 |
|---|---|
| 描述 | 校验跟牌：张数一致、花色跟满、对子数跟满 |
| 规则依据 | §6.3 |
| 验收 | ① 张数必须与首出相同；② 该花色张数必须等于 `min(首出张数, 手里该花色张数)`；③ 该花色不足时垫牌完全自由，不校验垫牌内容；④ 该花色足够时，对子数必须等于 `min(首出对子数, 手里该花色对子数)`；⑤ **不要求跟连对**（宽松结构跟随） |

### FR-09 一墩判定

| 项 | 内容 |
|---|---|
| 描述 | 四家出完后判定赢家 |
| 规则依据 | §7.1 |
| 验收 | ① `typeCode == 10` 的牌永远不能赢；② 主牌型（4）压任意副牌型（0..3）；③ 同花色槽内比 `keyCard` 的 power，大者赢；④ 不同花色槽且都不是主牌时，首出方赢；⑤ 赢家收走本墩全部分数牌 |

### FR-10 计分

| 项 | 内容 |
|---|---|
| 描述 | 统计闲家方吃到的分数 |
| 规则依据 | §8.1 §8.2 |
| 验收 | ① 5 = 5 分，10 = 10 分，K = 10 分，其余 0；② 分数归该墩赢家所在队伍；③ 两副牌总分 200；④ 闲家得分 = 闲家两家的合计 |

### FR-11 扣底

| 项 | 内容 |
|---|---|
| 描述 | 最后一墩由闲家赢且含底分时，底分翻倍计入闲家得分 |
| 规则依据 | `【标准】` 原版无，见 ADR-006 |
| 验收 | ① 底分 = 8 张扣底牌的分数合计；② 最后一墩赢家是庄家方 → 底分不计；③ 最后一墩赢家是闲家 → 底分 × 倍数计入；④ 倍数为 **2（单张）／4（对子）／8（拖拉机及以上）**，按赢家最后一墩的牌型判定 |

### FR-12 升级结算

| 项 | 内容 |
|---|---|
| 描述 | 按闲家得分决定升级队与升级级数 |
| 规则依据 | §9.1 §9.2 §9.3 |
| 验收 | ① 得分 0 → 庄家方升 3 级；② 1..39 → 升 2 级；③ 40..79 → 升 1 级；④ ≥80 → 闲家上台，升级数 = `floor((score-80)/40)`（即 80–119 升 **0** 级，120–159 升 1 级，160–199 升 2 级，200 升 3 级）；⑤ 级牌推进顺序 `K→A→打王→2`，打王之后回到 2（或 3，视 `mode`） |

### FR-13 必打（升级禁止跳级）

| 项 | 内容 |
|---|---|
| 描述 | 升级时若途经受保护的级牌，则截断在该级牌前一级 |
| 规则依据 | §10.3（注意：**与出牌无关**） |
| 验收 | ① 判定发生在级牌推进之后，判断对象是「新级牌」；② 开关 `5,10,K必打` 保护 {5,10,K}；③ 开关 `J,A必打` 保护 {J,A}；④ `打王必打` 保护 {打王}；⑤ 例：9 升 3 级且 J 受保护 → 停在 10 |

### FR-14 终局判定

| 项 | 内容 |
|---|---|
| 描述 | 某队打到打王级并再赢一局，则该队获胜，游戏结束 |
| 规则依据 | `【标准】` 原版无，见 ADR-011 |
| 验收 | ① 该队级牌 = 打王且本局该队为庄家方且赢下本局 → 胜；② 结算界面显示胜方与总局数；③ 可开新游戏重置 |

### FR-15 游戏流程状态机

| 项 | 内容 |
|---|---|
| 描述 | 驱动一局的完整阶段流转 |
| 规则依据 | §3.6 §16.7 |
| 验收 | 状态序列：`发牌 → 定庄 → 亮主(可反复反主) → 埋底 → 出牌(25 墩) → 结算 → 下一局`；任意时刻状态可序列化与恢复；非法转移抛错而非静默 |

### FR-16 AI 对手

| 项 | 内容 |
|---|---|
| 描述 | 3 个 AI 玩家，至少 3 个难度档 |
| 规则依据 | §11.1（仅参考难度划分，算法不移植） |
| 验收 | ① AI 出牌必然通过 `FR-07` / `FR-08` 的合法性校验；② 3 档难度在固定牌局下胜率单调递增；③ AI 思考有可配置延迟（0 / 300 / 800 ms）；④ 相同输入 + 相同随机种子 → 相同出牌（**确定性**，与原版相反，便于测试） |

### FR-17 存档与恢复

| 项 | 内容 |
|---|---|
| 描述 | 保存偏好设置与当前局进度 |
| 规则依据 | 无（原版 `Game.sav` 只存偏好，本项目扩展） |
| 验收 | ① 刷新页面后可恢复未完成的一局；② 存档含版本号，版本不匹配时提示且不崩溃；③ 存档损坏时降级为「新游戏」并提示 |

### FR-18 设置项

| 项 | 内容 |
|---|---|
| 描述 | 规则开关与体验选项 |
| 规则依据 | §10.1 §10.2 |
| 验收 | ① 6 个规则开关：允许自反 / 2 为常主 / 允许对家保 / 允许反无将 / 5,10,K必打 / J,A必打；② 体验项：AI 难度、AI 速度、动画开关、牌面尺寸（小 120×168 / 中 150×210 / 大 190×266）；③ 开关改动在下一局生效，当前局不生效；④ 设置持久化 |

### FR-19 可出牌提示

| 项 | 内容 |
|---|---|
| 描述 | 选牌时实时提示合法性，并可一键提示可出的牌 |
| 规则依据 | 无（原版无，纯体验增强） |
| 验收 | ① 选中的牌不合法时，给出具体原因（张数不对／没跟够对子／有该花色不能垫牌…）；② 点「提示」高亮一手**建议**的牌 —— **与 AI 共用同一决策引擎**（`app/game.ts` 的 `choosePlay`，L3 超强 + 残局精确搜索），不是「随便找一手合法的」；③ 提示不改变游戏状态 |

> **② 的口径变过（v1.3.31 / v1.3.33）**：v1.3.31 起与 AI 同源（`choosePlay`）；
> v1.3.33 起**风格可选**（设置 → 画面 → 提示风格）：默认「稳妥」= `ai/safeHint.ts`
> 的保守打法（不首出带分牌、能赢才抢、队友赢着垫最小），可切「最强」= L3。
> 两种风格都接同一套「一句话理由」（`app/hintView.ts`）。
>
> 旧口径（供追溯）：：早先提示取的是 `enumeratePlays(...)` 的**第一个合法候选**，
> 而候选按小到大枚举 ⇒ 提示恒等于「出最小的一手」，玩家反馈「提示还是太弱智了」。
> 现在与 `aiPlayFor` 同源，`tests/app/hint.test.ts` 锁住三条：
> 建议永远合法 / 与 AI 不可能分叉 / 不再退化成「枚举第一个候选」（实测 400 个局面里
> 与旧实现只剩 27% 巧合一致）。


### FR-20 对局记录

| 项 | 内容 |
|---|---|
| 描述 | 记录每一墩的出牌，供回看 |
| 规则依据 | 无 |
| 验收 | ① 每墩记录四家出牌与赢家；② 可翻看已结束的墩；③ 记录仅存内存，不写存档 |

## 4. 非功能需求

| 编号 | 需求 | 验收 |
|---|---|---|
| NFR-01 | **分辨率无关**：牌面与文字在任意 DPI 下清晰 | 在 1920×1080 / 2560×1440 / 3840×2160 下截图，牌面点数文字边缘无插值模糊；**牌面宽度不低于 120px**（低于此值点数难辨，等于退回原版） |
| NFR-02 | **窗口自适应**：1366×768 至 4K 布局不破 | 窗口任意拖拽尺寸，无横向滚动条、无元素重叠、无空白未绘制区 |
| NFR-03 | **可测试性**：`src/core` 零浏览器 API 依赖 | `grep` 无 `window` / `document` / `localStorage`；测试在 Node 环境跑通 |
| NFR-04 | **性能**：出牌到界面更新 < 50ms；AI 单步决策 < 200ms（高级档） | 用 `performance.now()` 打点，10 次取均值 |
| NFR-05 | **覆盖率**：`src/core` 行覆盖 ≥ 90% | Vitest coverage 报告 |
| NFR-06 | **确定性**：规则引擎纯函数，同输入同输出 | 无全局可变状态；随机源显式注入 |
| NFR-07 | **兼容性**：Chrome / Edge 最新两个大版本 | 手动验证 |
| NFR-08 | **离线可用**：构建产物无外部网络请求 | DevTools Network 面板零外部请求 |
| NFR-09 | **体积**：首屏 JS < 300KB（gzip 后） | `vite build` 报告 |
| NFR-10 | **可访问性**：全部操作可用键盘完成 | Tab 可遍历、Enter 确认、Esc 取消 |
| NFR-11 | **无崩溃**：连续 10 局控制台零 error | 手动长跑 |

## 5. 数据需求

### 5.1 需要持久化的数据

| 数据 | 存储位置 | 生命周期 |
|---|---|---|
| 偏好设置（规则开关、AI 难度、动画） | 浏览器本地存储 | 永久 |
| 当前局进度（发牌结果、阶段、出牌历史、比分） | 浏览器本地存储 | 直到本局结束 |
| 累计战绩（胜场、总局数） | 浏览器本地存储 | 永久 |

### 5.2 不需要持久化的数据

- 对局内每一墩的详细记录（仅内存）
- AI 内部搜索状态
- 原版 `Game.sav` 的 47 个字段（无迁移价值）

## 8. 验收清单

开发完成后逐项打勾，全部通过才算交付：

- [ ] 108 张牌全派（庄家 33 / 闲家 25），牌值不重不漏
- [ ] 64 重校验确实禁止了天然连对（可用断言验证）
- [ ] 亮主 5 选项、反主需新花色级牌、打王级强制无将
- [ ] 庄家发牌即 33 张、埋底扣 8 张
- [ ] 首出混花色被拒
- [ ] 连对不被判为甩牌
- [ ] 甩牌逐组校验，失败只出最小一张
- [ ] 跟牌张数/花色/对子数三重校验
- [ ] 不要求跟连对（宽松）
- [ ] 主牌压副牌，同花色比牌力
- [ ] 5/10/K 计分正确，两副共 200
- [ ] 扣底翻倍在最后一墩生效
- [ ] 升级 4 档全部正确
- [ ] ≥80 走闲家上台分支
- [ ] 必打截断正确（9 升 3 级停在 10）
- [ ] 终局判定正确
