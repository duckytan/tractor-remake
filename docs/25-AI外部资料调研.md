# 25 · 外部 AI 资料调研（拖拉机 / 双升）

> 目的：找现成的拖拉机 AI 算法与实现，避免重复造轮子。
> 结论先说：**没有可以直接用的拖拉机专用 AI**，但找到了三条可借鉴的路线。

## 1. 关键词怎么设计的（这个题材很容易搜错）

「拖拉机」在中文里至少三种含义：

| 含义 | 例子 |
|---|---|
| 农用机械 | 拖拉机厂商、农机维修 |
| 数学问题 | 拖拉机调度、路径规划 |
| **扑克游戏** | 双升 / 升级 / 80 分 / 八十分 / 甩牌 / 炒地皮 |

英文更麻烦：`Tractor` 同时是
- 农机
- **定理证明器**（Kripke-Platek 集合论的 Tractor）
- **NLP 工具**（把数学论文自动形式化，Facebook 出的）

扑克游戏的英文名：`Sheng Ji`、`Tractor`、`Eighty Points`、`Up and Down the River`。

### 实际用过的关键词与命中率

| 关键词 | 结果 |
|---|---|
| `双升 扑克 AI 出牌算法 设计` | 1 条有用（牌型解析 CSDN），其余是斗地主/记牌器 |
| `Sheng Ji card game AI algorithm github` | **找到最有价值的一个仓库**（DouDiZhu 权重框架） |
| `掼蛋 AI 出牌 算法 权重 手牌拆分` | 商业辅助器 + 思维类文章，无算法细节 |
| `"Tractor" OR "Sheng Ji" card game strategy AI program implementation` | **搜错**：命中农机厂商、`JI-CAI-50 TRACTOR` 断裂分析论文 |
| `github shengji 升级 双升 扑克 游戏 源码 规则 引擎` | Python 版「升级」教程（只有规则，无 AI） |
| `甩牌 判定 算法 拖拉机 双升 牌型 程序` | 规则说明（百科/文库）+ **农机厂商**（百度爱采购） |
| `不完全信息 卡牌游戏 AI 信息集蒙特卡洛搜索 ISMCTS 实现` | 方法论资料丰富（知乎/CSDN） |
| `"Sheng Ji" trick-taking game AI research paper computer player` | 1 条同类游戏论文（Klaverjas），其余无关 |

**经验**：搜这个题材必须带上「扑克 / 牌 / 双升 / 80 分」这类词，
或者用 `Sheng Ji` 而不是 `Tractor`；`甩牌` 是最精准的中文术语（只有这个游戏用），
但仍会被农机污染。

## 2. 最有价值的发现：手牌拆分权重框架

**`ZhouWeikuan/DouDiZhu`**（基于权重的斗地主 AI，C++ + Lua）

README 原文明确写着：

> 「稍加修改，算法可以很容易的拓展到其他类似棋牌游戏上，如掼蛋，争上游，**拖拉机**等。」

### 核心公式

```
p(cards) = max( node_i + p(cards_i) )
```

即：**手牌的总价值 = 从中拆出一种牌型的价值 + 剩余手牌的价值，在所有拆法里取最大**。

权重用「厌恶度 bad」表达（斗地主以跑光手牌为目标，牌多一张就多一分负担）：
- 出完 = 0
- 每多「一手牌」扣固定分（`kOneHandPower = -150`）
- 牌越小、越难出手，厌恶度越高

### 与我们的根本差别

| | 我们 | DouDiZhu 框架 |
|---|---|---|
| 评估对象 | **这一手**本身赚不赚（省牌、吃分、会不会被压） | **出完这手之后，剩下的手牌还有多好打** |
| 决策方式 | 候选打分，取最高 | 枚举拆法，取「剩余手牌价值」最高 |

这个视角差异很关键：出牌的真正价值是**让剩下的手牌更好打**，而不是这一手多赚两分。

### 工程细节（可直接借鉴）

- **递归 + 哈希缓存**（手牌 key → 结果），避免重复计算
- **关键优化**：固定提取顺序（每次先提最大面值的牌型），
  把排列组合 `P(N,M)` 退化成单一路径，复杂度降到近似 `O(N+M)`；
  实测 C 语言从 0.5~3 秒降到**几十毫秒**
- 出牌提示排序用「剩余手牌权重」而不是牌型权重 ——
  比如手牌 `4 3 3 3 3 5`，提示第一位是 `4`（剩下 `3333 5` 价值最大），符合玩家直觉
- 人工规则版胜率约 47~48%（接近人类熟手）

### 迁移到拖拉机需要改什么

- 牌型定义：单张 / 对子 / 拖拉机 / 甩牌（我们的 `analyze` 已经能给出）
- 「手数」的度量：按花色槽分别算，主牌单独算
- 分牌（5/10/K）的价值：拖拉机里分牌是**资产**（要抢），斗地主里是负担 —— 权重方向相反
- 队伍：还要考虑「这手能不能让队友接」

## 3. 方法论：我们现在的做法是学术上已知的低效简化

搜「麻将 AI / 不完全信息博弈」时反复看到同一句话：

> 「最直观但效果有限的方法是**完美信息假设**，即让 AI 能看到所有家的手牌，
> 把它当作完全信息游戏来处理。」

**这正是我们现在的做法**（`aiPlayFor` 直接读 `s.hands[x]`）。

学术主流是 **ISMCTS（信息集蒙特卡洛树搜索）**：
- 每个节点代表「一组可能的世界」，而不是确定状态
- 在多个可能世界间共享统计信息
- 参考：知乎《【博弈论-不完美信息】ISMCTS 论文总结》

对我们来说，短期不必上 ISMCTS（工程量大、还要确定性保证），
但**「完美信息」这个假设值得记在心里**：它让 AI 看起来很准，
一旦改成真实信息就会全线崩。

## 4. 同类游戏的学术研究

**Klaverjas**（荷兰的 trick-taking 游戏，两队两两对抗、有将牌）：
> 「我们提出一种高效编码来枚举游戏的可能配置，从而可以在此基础上做搜索」
> —— Springer, 2019

思路是「**高效编码 + 后续搜索**」，与 ISMCTS 同源。
这类研究和拖拉机结构最接近（两队、将牌、跟牌），比斗地主更值得参考。

## 5. 结论

**没有可以直接抄的拖拉机 AI**（专用资料几乎为零，中文只有规则与牌型解析，
英文被农机/定理证明器/NLP 工具占满）。

三条可借鉴的路线，按「投入产出比」排序：

1. **手牌拆分权重**（DouDiZhu）—— 换个评估视角，不动架构，最容易落地
2. **编码 + 搜索**（Klaverjas）—— 需要先定义「局面编码」，中等工程
3. **ISMCTS**（信息集搜索）—— 最强但最贵，且要解决确定性/性能

结合 docs/23 的结论（瓶颈在候选集），建议顺序仍是：
**先补候选集 → 再引入「剩余手牌质量」作为评估项 → 最后才考虑搜索。**
