## 2. 发现清单

### E-1 [P1] 全局 Space 键劫持：顶栏按钮和设置开关按空格完全无效

**现象**：焦点在顶栏按钮或设置里的 `role=switch` 上按 **Space → 毫无反应**；按 **Enter 正常**。

| 操作 | Enter | Space |
|---|---|---|
| 顶栏「设置」 | 打开 ✅ | **不打开** ❌ |
| 顶栏「新游戏」 | 弹确认 ✅ | **不弹** ❌ |
| 设置「各家出牌留痕」开关 | `true → false` ✅ | **`false → false`** ❌ |

**证据**：
```bash
node .tmp/e-audit/e1-consistency.mjs
```
```
=== ①-3 焦点在顶栏按钮上按 Space ===
  [openSettings] 按 Space → {"settingsOpen":false}｜已选牌 1→1
  [newGame] 按 Space → {"confirm":false}｜已选牌 1→1
  [openSettings] 改按 Enter → 设置面板打开=true
=== ①-4 设置内 role=switch：Enter 与 Space ===
  「各家出牌留痕」Enter：true → false
  「各家出牌留痕」Space：false → false（期望翻转）
```

**根因**：`src/main.ts:365-367`
```ts
if (ev.code === 'Space') {
  ev.preventDefault()
  dispatch({ type: 'playSelected' })
}
```
这是**全局**监听，不检查焦点在哪。空格在浏览器里是「激活当前焦点元素」的默认键，被 `preventDefault()` 吃掉后按钮永远收不到。而 `Enter` 没被拦截，所以 Enter 能用。

**影响**：NFR-10 声称「全部操作可用键盘完成」，实际键盘用户**无法用空格操作任何按钮**，只能改用 Enter。这是可访问性硬伤（WCAG 2.1.1 键盘可达）。

**建议修法**：加焦点判断 —— 当 `ev.target` 是 `button` / `[role=switch]` / `[role=tab]` / `input` / `select` / `a[href]` 时直接 `return`，让浏览器默认行为生效；只有焦点在 `body` / 牌桌 / 手牌容器上时，Space 才是「出牌」。

**验收断言**：焦点在任意 `<button>` 上按 Space，该按钮被激活；焦点在 `body` 上按 Space，执行出牌。

### E-2 [P1] 键盘选牌后焦点丢到 `BODY`，连续操作断裂

**现象**：Tab 到手牌（`aria-label="第 104 张牌"`）→ 按 Enter 选中成功（`selected: 1`）→ **焦点变成 `BODY`**，再按 Enter 不会取消选中（`已选 1`，期望 0）。键盘用户每选一张牌就要重新 Tab 十几下。

**证据**：
```
=== ①-2 手牌选中：Tab + Enter，以及选中后焦点是否保住 ===
  Tab 到手牌：{"tag":"DIV","label":"第 104 张牌"}
  按 Enter 后：{"active":"BODY","inHand":false,"selected":1}
  紧接着再按一次 Enter：已选 1（期望 0=取消）
```

**根因**：`toggleSelect` → `dispatch` → `paint()` → `render()` 重建整棵 DOM（见 `docs/34` D-3）。原来那个 `.card` 元素被销毁，焦点自然回落到 `BODY`。

**建议修法**（与 D-3 同一处修复，收益叠加）：
1. 选牌不重建 DOM，只切 `.card.is-sel` 类 → 焦点天然保留；
2. 若短期不改渲染，则在 `render()` 后按 `data-id` **恢复焦点**（`lastFocusedId` 记在模块级，paint 后 `querySelector` 回填）。

**验收断言**：键盘选中一张牌后 `document.activeElement` 仍是那张牌；再按 Enter 能取消选中。

### E-3 [P2] 设置项只有开关本体可点，同一行的文字不可点

**现象**：点开关本体 → 生效；点同一行的文字「记牌器」→ **无反应**。规则页「2 为常主」文字同理。

**证据**：
```
=== ①-5 设置开关：点本体 vs 点同一行文字 ===
  点开关本体：false → true｜记牌器出现=true
  点同一行文字「记牌器」：true → true（期望翻转）
  点规则「2 为常主」文字：true → true
```

**根因**：`.set-row` 上没有绑定点击代理，只有 `.switch` 元素自己是可点区。

**影响**：移动端尤其明显 —— 开关本体只有 ~34×20px，远小于 44×44 的触控推荐尺寸，手指容易点空。

**建议修法**：给 `.set-row` 加 `data-act` 代理（点整行即切换），并把 `.switch` 的可点区用 `::before` 扩到 44×44。

### E-4 [P2] 手牌 `aria-label` 只报「第 N 张牌」，读不出是什么牌

**现象**：每张牌有 `aria-label="第 105 张牌"`、`role="button"`、`tabIndex=0`，**可读名称 0 缺失**（33 个可点元素全部有名字）。但 `aria-label` 会**覆盖**内部文本，屏幕阅读器只会念「第 105 张牌」，不会念「小王」。

**证据**：
```bash
node .tmp/e-audit/e4-a11y.mjs
```
```
[手牌可读名称抽查] [
 { "ariaLabel": "第 105 张牌", "innerSvgLabel": "小王",  "role": "button", "tabIndex": "0" },
 { "ariaLabel": "第 52 张牌",  "innerSvgLabel": "梅花2", "role": "button", "tabIndex": "0" },
 { "ariaLabel": "第 78 张牌",  "innerSvgLabel": "方片2", "role": "button", "tabIndex": "0" } ]
```

**根因**：`src/ui/card.ts` 里牌面 SVG 自带 `aria-label`（「梅花2」），但外层 `.card` 又设了 `aria-label="第 N 张牌"`，外层胜出。

**影响**：视障用户能 Tab 到手牌，但**完全无法知道手里是什么牌** —— 这个游戏对他们不可玩。

**建议修法**：外层 `aria-label` 改成「梅花2，第 52 张牌」；或在有牌面名称时干脆不设外层 `aria-label`，让内部 SVG 的 label 透出（并给 `.card` 加 `aria-pressed` 表达选中态 —— 实测已有 `aria-pressed`）。

**验收断言**：手牌元素的 `aria-label` 包含牌面名称。

### E-5 [P2] 设置面板的开关没有 `:focus-visible` 样式

**现象**：顶栏按钮与手牌有焦点框（`outline: auto 1px`，浏览器默认，很细但可见）；**设置里的 `.switch` 是 `matchesFocusVisible: false`、`outline: none`** —— 键盘 Tab 到开关时看不出焦点在哪。

**证据**：
```
[focus-visible 计算样式]
  [顶栏·新游戏]   {"matchesFocusVisible":true, "outline":"auto 1px rgb(16,16,16)"}
  [手牌第 1 张]   {"matchesFocusVisible":true, "outline":"auto 1px rgb(16,16,16)"}
  [设置·开关]     {"matchesFocusVisible":false,"outline":"none 3px rgb(0,0,0)"}
  [设置·标签]     {"matchesFocusVisible":true, "outline":"solid 2px rgb(24,95,165)"}
```

**根因**：`styles.css` 里给 `.set-tabs button:focus-visible`（:810）和 `.btn` 写了焦点样式，但 `.switch` 漏了；且 `.switch` 可能有 `outline: none` 重置。

**建议修法**：补 `.switch:focus-visible { outline: 2px solid var(--sel); outline-offset: 2px; }`，并把顶栏/手牌的 `auto 1px` 统一成同一套 2px 品牌色描边（默认 `auto` 在深色底上几乎看不见）。

**验收断言**：Tab 到任意开关时计算样式里 `outline-style !== 'none'`。

### E-6 [P2] 两处正文对比度不达 WCAG AA（< 4.5:1）

| 元素 | 对比度 | 字号 | 判定 |
|---|---|---|---|
| `.set-desc`（设置项说明文字） | **3.55** | 11.5px | ✗ 需 4.5 |
| `.seg button.is-on`（分段控件选中态） | **3.39** | 12.5px | ✗ 需 4.5 |
| `.set-sub` | 6.49 | 11.5px | ✓ |

| `.seg button`（未选中） | 5.65 | 12.5px | ✓ |

### E-7 [P2] 844×390 横屏：总音量滑条被裁在面板下沿之外，首屏点不到

**现象**：横屏 844×390 打开「设置 → 声音」后，总音量滑条位于 `y=355..371`，而面板可视底边是 `y=363` —— **滑条下半截被裁掉**，`document.elementFromPoint` 在滑条中心命中的是 `div.overlay`（遮罩）而不是滑条。此时鼠标拖动/点击都无效。

**证据**：
```bash
node .tmp/e-audit/vol-hit.mjs      # 定位遮挡
node .tmp/e-audit/vol-drag3.mjs    # 滚到底后再拖
```
```
滚动前 {"panelBottom":363,"sliderTop":355,"sliderBottom":371}
滚到底 {"scrollTop":158,"panelBottom":363,"sliderTop":197,"sliderBottom":213,"hit":"slider"}
拖动 75 → 18
```
```
topEl: "div.overlay"   isSlider: false
panel: { y:27, h:335, bottom:363, overflowY:"auto", scrollTop:0, scrollH:493 }
```

**关键结论（避免误判）**：这**不是**历史 bug「滑条完全无法拖动」的复发。滚到底后拖动正常（75 → 18）。真实问题是**首屏把重要控件裁在折叠线以下**，且被裁的那部分点击会打到遮罩上（可能顺手关掉面板）。

**同批复验的历史 bug（均未复发）**：

| 历史 bug | 复验结果 | 证据 |
|---|---|---|
| 音量滑条无法拖动 | **未复发**（竖屏拖动 75 → 18；横屏滚到底 75 → 18） | `vol-drag.mjs` / `vol-drag3.mjs` |
| 设置页每次点击跳回顶端 | **未复发**（点开关后 `scrollTop` 166 → 166） | `e3-out.txt` |

**建议修法**：`@media (max-height: 420px)` 下把声音页的滑条行改成更紧凑的布局（标签与滑条同行），或把「总音量」提到页面最前，保证首屏可见。

### E-8 [P3] 游戏中显示「第 X / 25 墩」，但实际墩数不固定

**现象**：状态栏写 `第 3 / 25 墩`，而一局实际可能只有 **24 墩**（实测 `d2c-ops.json` → `wEnd.tricks = 24`）。结算时已改成「共 24 墩」，但**出牌过程中仍写 `/ 25`**。

**证据**：`src/ui/render.ts:432-436`
```ts
s.phase === 'settle' || s.phase === 'over'
  ? `共 ${s.history.length} 墩`          // 结算：正确
  : `第 ${s.tricksDone + (s.phase === 'play' ? 1 : 0)} / 25 墩`   // 出牌中：写死 25
```
注释里已经写明「一墩出对子/拖拉机时一次耗多张牌，实际墩数会少于 25」，但只修了结算分支。

**建议修法**：出牌中改为 `第 N 墩`（去掉分母），或按剩余牌数估算上限。

## 4. 主观体验观察（非缺陷判定，供参考）

1. **`第 X / 25 墩` 会让人以为打不完** —— 见 E-8，用户看到 24 墩就结束会疑惑。
2. **设置面板滚到底后标签栏滚出视野** —— `.set-tabs` 不是 `position: sticky`（`styles.css:783`），滚到声音页底部再想换标签必须滚回去。
3. **顶栏「四色」/「记录」/「设置」/「新游戏」四个按钮字号偏小**（13px），移动端容易误触相邻按钮。
4. **结算面板出来后顶栏按钮被遮罩挡住** —— 用户想「再来一局」必须先找到结算面板里的按钮，顶栏的「新游戏」点不到。

## 6. 一句话结论

**布局和文案这两块是干净的（移动端零重叠零截断、术语泄露 0 命中、非法操作有具体提示），问题集中在键盘与可访问性：全局 Space 劫持让所有按钮的空格失效、整棵重建让键盘选牌后焦点掉到 BODY、手牌 aria-label 只报序号不报牌面 —— 三条叠加起来，视障和纯键盘用户实际上玩不了。**
