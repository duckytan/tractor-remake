# 01 · 项目章程

> 状态：`已定稿` ｜ 版本：v1.0 ｜ 日期：2026-10-22

## 1. 背景

《拖拉机大赛 Ver 1.1》是一款 1999 年的 Windows 单机游戏（PE32 / MFC 静态链接），
实现的是中国纸牌游戏「拖拉机 / 升级 / 80 分」。

游戏本体可以正常运行，规则实现完整、AI 有四个难度档，**玩法部分是合格的**。
唯一的问题是渲染层：

- 窗口客户区固定 **632×450**，不可缩放、无最大化、无全屏；
- 绘制全部走 `BitBlt`（1:1 位图拷贝），程序**未导入 `StretchBlt`**，物理上无法缩放；
- 牌面位图 **71×96** 像素，在 2K（2560×1440）显示器上物理尺寸不足 3 厘米；
- 强行拉大窗口只会露出未绘制区域（白边），因为 `CCardView` 的消息表里**没有 `WM_SIZE`**。

⇒ 结论：**原架构不存在「保留二进制、替换 UI」的中间路线**（证据见
`rules/逆向分析报告-03-规则引擎闭合.md` §17）。

## 2. 问题陈述

> 我想在 2K 显示器上舒服地玩这个游戏，但牌面看不清，窗口又放不大。

## 3. 项目目标

| # | 目标 | 可验证标准 |
|---|---|---|
| G1 | 规则 1:1 复刻原版 | 规格书中全部 `【确证】` 项均有实现与单测 |
| G2 | 牌面在任意分辨率下清晰 | 在 1080p / 2K / 4K 下牌面点数文字无模糊、无锯齿 |
| G3 | 窗口自适应 | 浏览器窗口任意尺寸下布局不破、不出现空白未绘制区 |
| G4 | 可玩完整一局 | 从定庄到升级结算，能连打多局直到终局 |
| G5 | 规则可验证 | 规则引擎可在 Node 环境独立跑测试，不依赖浏览器 |

## 4. 非目标（明确不做）

划清边界比列功能更重要，以下内容**本版本不做**：

| 非目标 | 原因 |
|---|---|
| 联网对战 | 原版网络层是空壳；联机会让工作量翻倍且分散对规则正确性的注意力 |
| 逐像素复刻原版 UI | 与原目标 G2 直接冲突 |
| 移植原版 AI 状态机 | 80 状态脚本 + 回溯搜索，且用洗牌打乱候选顺序，结果不确定（ADR-012） |
| 兼容原版 `Game.sav` 存档 | 格式是 MFC 序列化二进制，无外部价值 |
| 移动端专项适配 | 先保证桌面浏览器；触屏可作为后续增量 |
| 音效 / 语音 | 原版只有几个 wav，不影响核心体验 |
| 战绩排行 / 账号体系 | 单机游戏不需要 |

## 5. 范围

### 5.1 包含

- 完整规则引擎：发牌、定约、出牌合法性、压制、计分、升级、终局
- 单机对战：1 名人类 + 3 名 AI
- AI：至少 3 个难度档（对应原版的初/中/高级）
- 表现层：牌桌、手牌、出牌区、计分板、对话框、设置
- 存档：偏好设置 + 当前局进度（浏览器本地存储）
- 响应式布局：1366×768 至 4K

### 5.2 不包含

见 §4。

### 5.3 边界情况：与原版规则的差异

项目**主动**与原版不同之处（均需 ADR 支撑）：

| 差异 | 原版 | 本项目 | 决策 |
|---|---|---|---|
| 埋底 | 无，8 张底牌作废 | 有，庄家发牌即 33 张、埋底扣 8 张（v1.3.3 起） | ADR-006 |
| 扣底翻倍 | 无 | 有 | ADR-006 |
| 终局条件 | 无，级牌循环回 2 永远打不完 | 打王后再赢一局即胜 | ADR-011 |
| 甩牌失败 | 对子组失败时保留全部对子 | 只出最小的一张 | ADR-008 |
| 必打 | 判定在升级结算 | 同原版（修正早先误读） | ADR-010 |

## 6. 成功标准

项目视为成功，当且仅当以下全部成立：

1. 能在 Chrome / Edge 最新版打开即玩，无需安装；
2. 在 2560×1440 分辨率下，手牌点数一眼可辨（主观验收，截图留档）；
3. 完整打完一局（含升级结算），且结算数字与手工计算一致；
4. 规则引擎单测覆盖率 ≥ 90%（`src/core` 行覆盖）；
5. 连续对局 10 局无崩溃、无状态错乱（浏览器控制台零 error）。

## 7. 干系人

| 角色 | 职责 |
|---|---|
| 项目所有者 / 唯一用户 | 提出需求、验收、决定规则差异取舍 |
| 开发（AI 辅助） | 设计、编码、测试 |
| 上游逆向分析 | 提供规则事实，维护 `tractor-游戏规则规格书.md` |

单人项目，不设独立测试角色；测试由开发自测 + 自动化测试承担。

## 8. 约束

| 类型 | 约束 |
|---|---|
| 技术 | 浏览器环境；不得依赖需要原生编译的 npm 包 |
| 规则 | 一切规则以 `tractor-游戏规则规格书.md` 为准，不得凭记忆修改 |
| 素材 | 不使用原版位图；牌面自绘 |
| 版权 | 仅个人学习用途，不分发原版二进制 |
| 运行环境 | 现代浏览器（ES2022、CSS Grid、SVG）；不兼容 IE |

## 9. 假设

若以下假设不成立，需重新评估方案：

- A1：用户主要在桌面浏览器上游玩（非手机）
- A2：单机对 AI 已能满足需求，不需要真人对手
- A3：原版规则规格书已闭合，无需再补逆向
- A4：108 张牌的规模下，纯 TypeScript 性能绰绰有余
