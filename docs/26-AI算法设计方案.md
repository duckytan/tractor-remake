# 26 · 自研 AI 算法设计：意图驱动 + 双层评估

> 综合 docs/23（现状与瓶颈）、docs/24（三版对比）、docs/25（外部资料）、
> `reference/DouDiZhu-ai/`（手牌权重框架源码）、**docs/27（人类技巧 → 算法规则映射）**。
>
> **结论：能做出属于我们自己的算法，而且不是三方拼凑。**
> 核心创新有两处：**意图驱动的候选生成**、**概率化的对手模型**；
> 另外三处是把别人的优点改造成适配拖拉机的形式（分牌资产化、阶段权重、埋底绝门）。

## 0. 先说清楚「拖拉机 AI 到底在优化什么」

这是整个设计的出发点，也是最容易被抄错的地方：

| 游戏 | 目标 | 直接后果 |
|---|---|---|
| 斗地主 | **先跑光手牌** | 手牌越少越好，牌是负担 |
| 拖拉机 | **抢分 + 保级** | 分牌（5/10/K）是**资产**，跑光手牌只是手段 |

所以：
- 抄 DouDiZhu 的「手数越少越好」会得到**只会跑牌、不会抢分**的 AI
- 抄原版系的决策树会得到**会打但不会规划**的 AI

我们的目标函数应该是：

```
最大化  我方得分 − 对方得分        （单局）
受约束于 保级 / 上台                （跨局）
```

中间量：**每一墩的「期望净得分」**。

## 1. 三方资料各贡献什么

| 来源 | 拿什么 | 怎么改 |
|---|---|---|
| **原版系**（tractor / smallnest） | 埋底**扣绝一门**、首出**递牌给队友**、跟牌**按位置分策略**、缺门时**明确判毙**、首出**甩牌** | 不抄 3100 行决策树，把这些拆成「候选生成规则 + 评估特征」 |
| **DouDiZhu** | **手牌质量**（手数 / 大牌 / 结构）、递归拆牌 + 哈希缓存、候选用 `PermutationCombine` 组合 | 手数改成「按花色槽算」；**分牌从负担翻转为资产** |
| **我们现有** | **前瞻**（出完会不会被压）、精确压牌判定、**可标定**（权重常量 + 座位互换配对） | 前瞻从「二元判断」升级为**概率估计** |
| **学术**（ISMCTS / Klaverjas） | 「信息集」意识：完美信息是已知的低效简化 | 短期不上搜索，但把「对手模型」显式化，为将来留口子 |

## 2. 核心创新一：意图驱动的候选生成

### 2.1 为什么不是穷举

现做法（`enumerateFollows`）只给 2 个候选，等于把选择权砍掉了。
但穷举也不行：25 张手牌的组合是天文数字，而且**绝大多数候选是明显愚蠢的**。

**人类打牌不是穷举，是按意图找牌**：想抢分就找能赢的、想保分就找最小的非分牌、
想清门就把短门打光。所以候选应该**按意图生成**。

### 2.2 六种意图

每个意图最多生成 2~3 个候选，总量 15~20 个 —— 比现在多一个数量级，
但每一个都是「人真的会考虑的出法」。

| 意图 | 触发条件 | 生成什么 |
|---|---|---|
| **抢分** `grab` | 墩内已有分 ≥ 5，且我有能赢的牌 | 能赢的最小 / 能赢的最大（两个） |
| **保分** `protect` | 墩内已有分 ≥ 5，但我赢不了 | 垫牌里**分最少**的 / 垫牌里**牌力最低**的 |
| **清门** `void` | 首出，且某门 ≤ 3 张 | 把该门一次打光（单/对/连对里能一次出完的） |
| **逼牌** `pressure` | 首出，且我主牌多 | 副牌里的绝对大牌（逼对手用主牌毙） |
| **递牌** `feed` | 首出，队友在某门有绝对大牌 | 该门最小的一张（原版系的招） |
| **兑现** `cash` | 我手里有「绝对大」的牌（全场没人能压） | 直接出（防被毙、顺便吃分） |

**为什么这样比穷举好**：
- 覆盖了人类的主要打法（原版系的 7 段优先级本质就是这几种意图的排序）
- 每个意图只挑代表，候选数可控
- **意图本身可以作为评估的先验**（抢分意图出的牌，评估时天然加分）

### 2.3 甩牌怎么生成

甩牌 = 同一门里「多组牌」一次出。合法前提是每组都是全场最大。

生成方式：对该门按 `analyze` 分组，从「最大的组」开始逐个往回收，
每加一组就校验一次「每组都是全场最大」（用现有的 `checkLead` 逻辑），
合法就作为一个候选。

## 3. 核心创新二：概率化对手模型

### 3.1 现做法的问题

`exactBeatable` 的判断是：**对手手里有更大的牌 ⇒ 我一定会被压**。
但真实对手会：
- 省牌（墩内只有 5 分，不值得用主牌毙）
- 保结构（不想拆对子）
- 让队友（队友已经赢着就不压）

所以现在是**系统性悲观**，导致 AI 不敢兑现大牌。

### 3.2 改成概率

```
P(被压) = 1 − Π(1 − P(第 i 家会压))
P(某家会压) = P(他有能压的牌) × P(他会选择压 | 他有)
```

- `P(他有能压的牌)`：完美信息下是 0/1，但我们**按他的意图反推** ——
  如果他压我需要拆对子 / 用掉唯一的主牌，概率打折
- `P(他会选择压 | 他有)`：用一个简单的价值门槛 ——
  墩内分越高、他越可能压；他剩余主牌越少、越可能压

这样前瞻从「会不会被压」变成「**期望损失** = P(被压) × 墩内分 × 归属翻转」，
而不是「一定被压」的硬扣分。

### 3.3 为什么这是我们的独家

- 原版系**完全没有前瞻**
- DouDiZhu **不建模对手**（斗地主一轮出完就过）
- 学术上的 ISMCTS 是「采样多个可能世界」，我们是「在完美信息下估计对手行为概率」——
  **更轻、更快、且保留确定性**（用固定 rng，可复现）

## 4. 评估函数：双层结构

```
Score(action) = w_h · ΔHQ(action)          ← 手牌质量变化（DouDiZhu 思想，改造）
              + w_t · TrickEV(action)      ← 这一墩的期望净得分（我们的强项）
              + w_c · ControlShift(action) ← 首出权 / 主牌控制的变化
              + w_m · TeamValue(action)    ← 对队友的影响
```

### 4.1 手牌质量 `HQ`（借鉴 DouDiZhu，按拖拉机重写）

```
HQ(hand) = a₁·(−手数) + a₂·(绝对大牌数) + a₃·(主牌控制) + a₄·(结构完整度) + a₅·(分牌保有)
```

- **手数**：按花色槽分别拆（单/对/拖拉机各算一手），主牌单独一槽。
  手数少 ⇒ 更容易清门、更容易保首出。
- **绝对大牌数**：全场没人能压的牌（用完美信息算）。这是拖拉机里最硬的资产。
- **主牌控制**：主牌张数 + 王的数量。决定能不能毙、能不能逼。
- **结构完整度**：完整拖拉机 > 散对 > 单张。
- **分牌保有**：手上还有多少分（**正号！** 斗地主里是负担，这里是资产）。

`ΔHQ = HQ(手牌) − HQ(手牌 − 这手)` —— 与 DouDiZhu 的 `removeSubset + calcPowerValue` 同构。

### 4.2 墩期望 `TrickEV`

```
TrickEV = (1 − P(被压)) × (墩内分 + 未来分) × 归属符号
```

- 我方赢墩：`+ (墩内分)`
- 对方赢墩：`− (墩内分)`
- `P(被压)` 来自 §3 的概率模型
- 「未来分」= 赢了这墩之后，首出权带来的期望收益（可以粗略估为 `底分 × 0.3`）

### 4.3 控制权 `ControlShift`

- 出主牌 ⇒ 控制力下降（负）
- 赢墩 ⇒ 拿到首出权（正）
- 但只在「这手白花」时计负（沿用 L3 的教训：赢了不算亏）

### 4.4 团队 `TeamValue`

- 队友已领先：我压过去是**负**（抢队友的分）
- 队友缺门：我出他那门的小牌是**正**（递牌）
- 队友在毙牌：我别抢

## 5. 阶段自适应权重

固定权重是现有设计的局限 —— 前期该试探、后期该保分，权重应该不同。

| 阶段 | 判据 | 权重倾向 |
|---|---|---|
| **开局**（前 1/3 墩） | `tricksDone < 8` | 重 `ΔHQ`（清门、保结构），轻 `TrickEV` |
| **中局** | `8 ≤ tricksDone < 18` | 均衡，`TrickEV` 权重最高 |
| **收官** | `tricksDone ≥ 18` | 重 `TrickEV` + `ControlShift`（每一分都要争） |

阶段判据还可以加「分数进度」：闲家得分接近 80 时，庄家方要拼命拦分。

## 6. 埋底：扣绝一门 + 保分

> 人类经验的完整版见 docs/27 §2 与 §7 的伪代码（6 条规则 + 硬约束 + 无将局特例）。

现做法（按牌力扣最弱 8 张）有三个问题（见 docs/23 §4.3）。新算法：

```
1. 统计四门副牌张数
2. 选「张数最少的一门」作为目标缺门（张数 ≤ 8 才能扣绝）
3. 该门按牌力从低到高扣，直到扣够 8 张
4. 如果该门不够 8 张：
   - 从其他门继续扣，但**优先扣非分牌**
   - 不拆完整的对子/拖拉机（拆了就是废牌）
5. 绝不扣「绝对大牌」（留着毙牌 / 兑现）
```

实测指标：底分（`cardsScore(buried)`）应该显著下降 —— 这是可直接验证的。

## 7. 亮主 / 反主：从「看张数」到「看质量」

```
亮主分数 = 该门张数 × 1.0
         + 该门绝对大牌数 × 2.0
         + 主牌张数 × 0.5
         + (手上分牌数 × 0.3)          // 有分更想坐庄（底牌能藏分）
门槛：≥ 5 分才亮（现在是「≥3 张 + 100% 必抢」）
```

反主：新主的分数 **必须显著高于** 现主（+3 分以上），否则不反。
（原版系的「该门级牌数 > 四门平均」是个不错的代理指标，可以并入。）

## 8. 复杂度与性能

| 环节 | 现做法 | 新做法 | 估算 |
|---|---|---|---|
| 候选生成 | 2~3 个 | 15~20 个（6 意图 × 2~3） | 可忽略 |
| 单候选评估 | 线性特征 | `ΔHQ` 要递归拆手牌 | **需缓存** |
| 手牌质量 | 无 | 递归 + 哈希（DouDiZhu 同款） | 每帧 1 次 `HQ(手牌)`，候选只算 `HQ(手牌−这手)` |

关键优化（直接抄 DouDiZhu 的经验）：
- **哈希缓存**：`HQ` 的 key = 手牌签名（花色槽 × 点数计数）
- **固定提取顺序**：拆牌时每次先提最大面值的组，把 `P(N,M)` 降到 `O(N+M)`
- 实测参考：DouDiZhu 用这两招把 0.5~3 秒降到几十毫秒

我们的手牌只有 25 张（斗地主 17~20），更轻。

## 9. 可标定（保留我们的优势）

所有权重（`w_h / w_t / w_c / w_m`、`a₁~a₅`、阶段阈值）都是**具名常量**，
放在一个 `HQ_WEIGHTS` 对象里，并沿用现有的测量协议：

```
座位互换配对测量（300 副 × 2 = 600 次），自检「同档对同档 = 0%」
```

新增两档的定位建议：
- **L2「强」**：意图候选 + `ΔHQ` + 固定权重（不区分阶段）
- **L3「超强」**：+ 概率化对手模型 + 阶段自适应权重

这样两档的差异是**可解释的**（不是靠调参数堆出来的 6%）。

## 10. 实施步骤（每步都可独立验证）

| 步 | 内容 | 验证方式 |
|---|---|---|
| **1** | 意图驱动的候选生成（替换 `enumerateFollows` / `enumerateLeads`） | 候选数从 2~3 → 15~20；跑标定看 L2 是否提升 |
| **2** | `HQ` 手牌质量 + 哈希缓存 | 单测：已知手牌的 HQ 排序合理；性能 < 5ms |
| **3** | 评估函数接入 `ΔHQ` | 标定：L2 vs L1 应显著 > 59.2% |
| **4** | 概率化对手模型 | 标定：L3 vs L2 应 > 57.7% |
| **5** | 埋底绝门 | 单测：底分显著下降；标定看庄家胜率 |
| **6** | 亮主/反主质量评估 | 单测：给定手牌应/不应亮 |
| **7** | 阶段自适应权重 | 标定：分阶段对比 |

**第 1 步就能拿到大部分收益** —— 因为瓶颈在候选集（docs/23 的结论）。

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| 候选变多后，权重更难调 | 分步实施，每步只加一个变量，跑标定再进下一步 |
| `HQ` 递归太慢 | 哈希缓存 + 固定提取顺序；先测单次耗时 |
| 概率化对手模型可能引入新的偏差 | 保留「硬判定」作为对照组，标定里直接比 |
| 完美信息假设迟早要改 | 把 `opponents` 的读取收敛到一个函数，将来换成「推断手牌」只改一处 |
| 改完反而变弱 | 每一步都有标定；**不允许为了让测试变绿而调低阈值**（沿用现有约定） |

## 12. 一句话总结

**「意图驱动的候选生成」+「手牌质量与墩期望的双层评估」+「概率化对手模型」**
—— 这三样组合起来，原版系和 DouDiZhu 都没有：

- 原版系有意图（决策树），但没有评估、没有前瞻、无法标定
- DouDiZhu 有手牌质量，但目标是跑牌、不建模对手
- 我们有前瞻和标定，但候选集残缺

把三者的强项按「拖拉机在抢分」这个前提重新组织，就是我们的专属算法。
