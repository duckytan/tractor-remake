## 三司结论

### 朱熹（明辨决）· 6+1 步 · 确信度：高

**① Pre-Mortem**（这个方案失败最可能怎么死）：
- 死法 A：**插件被静默踢掉**，后面几十局其实是内置机器人在打 ⇒ 我们测的是它，不是我们。
- 死法 B：卡在 C# 编译（沙箱拦）/ 卡在 UI 自动化。
- 死法 C：赢是赢了，但赢在它的规则口径下（甩牌校验/连对长度不同）⇒ 结论不可迁移。

**② 实证核验（5 条假设，逐条判定）**：

| 方案里的假设 | 核验结果 |
|---|---|
| 「放个 DLL 进 plugins/ 就生效」 | ✅ 成立（反射加载，不需重编译主程序） |
| 「牌 id 映射是中等风险」 | ✅ **比估计的低**：54 个 id、重复位表示两副牌，映射表 6 行 |
| 「插件看不到别家手牌，只能走 belief（27.5%）」 | ⚠️ **过于悲观**：`sendCards[i]` 是**每家整局累计出过的牌**，信息量比我们的 belief 输入更全 |
| 「自动化跑 100 局、纳入 CI」 | ❌ **不成立**：无 headless，只能 UI 自动化；**进不了 CI** |
| 「插件只是被调用」 | ❌ **漏了致命细节**：一次非法即 `UserAlgorithms[seat]=null` 永久踢掉并降级（事实 4） |

**③ 追问性对抗 —— 本司独立发现 3 条**：

- **F1（🔴 方案级漏洞）· 静默降级会污染全部成绩**
  事实 4：`IsInvalid/CheckSendCards` 不过 → 永久置空 + 回退内置。
  **如果我们不检测"插件还在不在被调用"，跑完 100 局得到的胜率可能是内置机器人的胜率。**
  必须做成硬检测：每次决策带自增序号，**序号断流即判定被踢**，该局作废。

- **F2（🟡 口径修正）· "只能走 belief"是错的**
  事实 5 给的是**整局每家出过的牌**。由「108 张 − 我看得见的」可推出各家剩余牌型，
  信息严格强于我们的 `belief`（后者只吃 history + 我的手牌）。
  所以这条路径测出来的强度**高于 27.5%**，我方案里的悲观预设需要撤回。

- **F3（🟡 工程可行性）· "纳入 CI"这句必须删掉**
  事实 6：没有 headless 入口。CI 里跑 Windows GUI + 模态对话框是灾难。
  正确的口径是"**半自动批量**：人工点开局，脚本读分与记局"。

**④ 根因**：我把"接口存在"直接推成了"端到端可行"，**跳过了三处关键实现细节**
（加载方式、容错行为、无头能力）。

### 六祖慧能（破妄诀）· 11 截面 · 确信度：高

**① 我执（把"能对打"当"有锚"）**：锚的四个要素是 **对手独立 / 裁判独立 / 计分公开 / 样本足够**。
方案 A 只拿到前两个，后两个（计分由我们记、样本 60~100 局）仍在我手里。
严格说它是"**半外部锚**"——比自洽强，但不是 Suphx 那种"天凤段位"。

**② 法执（把参照物当强）**：我们把 smallnest 的机器人默认当"强参照"。
但它 1999 年的代码，且我们早就记录过它的缺陷（甩牌只比最大一对、只认 2 连对）。
**如果它很弱，我们赢 60% 也不能证明"接近人类"** —— 只能证明"比它强"。
报告措辞必须写成"vs 参考实现"，不能写"强/弱"。

**③ 空执（把结果当结论）—— 本司独立发现 1 条**：

- **F4 · 规则口径污染**：即使跑通，也是在**它的规则**下（甩牌校验口径、连对最长 2、2 为常主可配）。
  我们赢的可能是"它的规则漏洞"，而不是"我们的 AI 强"。
  ⇒ 必须出一张**规则差异对照表**，并且**只在"两边规则一致"的局面里统计胜率**（或者明确标注"口径 = smallnest"）。

**④ 共识妄执**：我在 docs/41 里写"真正的外部锚不是更强的对手，而是判定权不在你手里的比赛"——
漂亮话。**判定权在它手里，但计分权仍在我手里**（我自己读窗口分数、自己判"这局算不算"）。
这句话需要降级为"判定与对手在它那边，计分与样本仍在我们这边"。

### 老子（五行诀）· 5 维 · 确信度：中高

**① 太初（拆到最小）**：一次"有效对局"的最小条件 =
插件被加载 → 出牌被接受 → 全程没被踢 → 打完 → 分数可读。**五步里前四步全部没验证过。**

**② 观复（能不能重复）**：无 headless ⇒ 每次都要人守。
**这是本方案最大的工程风险，比 C# 编译更大**（编译只一次，守夜要几十次）。

**③ 洞观（看不见的）**：它机器人强弱未知；规则差异未量化；**队友效应**——
我们只占 1 席、3 席是它的机器人，一局的胜负很大程度由"队友"决定 ⇒ 方差压过信号。

**④ 颠倒（怎么保证失败）—— 本司独立发现 1 条**：

- **F5 · 单席 vs 三机器人 = 高方差**
  同一批牌只换我们坐哪一席，结果可能天差地别。若不做**座位互换配对**（我们 1/3 位 vs 2/4 位各打一遍），
  60 局也读不出结论 —— 而我们的标定早就踩过这个坑（座位偏差：奇数位整体占优）。

**⑤ 知几（下一步最可能踩的坑）**：**C# 编译**与**插件被静默踢掉**。
前者一次性、可绕过（用户本机执行），后者是**长期隐性污染**，必须优先做检测。
