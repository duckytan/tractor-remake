## 3. M2 · 规则引擎闭环 ★ 最关键

**这个里程碑决定项目成败。** UI 可以慢慢磨，规则错了要推倒重来。

### 实施顺序（严格按依赖）

```
① cards.ts      牌值编解码 + buildPowerTable
② rng.ts        mulberry32 + shuffle
③ deal.ts       发牌 + 禁止天然连对
④ analyze.ts    分组 + 牌型识别
⑤ legality.ts   首出 / 跟牌 / 甩牌
⑥ trick.ts      一墩判定
⑦ score.ts      计分 + 扣底
⑧ settle.ts     升级 + 必打 + 终局
⑨ types.ts      收敛全部类型（最后统一，避免中途反复改）
⑩ index.ts      barrel 导出
```

### 每步的完成标准

| 步骤 | 完成标准 | 规模 |
|---|---|---|
| ① | TC-001 ~ TC-009 全绿 | M |
| ② | 相同 seed 输出一致；`shuffle` 是均匀排列 | S |
| ③ | TC-101 ~ TC-108 全绿，含 64 组合校验 | L |
| ④ | TC-401 ~ TC-410 全绿，**尤其 TC-403 连对不判甩牌** | M |
| ⑤ | TC-501 ~ TC-518 全绿，**尤其 TC-513/516** | L |
| ⑥ | TC-601 ~ TC-607 全绿 | S |
| ⑦ | TC-701 ~ TC-708 全绿 | S |
| ⑧ | TC-801 ~ TC-811 全绿 | M |
| ⑨⑩ | `tsc --noEmit` 无错；`grep` 确认 `core/` 无浏览器 API | S |

## 8. 依赖关系与关键路径

```
cards ─┬─► analyze ─┬─► legality ─┬─► trick ─► score ─► settle
       │            │             │
rng ───┴─► deal ────┘             └─► enumerate ─► ai
                                        │
store ─► reducer ─► machine ────────────┘
   │
   └─► ui/card ─► ui/hand ─► ui/table ─► ui/status
```

**关键路径**：`cards → analyze → legality → trick → score → settle`

这条链上任一环延期，整体延期。**优先保证它不被 UI 打断**——
建议 M2 阶段完全不碰 UI，专心把 core 写完并用 Node 测试验证。

**可并行**：`ui/card` 与 `core` 无依赖，可在 M2 期间穿插做，
但不要因为 UI 好看就提前进入 M3。
