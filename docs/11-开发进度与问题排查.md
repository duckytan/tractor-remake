## 2. 与原版不一致的问题排查（综合）

> 以下均按「当前代码 + 规则书」双向确认，区分「真实差距」「与原版一致（用户记忆偏差）」「文档矛盾」三类。

### 2.1 【用户点 1】没有发牌过程 / 抢庄 —— 部分成立，需澄清

- **发牌动画缺失（确证，真实差距）**：当前 `src/ui` 无任何发牌动画；`startRound`（`src/app/game.ts`）一次性把 25 张塞进每家手牌，牌直接呈现。原版有发牌动画（逐张/分批落位），「过程感」缺失。建议补一个发牌序列动画，受 `animation` 开关控制。
- **抢庄（bidding 定庄）**：规则书 §3.1 明确「庄家是随机产生的（`rand()%4+1`），**不是亮主定庄**」。即**原版本身就没有抢庄**。remake 的随机定庄（`startRound` 中 `dealer = rng.int(4)`）与原文一致 —— 此处 remake 实际**还原了原版**，用户感知的「无法抢庄」可能来自记忆中另一版拖拉机（很多联网版有亮主定庄/抢庄）。
  - ⚠️ **需向用户确认**：是否要**新增**抢庄玩法？若是，属功能增强，不在原版还原范围，需新开 ADR。
- **亮主时机与加固（差异，非阻断）**：规则书 §3.6 + 差异表（需求书 line 774）指出，原版是「发牌过程中随时亮主，可反主、可加固（对子/王）」，remake 是「发完牌后一次性 5 按钮选主」。**加固**（用对子/王提升主牌强度）remake 未实现。

### 2.2 【用户点 2】手牌排序不是拖拉机方式 —— 确证，真实差距，**已修复**

**根因（已定位到代码）**：`sortHand` 原先只有一行
`[...hand].sort((a,b) => ctx.power.get(b.value) - ctx.power.get(a.value))` —— 全局按牌力降序。
而 `buildPowerTable` 给**四门副牌的同一点数编了相同牌力**（副牌 A 与副牌 K 之差在所有门相同），
于是按牌力排会把**四张 A 排到一起、同花色被拆散**，正是「不是拖拉机排序方式」的观感来源。

**权威算法（用户确认基准：smallnest/Tractor，`CurrentPoker.Sort()`）**：

```
[大王] → [小王] → [主级牌] → [副级牌] → [主2 → 副2] → 主花色(点数降序)
      → 其余三门按 ♥ ♠ ♦ ♣(点数降序)；无将时四门全按 ♥ ♠ ♦ ♣
```

配套逻辑（`CommonMethods.parse` / `GetSuit`）：
- **只有王和级牌是主牌**，没有「2 为常主」——`GetSuit(a, suit, rank)`：
  `a==52||a==53 → trump`、`a%13==rank → trump`、否则按 `a/13` 归门。
- 花色编码 `♥0-12 ♠13-25 ♦26-38 ♣39-51 王52/53`；`SubRank = 四花级牌总数 - 主级牌`。

**修复（已完成）**：`src/app/game.ts` 的 `sortHand` 重写为
「① 主牌整段在前（按牌力降序）→ ② 副牌段**花色优先**、花色内点数降序」，
并列牌力再用「花色次序 + 点数降序」收尾，保证输出与输入顺序无关、可复现。
AI 埋底的「留大牌」另用 `sortByPowerDesc`（展示序与埋底序解耦）。
测试 `tests/app/sortHand.test.ts`（7 例，含原版截图那一手牌的完整期望序列）。

> **原版 UI 的实际展示序（据用户提供截图）与 smallnest 不同**：原版是
> 「♦ ♣ ♠ ♥ 四门**升序** + 末尾一组主牌杂牌（级牌/常主2）」；
> smallnest 是「主花色**降序**在前 + ♥ ♠ ♦ ♣ 降序」。
> 按用户「smallnest 规则可信、甚至比原版还好」的判断，重制版取 smallnest 方案。

**附带发现（原版开了「2 为常主」）**：用户提供的 `出牌.png` 中，手牌尾部
`2♣ 3♣` 单独成组、与 ♣4,6,7,7,8,9,Q,A 分开 —— 级牌是 3，`2♣` 却仍被当作主牌，
说明原版该局 `mode=1`（2 为常主）。重制版已有 `twoAsPermanent` 开关支持，
**默认值需与用户确认**（原版该局为开，smallnest 无此规则）。

### 2.3 【反主缺失】—— 确证，真实差距，**已修复**

- **原状**：`canCounter` 在 `src/` 中**不存在**；`declareTrump` 是一次性逻辑 —— 写完 `trump` 后立即转 `bury`/`play`，**没有任何路径回到 `contract` 重新定主**。设置面板里的 `allowSelfCounter` / `allowCounterNT` 是**死配置**。
- **需求要求**：FR-04 ②「反主必须持有**新花色**的级牌」、FR-15 状态序列「亮主(可反复反主)」、ADR-009 自身决策文字「发完牌 → 5 按钮 → 可反主（需新花色级牌）」。
- **CHANGELOG 错误**：原「与原版一致的规则（明确保留）」列了「反主需新花色级牌」，与代码事实相反 —— 已改为「已实现」。
- **修复（已完成）**：
  - `src/core/counter.ts` — `canCounter()` 纯函数，对齐原版 `FUN_004163A2`：
    持新花色级牌 / 打王级不可被覆盖 / 不能反成同一主 / 同队反主受「允许自反」约束 / `usedTrumps` 防重复
  - `src/app/game.ts` — `declareTrump` 区分「首次亮主」与「反主」；`resolveContract` 跑 AI 反主循环后判断人类是否还能反；`passCounter` 放弃反主
  - `src/ui/render.ts` — 反主面板（标题「反主」、按 `counterOptions` 置灰、带「过」按钮）
  - 状态新增 `trumpDeclarer` / `usedTrumps` / `counterPending` / `counterOptions`，`STATE_VERSION` 升到 2（旧存档自动作废）
  - 测试：`tests/core/counter.test.ts`（9 例）+ `tests/integration/counter.test.ts`（6 例）
- **遗留**：打王级目前一律不可反（依 §3.5「不可被花色覆盖」），`allowCounterNT` 仍为保留项。

### 2.4 【已澄清】埋底：三方口径不同，我们与 smallnest 一致

- **代码（确证已实现）**：`declareTrump` 庄家收 8 底牌 → 手牌 33 张 → `finishBury` 扣 8 张回底。
- **原版（1999）**：**没有**埋底。底牌数组只写不读、0 处访问（`docs/rules/逆向分析报告` §16.6，三条独立证据）。
- **smallnest**：**有**埋底。`MainForm.cs:481-490`（庄家选满 8 张）、`DrawingFormHelper.cs:240-254`（底牌 = 各家 index 25/26）、`TractorRules.cs:930-937`（扣底 ×2/×4/×8）。
- **结论修正**：既然规则基准已改为 smallnest，则我们**是「对齐」状态，不是「增强」**。
  之前 `CHANGELOG.md` 把它记成「与原版差异（本项目新增）」—— 那是相对原版说的，成立；
  但相对 smallnest 不成立，容易误导后续判断。
- **规则书 §14.2 line 768** 写「原版有埋底、remake 完全没有、建议加上」—— 该段仍是**错误描述**（原版确实没有），待修正。
- **处置**：见 `docs/13-开发方案升级.md` §2「不改的（我们主动的增强）」—— 埋底/扣底已从「增强」改判为「对齐」。

### 2.5 其他待核对细节（建议列入下一步排查）

## 5. 结论

代码工程完成度高（M0–M6 全绿，**193 单测**（含本轮新增排序 7 例 + 反主 15 例）+ 11 E2E，已上线 GitHub/Vercel）。**与原版还原度**方面：

- 「无发牌过程」—— 发牌动画确为真实差距（P1 待做）；「抢庄」则原版本就无（§3.1 随机定庄），属用户记忆偏差，需确认是否要做增强。
- 「手牌排序不对」—— **确证真实差距，已修复**：根因是牌力表给四门副牌同点数编了相同牌力，按牌力排会把四张 A 排一起、同花色拆散。已改为 smallnest `CurrentPoker.Sort()` 的「主牌段 → 主花色降序 → ♥♠♦♣ 降序」，并让定主阶段也按展示序排好。
- 「细节不符」—— **反主已补齐**（此前直接违反 FR-04 ② / FR-15 / ADR-009）；另修正了规则书里埋底的错误描述。

**规则基准已定**：用户确认「smallnest/Tractor 规则可信，甚至比原版还好」，
因此重制版以 `reference/smallnest-Tractor`（`Tractor.net/CurrentPoker.cs`、`CommonMethods.cs`、
`Algorithms/TractorRules.cs`）为规则基准，原版二进制逆向结论作为佐证与差异记录。
两者已确认的一处实质差异：**原版该局开了「2 为常主」，smallnest 没有这条规则**。

**两个 P0 已全部清零**。剩余最高优先级是 P1 的发牌动画（恢复「过程感」）。
