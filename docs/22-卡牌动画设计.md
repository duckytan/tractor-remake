# 22 · 卡牌动画设计（发牌 / 出牌 / 收墩）

> 本文只讲 `src/ui/dealFly.ts` 与 `.deal-fly` 层。
> 规则相关的动画触发条件在 `src/ui/fxDiff.ts`（纯函数，可单测）。

## 1. 为什么是「幽灵牌」而不是 CSS 动画

`render()` 每次 paint 都 `root.innerHTML = ...` 整棵重建，卡牌元素是全新的。
挂在元素上的 `animation` 会在下一次 paint（发牌时每 55ms 一次）随元素一起消失 ——
玩家看到的是「牌凭空出现在手上」。

所以所有卡牌动画都走同一个机制：

1. 真牌先藏（`.card--incoming` + `inFlight` 集合，`visibility: hidden` 保留布局）；
2. 在**不随 render 重建**的固定定位层 `.deal-fly` 里放一张等尺寸克隆牌；
3. 逐帧写 `transform`（`left/top` 定死起点，位移全交给 rAF）；
4. 结束那一帧删克隆牌、揭开真牌。

终点必须**每帧重算**：手牌是居中排布 + 按张数反算重叠率，开局量好的坐标 300ms
后早就不是那张牌的位置了。

## 2. 三条轨迹的规格

| 轨迹 | 起点 | 终点 | 基准时长 | 弧高 | 淡出 |
|---|---|---|---|---|---|
| 发牌 | 牌堆 `[data-slot=deck]` | 手牌那张牌 / 三家牌背 | 320 / 260ms | 24 / 20px | 无 |
| 出牌 | 手牌那张牌 / **单张**牌背 | 出牌区那张牌 | 280ms | 14px | 无 |
| 收墩 | 四家出牌区的每张牌 | 桌面内、朝赢家方向推出一段 | 340ms | **6px** | 0.28 起淡到 0 |

所有时长都乘 `ANIM_SPEED_SCALE`（慢 1.6 / 中 1 / 快 0.6），见 `animMs()`。

## 3. 收墩动画：为什么不能「飞到赢家手上」

v1.3.17 及以前，收墩是「四家的牌飞向赢家的手牌区 / 牌背区并淡出」。
玩家反馈：**这一墩玩家最大时，桌上的牌全往玩家这边飞，会遮挡手牌**。

三个问题叠在一起：

1. **物理上必然遮挡**：人类出牌区（`plays-mine`）就贴在手牌正上方
   （实测出牌区 y≈516，手牌 y≈522），落点取手牌包围盒 ⇒ 牌一定压在手上。
2. **隐喻是错的**：收墩的牌**不进手牌**（只记分），飞到手上是错的动作。
3. **四个方向都有同一个毛病**：AI 赢时飞向它的牌背区，一样压住牌背和座位标签。
   这不是「玩家侧要特判」，是公式选错了落点。

### 3.1 最终落点公式

```
box   = 本墩四家出牌区所有牌 rect 的并集包围盒
dir   = 座位方向单位向量（0=下 1=左 2=上 3=右）
off   = min(min(box.w, box.h) * 0.4, 牌高 * 2.2)
anchor = box 中心 + dir * off
若 anchor 的落点方框压到禁入区 → off 按 15% 一档递减重算，直到不压
```

四个方向**同一套公式**，没有 `if (winner === HUMAN)` 这种分支 ——
所以「只改玩家」在结构上就不可能发生。

`off` 用「并集短边 40%」而不是固定像素：手机竖屏和桌面宽屏都能落在桌面内。

### 3.2 禁入区（`KEEP_OUT_SEL`）

```
[data-slot=hand] / [data-slot=handbar] / [data-slot=back-1..3]
.seat-tag / .topbar / .scorebar
```

两个必须记住的点：

- **`.seat-tag` 不只出现在三家头顶**：桌面正中那条「南（你）· 25 张」也挂在
  `.seat--center` 里，类名同样是 `.seat-tag`。漏掉它，落点正好压在自己的名字牌上。
- **但正中这一条又必须放行**：它的位置就是桌面几何中心，而四家出牌区的并集中心
  也在那儿。把它算进禁入区等于要求「收墩落点不许在桌面中间」，
  所有方向都会被逼回原点（实测就是这样卡住的）。
  收墩不改手牌张数，牌扫过它 0.2 秒没有信息损失 —— 真人用手抹牌也会扫过桌心。
  实现上用 `el.closest('.seat--center') !== null` 跳过。

### 3.3 起飞点必须用「单张牌」，不能用「整块区域」

`captureFx` 原来把三家牌背区存成 `[data-slot=back-N]` 的 rect —— 那是**一整条**
（实测 239×64）。拿它当 `from`，`w0 = from.width` 就会得到一张 239px 宽的巨牌，
先糊在牌背区上再缩回去。第 4 张牌从牌背区起飞时尤其明显。

改成取 `[data-slot=back-N] .card` 的**最后一张**（最新长出来的那张）。

人类侧同理：`prev.southHand` 是整排手牌的包围盒（实测 1244 宽），
只能当最后兜底，正常路径一律走 `handRectOf()`（先找那张牌，找不到用任意一张手牌）。

### 3.4 第 4 张牌的特殊路径

出牌与整墩结算发生在同一次 reduce 里，所以本墩第 4 张牌**桌上从未出现过**，
`prev.plays` 里没有它。它要单独从「手牌 / 牌背」直接飞到收墩点，否则会凭空消失。

**这个缺失还牵连了落点计算**：早先的兜底拿 `box + dir*0.35*boxSize` 去估那家的
出牌区中心，实测会把西家估到桌面中央（因为 `box` 中心本身已经偏了），
于是牌正好压在自己的名字牌上。现在落点只用「并集中心 + 方向向量」，
缺哪家的 rect 都不影响 —— 这是把落点从「赢家出牌区」改回「并集中心」的真正原因。

### 3.5 观感参数

| 参数 | 值 | 理由 |
|---|---|---|
| `COLLECT_SHRINK` | 0.5 | 收成一叠 |
| `COLLECT_STAGGER` | 16ms/张，上限 72ms | 「扫成一堆」有层次，不是四张同时平移 |
| `fadeFrom` | 0.28 | 前 28% 清晰，看清往哪个方向收；之后迅速消失 |
| `arc` | 6px | 出牌区正上方就是 `.seat-tag`，抬得越高越容易擦过标签 |
| `spin` | 7° | 收墩要比出牌（-6°）更「乱」一点 |
| `COLLECT_MAX_BATCH` | 2 | AI 瞬时速度下会墩接墩，超过两批直接跳过，避免满屏幽灵牌 |

淡出用 **raw（线性时间）** 而不是 `t`（easeOut）：easeOut 让 `t` 很早就接近 1，
淡出会变成「刚起飞就没了」。

## 4. 层叠顺序

| 层 | z-index | 说明 |
|---|---|---|
| 牌桌内容（手牌 / 牌背 / 出牌区） | 1 | `.felt > *` |
| 牌堆 | 1–3 | `.deck__layer` |
| **飞行层 `.deal-fly`** | **5** | 只要高于牌桌、低于遮罩 |
| 遮罩 `.overlay` | 20 | 面板弹出时压住一切动画 |
| 面板 `.panel` | 30 | |

v1.3.18 之前飞行层是 **25**，比遮罩还高 —— 动画撞上弹窗时牌会浮在遮罩之上。
降到 5 即可：它只需要盖过牌桌内容。

`pointer-events: none` 是必须的，否则动画期间会吞掉点击。

## 5. 怎么验证「没遮挡」

肉眼看不出来（0.3 秒一闪），用 DOM 采样：

1. `MutationObserver` 监听 `.deal-fly` 新增的 `.card`；
2. 只跟踪 `el.style.opacity !== ''` 的 —— **出牌/发牌飞行的 opacity 恒为空串**，
   而它们的起点本来就在手牌/牌背里，混进来会每一帧都 100%「重叠」，测不出真问题；
3. 逐帧 `getBoundingClientRect()`，与禁入区求交面积；
4. 跳过起步 90ms（第 4 张牌的起点就在手牌里，那是「被抽走」不是「遮挡」）；
5. `opacity < 0.25` 的帧不算（肉眼已看不见）。

脚本：`.tmp/check-collect.mjs`，跑 2~3 局覆盖四个方向。

实测结果（v1.3.18）：四方向最大重叠率 **0.0%**；同一脚本在改之前是
南 100%（`[data-slot=hand]`）、西/东 100%、北 99%（`back-2`）。

## 6. 已知取舍

- 牌会扫过桌面正中的「南（你）· 25 张」（理由见 §3.2）。
- 收墩落点停在「桌面内、朝赢家方向」，**不落在赢家出牌区上** ——
  偏移量受「并集短边 40%」限制，牌局很挤时方向感会弱一些。
- 收墩时「第 4 张牌」从手牌/牌背直接飞向收墩点，路径比另外三家短一点，
  但它本来就没在桌上出现过，观感上反而更连贯。
