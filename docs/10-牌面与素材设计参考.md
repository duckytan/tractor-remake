# 10 · 牌面与素材设计参考

> 状态：`已定稿` ｜ 日期：2026-10-22
> 目的：把「别人怎么做牌面」的经验整理成可执行的设计规格，替代此前过于简陋的草图。

## 1. 结论

| 项 | 结论 |
|---|---|
| 宽高比 | **1 : 1.4**（标准 poker size） |
| 角标规格 | 用 **Jumbo Index**（大角标），不用标准角标 |
| 布局 | 角标 + 传统 pip 排列（2~10），A 用单个大花色 |
| 花色符号 | **SVG path**，不用字体字形 |
| 缩放方式 | 单一变量 `--card-w` 驱动全部尺寸 |
| 配色 | 默认两色，**可选四色**（可访问性） |
| 牌组来源 | **自绘**（理由见 §8），但借鉴下列开源实现的设计 |

## 2. 行业基准数据

### 2.1 尺寸

| 规格 | 尺寸 | 比例 |
|---|---|---|
| **Poker size（标准）** | 63.5 × 88.9 mm（2.5" × 3.5"） | **1 : 1.4** |
| Bridge size | 57.15 × 88.9 mm（2.25" × 3.5"） | 1 : 1.556 |
| Mini size | 44.45 × 63.5 mm | 1 : 1.43 |

⇒ 本项目取 **1 : 1.4**，与 poker size 一致。

### 2.2 角标：Jumbo Index 才是我们要的

这是本次调研**最有价值的发现**。市面上「看得清」的扑克牌是一个独立品类：

| 品类名 | 特征 |
|---|---|
| **Jumbo Index** | 角标点数/花色显著放大，适合牌桌远距离阅读 |
| **LoVision** | 专为低视力人群，图标高 **1.5 英寸**（卡高 3.5 英寸） |
| **E-Z SEE** | 同上，主打大字 |

LoVision 的关键数字：**角标图标高 1.5" / 卡高 3.5" = 卡高的 43%**，
宽度 1 英寸 / 卡宽 2.5" = **卡宽的 40%**。

对比标准角标通常只占卡高 ~25%。⇒ **我们要的是 Jumbo Index 风格。**

> 这直接印证了本项目的定位：原版 `tractor.exe` 的牌面就是"标准角标 + 71px 卡宽"，
> 在 2K 屏上等价于「标准角标 + 远距离阅读」，必然看不清。
> 换成 Jumbo Index 是**行业已有的成熟解法**，不是我们拍脑袋。

### 2.3 换算到我们的尺寸

以「中」档 `--card-w = 150px` 为例（卡高 210px）：

| 元素 | 比例 | 实际尺寸 |
|---|---|---|
| 卡宽 × 卡高 | — | 150 × 210 |
| 角标点数高 | 卡高 × 0.20 | **42px** |
| 角标花色高 | 卡高 × 0.13 | 27px |
| 角标区宽 | 卡宽 × 0.30 | 45px |
| 内边距（白边） | 卡宽 × 0.06 | 9px |
| 中央 pip 直径 | 卡宽 × 0.22 | 33px |
| 圆角 | 卡宽 × 0.07 | 10.5px |

**关键校验**：手牌重叠 42% 时露出 `150 × 0.58 = 87px`，
角标区 45px 完全落在露出区内 ✓

## 3. 可借鉴的开源实现

### 3.1 CSS Playing Cards（`selfthinker`，CC BY-SA 3.0）★ 技术参考首选

纯 CSS/HTML 实现，2011 年，至今仍是最清晰的"用代码画牌"教程。

| 它的做法 | 我们的取舍 |
|---|---|
| `width: 3.3em; height: 4.6em`，只改 `font-size` 就能整体缩放 | ✅ 采纳思路，但我们用 `--card-w` 更直观 |
| 比例 3.3:4.6 = **1:1.394** | ✅ 与 poker size 一致，佐证 §2.1 |
| 角标 = 普通块级流 + 左对齐 | ✅ 采纳（比绝对定位简单） |
| **2~10 的 pip 用 `content` 里的 Unicode 字符 + `\A` 换行拼成文本矩阵** | ❌ 不采纳：依赖字体字形，缺字体会变豆腐块；改用 `<use>` 引用 path |
| J/Q/K 用**国际象棋字形**（♟ U+265F / ♛ U+265B / ♚ U+265A） | ⚠️ 备选：简洁但不够"扑克感" |
| `simpleCards` 选项 = 只画一个居中的大花色 | ✅ 采纳为「简化皮肤」 |
| `fourColours` 选项 = 四色牌 | ✅ **采纳**，见 §5 |
| `.hand` 重叠：`nth-child` 逐张 `left += 1.1em`（牌宽 3.3em 的 33%） | ⚠️ 它只放 13 张；我们 25 张需要更大重叠（~42%） |
| `.back` 用 `text-indent: -4000px` 把内容推出可视区 | ✅ 采纳这个技巧做牌背 |
| `rotateHand` 扇形旋转 | ❌ 不采纳：降低可读性，与目标冲突 |

### 3.2 Vectorized Playing Cards 2.0（Chris Aguilar，**LGPL 3.0**）

专业级矢量扑克牌，被大量开源项目使用（`Simple-Solitaire`、`cardsJS`、`deck-of-cards` 等）。

- 优点：J/Q/K 是完整的人物插画，专业水准；
- 缺点：LGPL 3.0（署名 + 提供许可证 + 允许修改）；单张 SVG 数百行，54 张体积大；
- 另一个问题：它是**标准角标**，不是 Jumbo Index —— 直接用等于没解决我们的问题。

### 3.3 svg-cards（David Bellot，LGPL 2.1）

更早期的一套，`CSS-Playing-Cards` 的 J/Q/K 图就取自这里。同样是标准角标。

### 3.4 结论

**借鉴设计思路，不引入现成牌组。** 理由见 §8。

## 4. Pip 布局坐标表

传统扑克牌的 2~10 有固定的点数排列。归一化到 `100 × 140` 的卡面坐标（左下原点在左上）：

| 点数 | 布局 | 坐标（x, y） |
|---|---|---|
| A | 单个大花色居中 | (50, 70)，尺寸 ×2.2 |
| 2 | 上下 | (50,32) (50,108)↓ |
| 3 | 上中下 | (50,32) (50,70) (50,108)↓ |
| 4 | 四角 | (32,32) (68,32) (32,108)↓ (68,108)↓ |
| 5 | 四角 + 中 | 4 的坐标 + (50,70) |
| 6 | 两列三行 | (32,32) (68,32) (32,70) (68,70) (32,108)↓ (68,108)↓ |
| 7 | 6 + 上中 | 6 的坐标 + (50,51) |
| 8 | 6 + 上中下中 | 6 的坐标 + (50,51) (50,89)↓ |
| 9 | 两列四行 + 中 | (32,28) (68,28) (32,55) (68,55) (32,85)↓ (68,85)↓ (32,112)↓ (68,112)↓ + (50,70) |
| 10 | 两列四行 + 两中 | 9 的八点 + (50,42) (50,98)↓ |
| J/Q/K | 中央人物或字母 + 花色 | 见 §4.1 |
| 小王/大王 | 「小王 / 大王」+ JOKER 字样 | 见 §4.2 |

↓ = 该位置的 pip 需要**旋转 180°**（传统做法，下半部分倒置）。

**pip 尺寸**：卡宽 × 0.22。以 150px 卡宽算，pip 直径 33px。

> 用 `<use href="#suit-heart" transform="translate(tx,ty) scale(s) rotate(180,cx,cy)"/>`
> 复用同一个 path，不用为每个位置写新 path。

### 4.1 J/Q/K 的三种方案

| 方案 | 说明 | 成本 | 建议 |
|---|---|---|---|
| **字母 + 大花色** | 中央画 `J`/`Q`/`K` 大字 + 花色 | 极低 | ✅ **v1 用这个** |
| 国际象棋字形 | ♟♛♚（CSS-Playing-Cards 的做法） | 极低 | 备选，风格偏"棋"不偏"牌" |
| 人物插画 | 引 Aguilar 牌组或自绘 | 高 | v2 可选皮肤 |

### 4.2 大小王

- 角标：`王` 字（或 `JOKER` 缩写 `JKR`）；
- 中央：竖排「小王 / 大王」+ 一枚星形或皇冠装饰；
- **颜色区分**：小王深灰、大王正红（这是通行做法，比纯文字更快辨认）。

## 5. 四色牌（可访问性选项）

两色牌的红/黑对红绿色盲不友好。四色牌是成熟替代：

| 花色 | 两色（默认） | 四色（可选） |
|---|---|---|
| ♠ 黑桃 | 近黑 `#2C2C2A` | 近黑 `#2C2C2A` |
| ♥ 红心 | 正红 `#A32D2D` | 正红 `#A32D2D` |
| ♣ 梅花 | 近黑 `#2C2C2A` | **深绿** `#27500A` |
| ♦ 方片 | 正红 `#A32D2D` | **深蓝** `#185FA5` |

通过 `:root[data-four-color='true']` 切换，零成本。

> 对本项目还有额外好处：主牌（trump）需要高亮，
> 四色牌 + 主牌金边，两者叠加时辨识度更高。

## 6. 其他素材的参考

### 6.1 桌面背景

**不要用位图。** 三层 CSS 就够：

```css
.table {
  background:
    radial-gradient(ellipse at 50% 45%, #1d5c47 0%, #123c2e 55%, #0a2419 100%);
  box-shadow: inset 0 0 200px rgba(0,0,0,.45);   /* 边缘压暗，聚焦中央 */
}
.table::after {                                   /* 绒布颗粒 */
  content: '';
  position: absolute; inset: 0;
  background-image: radial-gradient(rgba(255,255,255,.035) 1px, transparent 1px);
  background-size: 3px 3px;
  pointer-events: none;
}
```

- 径向渐变造"灯光聚焦"效果；
- `inset box-shadow` 压暗边缘；
- 3px 网格噪点模拟绒布颗粒（比真贴图省 300KB 且无限清晰）。

### 6.2 牌背（已实现，见 `design/card.js`）

**结论：用内联 SVG `<pattern>`，不用 CSS 渐变。**

理由：CSS 渐变的图案精度受像素密度影响，且很难做细线网格；SVG pattern 走 viewBox 单位，
随卡面等比缩放，线条始终清晰。

**三层结构**（缺一层就像壁纸，三层齐了才像印刷品）：

```svg
<rect class="paper"/>                                          <!-- ① 白卡体 -->
<rect x="3.5" y="3.5" w="93" h="133" fill="url(#bk-diamond)"/> <!-- ② 图案，白边 3.5% -->
<rect x="7" y="7" w="86" h="126" stroke-dasharray="1.6 2.4"/>  <!-- ③ 点线边框带 -->
<rect x="10.5" y="10.5" w="79" h="119"/>                       <!-- ④ 细实线 -->
<circle cx="50" cy="70" r="16"/> + 内环 + 菱形                   <!-- ⑤ 中心徽记 -->
```

**四个色款**（同一套边框，只换图案/底色）：

| 方案 | 图案 | 底色 | 特点 |
|---|---|---|---|
| 1 | 菱形网格（描边，非实心） | `#16325E` | 经典 Diamond Back |
| 2 | 点阵（12 单位重复） | `#12294F` | 极简 |
| 3 | 45° 细斜纹（9 单位） | `#1A3A6B` | 织物感 |
| 4 | 纯色 + 大徽记 | `#241D47` 深紫 | 现代扁平 |

**关键细节**：
- **白边 3.5%**（真扑克牌约 3~5%，之前用 5% 显得太宽）。
- **菱形要用描边不要实心** —— 实心菱形拼起来像棋盘格，描边才是菱形网。
- **中心徽记必须有深色底圆盘**（`#08152B` + 50% 透明外圈），否则图案会穿透，视觉上"脏"。
- 徽记是**花色无关**的菱形，不画具体花色 —— 牌背不能泄露信息。

**不要用**：纯 CSS `repeating-linear-gradient` 做牌背。做出来是"彩色噪点"，
在 130px 以上就能看出不是印刷品（第一版就是这个问题）。

### 6.3 图标

全部用 **SVG path**，不用字体图标、不用 emoji：

| 图标 | 说明 |
|---|---|
| ♠♥♣♦ | 4 条 path，手写一次 |
| 庄家标记 | 简单的印章/皇冠 path |
| 主牌标记 | 小盾牌或王冠 |
| 计分 | 数字 + 「分」字，不用图标 |

> **不用 emoji 的原因**：跨平台字形差异大（Windows 的 ♠ 和 macOS 的 ♠ 大小不同），
> 而且部分环境渲染成彩色 emoji，与牌面风格冲突。

### 6.4 字体

| 用途 | 建议 |
|---|---|
| 点数（`2`~`10`、`A/J/Q/K`） | 几何无衬线、字重 500~600。优先 `system-ui`，回退 `Helvetica Neue, Arial` |
| 数字要**等宽**吗 | 需要。`10` 占两位，等宽可避免角标宽度跳动 |
| 中文（「主」「庄」「分」） | `system-ui` 即可，不打包字体 |
| 是否打包字体 | **不打包**。打包一个中文字体动辄 3~10MB，与 NFR-09（首屏 < 300KB）冲突 |

## 7. 反模式（不要做）

| 反模式 | 为什么不行 |
|---|---|
| 用字体字形画花色（`&spades;`） | 缺字体变豆腐块；不同系统字形差异大；无法单独调色/描边 |
| 用 emoji 画花色 | 可能被渲染成彩色 emoji，风格崩坏 |
| 用位图做牌面 | 就是原版的问题（见 §2.2） |
| pip 用绝对坐标逐张手写 54 份 | 不可维护。用「数据 + 模板 + `<use>`」 |
| 手牌扇形旋转（`rotateHand`） | 斜着的字更难读，与"看清"目标直接冲突 |
| 卡面加渐变/阴影/高光 | 2K 屏上会显脏；扁平更清晰 |
| 牌背用高分辨率位图 | 体积大、缩放糊；用 CSS 渐变或 SVG pattern |

## 8. 为什么自绘，不用现成 LGPL 牌组

| 维度 | 自绘 | 用 Aguilar 牌组（LGPL 3.0） |
|---|---|---|
| 角标规格 | **可做 Jumbo Index** | 标准角标，**不解决我们的核心问题** |
| 主牌高亮 | 加个 class | 要改 SVG 源码，等于 fork 54 个文件 |
| 四色牌 | 改 CSS 变量 | 要重新着色 54 个 SVG |
| 体积 | 54 张 < 20 KB | 数百行/张，总体积大 |
| 许可 | 无约束 | LGPL 3.0：署名 + 附许可证 + 允许修改 |
| 风格统一 | 完全可控 | 人物插画风，与极简牌桌可能不搭 |

**决定性理由**：现成牌组都是**标准角标**。而我们的核心需求恰恰是
「角标要大到 2K 屏上一眼可辨」——这是 Jumbo Index 的领域，市面上没有现成的
LGPL Jumbo Index 矢量牌组。

⇒ 自绘。但**J/Q/K 的人物插画**可以在 v2 作为可选皮肤引入（届时再评估 LGPL 合规成本）。
