## 2. 先更正一个我自己的错误结论

三司会审的「知彼」写的是「smallnest 全仓无任何 AI 决策函数」。**这是错的。**

我当时只扫了 `Tractor.net/*.cs` 的关键词（`Award/Decide/电脑/robot`），**漏了子目录**。实际：

| 文件 | 大小 | 作用 |
|---|---|---|
| `Tractor.net/Algorithms/ShouldSendedCardsAlgorithm.cs` | 26 KB | **首出算法** |
| `Tractor.net/Algorithms/MustSendCardsAlgorithm.cs` | 111 KB | **跟牌算法** |
| `Tractor.net/Algorithms/Algorithm.cs` | 36 KB | 调度（可按座位委派给插件） |
| `Tractor.net/Algorithms/TractorRules.cs` | 45 KB | 规则判定 |

合计约 **170 KB 的机器人实现**，README 里那句「机器人罗伯特，它可代替您自动出牌」是真的。

更关键的是它有**外部算法插件接口**（`TractorPlugins/IUserAlgorithm.cs`）：

```csharp
ArrayList ShouldSendCards(int who, int suit, int rank, int master,
                          string[] sendCards, string myCards);      // 首出
ArrayList MustSendCards(int who, int suit, int rank, int master, int whoIsFirst,
                        string[] sendCards, ArrayList[] currentSendCards, string myCards); // 跟牌
```

- `sendCards[i]` = 各家本轮已出的牌；`myCards` = 我的手牌；牌用**整数 id**、逗号分隔
- `Dialogs/SelectUserAlgorithm.cs` 支持**按座位**选算法（4 个槽位）
- `release/Tractor.exe` + `Kuaff.Tractor.Plugins.dll` **是预编译好的**（.NET 4.6.1 WinForms）

⇒ **我们和"独立实现"之间只差一个适配层。**

## 3. 三条可落地路线

### 路线 A（推荐·真外部锚）· 把我们的 AI 做成 smallnest 的插件

```
Tractor.exe ──调用──> OurAiPlugin.dll ──stdin/stdout(JSON)──> Node 桥 ──> choosePlay()
     ↑                        │
     └── 规则由它判 ───────────┘   ← 这就是"外部"：判定权不在我们手里
```

**为什么这条最值钱**：规则由**它的引擎**判、对手是**它的机器人**。
我们不是"自己跟自己比"，而是"在别人的场地、按别人的规则、跟别人的选手打"。

要解决的三个问题：

| 问题 | 具体做法 | 风险 |
|---|---|---|
| **牌 id 映射** | 它的 id 用 `ConstValue`/`CurrentPoker` 编码；先跑一遍 `AlgorithmSample/SampleUserAlgorithm.cs`（官方样例，就是"出第一张"）把 id ↔ 牌值表打印出来 | 中（编码可能是 1 基、含花色位） |
| **信息不完整** | 插件只给「我的手牌 + 各家已出的牌」，**没有别家手牌** ⇒ 只能走 `belief`（peek off）路径 | 低（刚好能测"公平模式"的真实强度） |
| **状态重建** | 由 `sendCards[]` / `currentSendCards` / `whoIsFirst` 拼出 `trick.plays` 与 `remainingSeats`，再构造 `GameState` 的最小骨架 | 中（要保证与我们的规则口径一致：主牌/级牌/庄家） |

**成本**：C# 适配 ~150 行 + Node 桥 ~150 行 + WinForms 自动化（`pywinauto`）~100 行。
**障碍**：编译插件需要执行一次 .NET 编译器；**当前沙箱会拦截编译类命令**，需你本机执行或用授权放行（一条命令）。
**产出**：vs 它的机器人的**胜率 + 每墩得分差**（可直接填进 `docs/39` 的强度表）。

---

### 路线 B（零编译·人肉锚）· 你当"出牌执行器"

我做一个小工具：给它一个局面（我的手牌 + 已出的牌），它输出建议；
你在 smallnest 里照着打，记录比分。

- 成本：半天（工具）+ 你打 20 局
- 缺点：样本量靠人力，且你执行时会有偏差
- 优点：**完全不需要编译、不需要自动化**，还能顺带验证"我们的建议是不是真的好"

---

### 路线 C（立刻可做·人类锚）· 战绩面板 + 标注题库

- **战绩面板**：每局结束累计「你的队 vs AI」的胜/负/平、平均闲家得分、最近 20 局走势（`localStorage`）
- **标注题库**：把你这三轮的反馈固化成 `tests/ai/cases/*.json`（局面 + 你认为的最佳出法），
  脚本按命中率打分 —— 以后改权重先看这个分数掉不掉

成本：半天。**它测的是"AI 是否像人"，不是"AI 是否强"** —— 但对你来说更直观。

---

### 不推荐：公共平台锚

升级/拖拉机没有像天凤那样的公开天梯（对局平台都是客户端，无开放 API 与真人池），
Botzone 也没有这个游戏。**这条路目前走不通，别投入。**

## 4. 判定标准（先定，免得跑完不知道算不算好）

| 对照 | 口径 | 「强」的门槛 |
|---|---|---|
| vs smallnest 机器人 | 同一批牌局，座位互换配对 | **胜率 ≥ 55%**、净得分差 > 0 |
| vs 你自己 | 你 1 人 + 3 个机器人 对 我们 4 个 AI（或你打 30 局） | **胜率 ≥ 40%** 就算"接近老手" |
| 标注题库 | 命中率 | 现有 3 题必须 100%，新题 ≥ 80% |

> 注意：路线 A 是**公平信息**（插件看不到别家手牌），而路线 C 的对手默认能看你的手牌（`AI 读牌` 开）。
> 两组数字不能混着比，报告里必须写清口径。

---

## 5. 建议顺序

1. **本周**：路线 C（半天）——立刻有"人类锚"，且能沉淀你的 expert 判断
2. **下一步**：路线 A 的第 1 步（**只验证桥能跑通**：单局、手动选算法、我们的插件出第一张牌不出错）
3. **再下一步**：路线 A 自动化跑 100 局配对，把胜率写进 `docs/39`

一句话：**真正的锚不是"更强的对手"，而是"判定权不在你手里的比赛"。**
smallnest 恰好提供了这样一个场地 —— 我们只需要写个插头插进去。
