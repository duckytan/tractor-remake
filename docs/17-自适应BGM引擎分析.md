## 1. 它是什么

一个**自适应背景音乐引擎 + 编辑器**，不是播放器：没有任何 mp3/ogg，**每个音符都是运行时用 Web Audio API 算出来的**。

- 单 HTML、`<script>` 是一个 IIFE、**零外部依赖**、零音频素材
- 链路：`素材（旋律/和弦/音型）` → `编排（每小节生成音符事件）` → `合成（25 种音色）` → `混音（总线 + 卷积混响 + 压缩）`
- 交互：实时改谱（钢琴卷帘 / 文本谱）、换场景、MIDI 导入导出、localStorage 存档

> 实测：无头 Chromium 打开 → 点「启动」→ 正常起播、零 console error。

## 3. 实现要点

### 3.1 信号链（`initAudio` 529-576）

```
各音色 ─► 总线(gain+pan) ─┬─► dryBus ─┐
   acc/lead/pad/fx/        │           ├─► master(0.8) ─► tone(LP 8500Hz, Q0.5)
   gtr/pno/flute           └─► wetBus ─► convolver(2.0s IR) ─► wetGain ─┘
                                                                      ─► 压缩器 ─► 输出
                                          (thr -20, knee 22, ratio 2.6, atk 12ms, rel 280ms)
```

- 混响 IR 是**合成**的：指数衰减噪声 + 一阶低通，逐采样递推（避免 24 万次 `Math.pow`）
- 总线 pan：gtr -0.28 / pno +0.22 / acc -0.12 / lead +0.06 / flute +0.06
- **注意**：实际编排只用到 `accBus`（伴奏）、`leadBus`（旋律）、`padBus`（和声床）、`fxBus`（沙锤/雨）；`gtrBus`/`pnoBus`/`fluteBus` 是历史残留

### 3.2 合成技术分四类

| 技术 | 用在哪 | 关键手法 |
|---|---|---|
| **物理建模** | 钢弦吉他（580-648） | Karplus-Strong：噪声激励 → 延迟线 + 低通反馈（R=0.9965）；**按音高缓存缓冲区**（首次 ~57ms，之后复用，`pluckCache` 上限 240）；琴体两个 peaking（128Hz +4.5dB、420Hz +2.6dB） |
| **加法合成** | 钢琴(651-690，7 个分音)、钢片琴、马林巴、八音盒、钟琴、颤音琴、竖琴、尼龙、羽管键琴、管风琴 | 每分音独立包络 + **轻微非谐性**（`f*h*(1+0.0004h²)`）；钢琴另有击槌噪声（bandpass 2400，9ms） |
| **FM / 减法** | 电钢（载波 + 2×调制器 + 7.02×音叉）、合成主音、弦乐族、管乐族 | 锯齿/方波失谐叠层（±0.6%）→ 低通 → 共振峰 peaking（小提琴 1150Hz、大提琴 300Hz） |
| **噪声整形** | 沙锤、长笛气声、雨声、钢琴击槌 | 噪声 → 高通/带通串联 + 极短包络 |

### 3.3 调度器（1562-1600）—— 最值得抄的部分

```js
setInterval(scheduler, 40)           // 40ms 轮询
while (nextBarTime < now + 0.45)     // 0.45s 前瞻，按「小节」排
    scheduleBar(barIndex, nextBarTime)
```

**卡顿保护**：若 `nextBarTime < now`（主线程被卡过：冷启动 JIT、首次渲染拨弦缓冲、切场景），
直接 `skip` 到未来整小节，**绝不补播欠下的小节**。
注释写明：否则会「十几秒的曲子 2 秒播完」，且越补越落后会锁死主线程。

### 3.4 每小节的编排（`scheduleBar` 1476-1560，四层叠加）

1. **分解和弦**（`scene.gtr` 层）：读 8 个八分位置 → 位掩码 → 每列可多音（柱式）；
   偶数位力度 0.95、奇数位 0.72；同列 n 个音时每个 ×`1/√n`（等功率，避免柱式比单音吵）
2. **左手和弦**（`scene.pno` 层）：根音 + 五音长音（1.6 拍）；`dens>0.7` 且奇数小节再加三音
3. **和声床**（`scene.pad` 层）：低音 + 三音铺满 4 拍
4. **主旋律**：按 4 小节窗口过滤音符 → 力度 `= (0.93+r*0.07) * scene.mel * phraseAccent(...)`；
   再按变奏开关叠八度 / 对位 / 倚音

### 3.5 人性化（`phraseAccent` 400-409，不靠随机的"乐感"）

```
强拍 1.00 / 次强 0.94 / 弱拍 0.88
反拍（半拍位）×0.95
每句第 2、8 小节 ×0.93（收句）
越高越亮：× (0.90 + 0.10 * clamp((midi-60)/21))
```
外加时间抖动 ±12ms（伴奏）/ ±14ms（旋律）、力度抖动 0.85~1.10。

### 3.6 生命周期

- **停止 = 关掉整个 AudioContext**（`stop()` 只停调度，已排出去的音符会自己播完 ——
  注释实测**余音 4.9 秒**，期间再启动会新旧叠音）。下次启动重建（音频图 7.2ms + 拨弦缓冲 57ms）
- 拨弦缓冲按音高缓存；IR/噪声缓冲只建一次

## 4. 音乐微调能力：参数全表（**本节是核心参考**）

### A. 场景级 —— 11 个参数（`SCENES` 482-491，一行一个场景）

| 参数 | 实际作用（逐个核对过真实用法） | 现有范围 |
|---|---|---|
| `bpm` | 每小节 4 拍的速度 | 62~126 |
| `tp` | 移调半音数，旋律/伴奏/和弦**一起**移 | -3~0 |
| `gtr` | **分解和弦层力度倍率**（`min(1.4,max(0,x))`） | 0.30~1.05 |
| `pno` | **左手和弦层力度倍率**；同时是尾句加花与事件跑动的开关（`>0.02`） | 0.55~1.20 |
| `mel` | **主旋律力度倍率** | 0.85~1.20 |
| `dens` | **密度**：加花概率 `(dens-0.75)*0.34`；`>0.7` 时奇数小节加三音（MIDI 导出同步） | 0.6~1.25 |
| `verb` | 混响湿量（切场景自动写进滑条，用户可再覆盖，`applySceneVerb` 2702） | 0.28~0.52 |
| `bright` | **亮度**：**10 处**音色的低通截止（吉他 `1800+4200×b`、小提琴 `2400+2200×b`…） | 0.42~0.84 |
| `shaker` | 沙锤量（每小节反拍 4 下） | 0~0.30 |
| `rain` | 雨声床量（合成噪声 + 低通/高通，静态） | 0~0.30 |
| `pad` | 和声床量（两层，×0.10 / ×0.07） | 0.12~0.34 |
| `inst` | 该场景默认主旋律音色（可选；切场景会覆盖用户选择） | flute / piano 等 |

## 5. 局限（接入前必须知道）

1. **只有 4/4**，和弦进行写死 C–F–Am–G，无转调/离调
2. **旋律单声部**（只做八度/三度叠加），无真正复调
3. **无 swing/shuffle**，无渐强渐弱曲线（只有逐音力度）
4. **切场景不是交叉淡入**：音色/旋律立即换，速度/混响在下一小节生效
5. 雨声是静态噪声床，不随强度变化
6. MIDI 导入是「多轨合并成一条旋律」，丢掉时值细节与力度曲线

## 6. 接到拖拉机上的建议（尚未实施）

### 6.1 场景 ↔ 对局状态映射（草案）

| 对局状态 | 建议场景（复用现成 8 个之一） | 理由 |
|---|---|---|
| 定主 / 埋底 | 咖啡小憩（66 BPM，gtr 0.55） | 慢、疏、给思考留空间 |
| 正常出牌 | 午后阳光（72 BPM，基准） | 中性，不抢注意力 |
| 对手接近 80 分 / 关键墩 | 心事暗涌（76 BPM，dens 1.25，tp -1） | 同素材下"加密 + 降调"制造紧张 |
| 本局结算 | 素面时节（126 BPM，明亮） | 明快收束 |
| 终局（胜 / 负） | 素面时节 / 回忆闪回（62 BPM，降 2 度） | 胜负两版 |

### 6.2 接入时的硬约束

1. **零依赖**：Web Audio 是浏览器 API，不违反项目「运行时零依赖」铁律 ✓
2. **分层**：落 `src/audio/`（表现层），不得反向依赖 `core` 的规则概念
3. **测试/CI**：必须懒初始化 + 无 `AudioContext` 时静默 no-op，否则 node 环境单测会挂
4. **自动播放策略**：iOS/Chrome 都要用户手势后才能起播 —— 用第一次点牌/点「开始」触发
5. **移动端 CPU/耗电**：同时发声节点数要克制（参考实现单小节最多约 12~16 个节点）
6. **停止语义**：照抄「停止 = close AudioContext」，否则余音会叠
7. **PWA 离线**：合成不依赖网络，天然可离线 ✓
8. **与动画速度档位解耦**：BGM 速度属于音乐参数，不跟 `animSpeed` 走

### 6.3 提取量估计

去掉编辑器 / MIDI / UI 后，引擎核心约 **800~1000 行**：
`initAudio` + 音色表（25 个函数）+ `scheduleBar` + `scheduler` + `SCENES` + `CHORDS` + 音型网格。
