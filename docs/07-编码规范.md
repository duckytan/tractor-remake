# 07 · 编码规范

> 状态：`已定稿` ｜ 版本：v1.0 ｜ 日期：2026-10-22
> 目标：让代码在半年后自己还能看懂，且规则改动时只改一处。

## 1. 总则

1. **可读性 > 简洁性 > 性能。** 108 张牌的规模，性能从来不是瓶颈。
2. **规则只实现一次。** 同一规则出现在两处就是 bug 温床。
3. **类型即文档。** 能用类型表达的约束，不写在注释里。
4. **不引入不必要的依赖。** 运行时依赖目标为 0。

---

## 2. 目录与文件

| 规则 | 说明 |
|---|---|
| 一个文件一个主题 | `cards.ts` 只放牌相关的；不要 `utils.ts` 这种垃圾桶 |
| 文件名 kebab-case | `power-table.ts`，不用 `powerTable.ts` |
| 模块入口统一 `index.ts` | 外部只能从 `index.ts` 导入，不深挖内部文件 |
| 测试文件与被测文件同名 | `cards.test.ts` 测 `cards.ts` |

```ts
// ✅ 外部使用
import { buildPowerTable, analyze } from '@core'

// ❌ 禁止深挖
import { buildPowerTable } from '@core/cards'
```

> 深挖会让重构变难。**例外**：`tests/` 下可以深挖，便于针对性测试。

## 3. 命名

| 类别 | 规则 | 示例 |
|---|---|---|
| 类型 / 接口 | PascalCase | `GameState` `PlayAnalysis` |
| 函数 / 变量 | camelCase | `checkPlay` `defenderScore` |
| 常量 | SCREAMING_SNAKE | `CARD_SCORE` `STATE_VERSION` |
| 布尔 | `is` / `has` / `can` / `should` 前缀 | `isMultiGroup` `hasNaturalTractor` `canCounterTrump` |
| 工厂函数 | `create*` / `make*` | `createPolicy` `makeDeck` |
| 判定函数 | 动词开头，返回 bool | `checkPlay` 返回 Result，`isValid` 返回 bool |
| 事件 / 意图 | 动词短语 | `DECLARE_TRUMP` `PLAY` `BURY` |

**避免的命名**：

| 不要 | 因为 |
|---|---|
| `data` `info` `obj` `temp` | 无信息量 |
| `handleClick` `doSomething` | 描述手段而非目的 |
| `nGroup` `pGroup` `typeCode` 原样照搬 | 这是原版的反编译名，本项目用语义名（`pairCount` / `groups` / `suitSlot`） |
| `mustPlay` | 有歧义，用 `LevelSkipGuard` / `guardLevels` |

## 4. TypeScript 使用

### 4.1 配置

```json
{
  "compilerOptions": {
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "noImplicitOverride": true,
    "exactOptionalPropertyTypes": true,
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "verbatimModuleSyntax": true
  }
}
```

`noUncheckedIndexedAccess` 会让 `arr[i]` 返回 `T | undefined`。
牌类代码里数组访问很多，这会带来一些摩擦，但能挡住越界 bug，**值得**。

### 4.2 类型使用原则

| 原则 | 做法 |
|---|---|
| 值域有限就用联合类型 | `type Suit = 0\|1\|2\|3`，不要 `number` |
| 不要 `any` | 万不得已用 `unknown` + 类型守卫 |
| 不要类型断言 `as` | 除非在边界处（如 JSON 解析）并写注释 |
| 不要 `enum` | 用 `as const` 对象或联合类型（`enum` 有运行时开销且行为怪异） |
| 只读优先 | 函数参数用 `readonly T[]`，返回用 `readonly` |
| 不要 `namespace` | 用 ES 模块 |

```ts
// ✅
export const SUITS = [0, 1, 2, 3] as const
export type Suit = typeof SUITS[number]

// ❌
export enum Suit { Spade, Heart, Club, Diamond }
```

### 4.3 不可变性

`core` 的所有函数**不得修改入参**。

```ts
// ✅
function addPlay(state: GameState, play: Play): GameState {
  return { ...state, trick: { ...state.trick, plays: [...state.trick.plays, play] } }
}

// ❌
function addPlay(state: GameState, play: Play) {
  state.trick.plays.push(play)   // 修改了入参
}
```

测试里用 `Object.freeze` 深冻结入参，一旦被改立刻抛错（I-8）。

## 5. 函数设计

| 规则 | 说明 |
|---|---|
| 单一职责 | 一个函数只做一件事；超过 40 行考虑拆分 |
| 参数不超过 4 个 | 超过就收成一个对象 |
| 显式依赖 | 需要随机数就传 `rng`，不读全局 |
| 纯函数优先 | `core` 里不允许副作用 |
| 早返回 | 用 `if (!x) return ...` 而不是嵌套 `if` |

```ts
// ✅ 早返回，扁平
function checkFollow(...): PlayResult {
  if (cards.length !== leadCards.length) return { ok: false, reason: 'count-mismatch' }
  if (sameSuit !== expected) return { ok: false, reason: 'must-follow-suit' }
  if (sameSuit < leadCards.length) return { ok: true, cards }
  if (pairs !== expectedPairs) return { ok: false, reason: 'must-follow-pairs' }
  return { ok: true, cards }
}
```

## 6. 错误处理

见 `04` §11。落地规则：

| 场景 | 写法 |
|---|---|
| 用户操作不合法 | 返回 `PlayResult` 的 `ok: false` 分支 |
| 存档损坏 | 返回 `null`，调用方降级 |
| 参数越界（编程错误） | `throw new Error('seat out of range: ' + seat)` |
| 不变量破坏 | `throw new Error(...)` + `console.error(state)` |

**禁止**：

- ❌ 空 `catch {}`
- ❌ `catch (e) { console.log(e) }` 后继续执行（等于吞掉错误）
- ❌ 用异常做流程控制（比如用 `throw` 表示「这手牌不合法」）

## 7. 注释

**注释解释「为什么」，不解释「是什么」。**

```ts
// ❌ 废话注释
// 遍历所有牌
for (const card of cards) { ... }

// ✅ 解释非显然的决策
// 原版在这里先排序再去重：排序保证 keyCard 是最大牌，
// 去重把"两张同值"折叠成多重度，避免后续判断对子时重复计数。
sortAndDedup(cards)
```

必须写注释的地方：

| 位置 | 内容 |
|---|---|
| 规则实现处 | 引用规则书章节，如 `// 规则书 §6.3：结构只查对子数` |
| 与原版不同处 | 引用 ADR，如 `// ADR-008：甩牌失败只出最小一张（原版保留全部对子）` |
| 魔数 | 说明来源，如 `const BOTTOM_COUNT = 8 // 规则书 §2.1` |
| 反直觉的实现 | 说明为什么不按直觉写 |

不写注释的地方：显而易见的赋值、getter、类型定义。

## 8. 测试规范

| 规则 | 说明 |
|---|---|
| 测试名说人话 | `it('有对子时必须跟够对子', ...)` 而非 `it('test1', ...)` |
| 一个用例一个断言主题 | 不要在一个 `it` 里测 5 件事 |
| 用 fixture 不用魔法数字 | 牌局数据放 `tests/fixtures/`，命名说明用途 |
| 测行为不测实现 | 断言返回值，不断言内部调用次数 |
| 边界必测 | 空数组、单元素、最大张数 |

```ts
// ✅
describe('checkFollow', () => {
  it('有对子时必须跟够对子', () => {
    const state = loadFixture('follow-pairs')
    const result = checkPlay(state, 1, [c(26), c(27)])
    expect(result).toEqual({ ok: false, reason: 'must-follow-pairs' })
  })
})
```

## 9. CSS 规范

| 规则 | 说明 |
|---|---|
| 尺寸全走自定义属性 | 禁止硬编码 `width: 88px`，用 `var(--card-w)` |
| BEM 风格类名 | `.hand__card--selected` |
| 不写行内样式 | 除了动态计算的位置 |
| 颜色走变量 | `var(--color-trump)`，方便换主题 |
| 不用 `!important` | 用了说明选择器设计有问题 |
| 动画统一时长变量 | `var(--dur-fast)` / `var(--dur-normal)` |

```css
:root {
  --card-w: clamp(44px, 5.2vw, 88px);
  --dur-fast: 120ms;
  --dur-normal: 260ms;
}

@media (prefers-reduced-motion: reduce) {
  :root { --dur-fast: 0ms; --dur-normal: 0ms; }
}
```

## 10. Git 提交规范

采用 Conventional Commits：

```
<type>(<scope>): <subject>

<body 可选>
```

| type | 用途 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修 bug |
| `test` | 只改测试 |
| `docs` | 只改文档 |
| `refactor` | 重构，行为不变 |
| `perf` | 性能优化 |
| `chore` | 构建 / 依赖 / 杂务 |

`scope` 用模块名：`core/cards`、`ui/hand`、`app/store`、`ai`、`docs`。

```
feat(core/legality): 实现跟牌对子数校验
fix(core/settle): 修正必打截断判定对象应为新级牌
test(core/deal): 补 64 组合禁止连对用例
docs: 补充 ADR-008 甩牌失败处理
```

**粒度**：一次提交只做一件事。规则修正与 UI 调整不要混在一次提交里。

## 11. 禁止事项清单

开发时对照自查：

- [ ] ❌ `src/core/` 里出现 `window` / `document` / `localStorage` / `navigator`
- [ ] ❌ 代码里直接调 `Math.random()`（必须走注入的 `Rng`）
- [ ] ❌ `src/ui/` 里出现 `power` / `typeCode` / `pairCount` 等规则概念
- [ ] ❌ 修改函数入参
- [ ] ❌ 用 `any`
- [ ] ❌ 空 `catch`
- [ ] ❌ 硬编码尺寸 / 颜色
- [ ] ❌ 同一规则在两个文件里各写一遍
- [ ] ❌ 改了规则实现但没改测试
- [ ] ❌ 引入未在 `03-系统架构设计.md` 里列出的依赖

> 前三条是架构级红线，违反会破坏「规则引擎可独立测试」这个根基。
> 建议在 CI 里加 `grep` 检查自动拦截。
