# 28 · AI 总体规划（四档 + 全触点 + 提示）

> 汇总 docs/23~27 的结论，给出**一套可实施、可分档、覆盖全部 AI 触点**的规划。
> 核心原则：**一条管线，四档降级** —— 不是写四套代码，而是一套代码的四组开关与预算。

## 0. 设计原则

1. **一条管线**：候选生成 → 评估 → （可选）搜索 → 输出。
   四档只在「候选多不多 / 评估细不细 / 搜不搜」三处降级。
   理由：四套代码必然发散，改一处要改四遍，标定也无法横向比较。
2. **算力预算先行**：每档先定死时间上限，再决定能开哪些功能（§3 的表）。
3. **完美信息是资产，也是债**：因为能读到三家手牌，「搜索」不需要 MCTS，
   确定性枚举就够 —— 这让超强档的算力需求降一个数量级。
   但也要把读取收敛到一处，为将来改「推断手牌」留口子。
4. **可标定**：所有权重、阈值都是具名常量；改动必须跑座位互换配对测量。

## 1. 全触点盘点（12 处需要 AI）

原来只有「出牌」一处是真正的算法，其余都是拍脑袋的 if。

| # | 触点 | 现状 | 档次 |
|---|---|---|---|
| 1 | **抢庄 / 亮主** | 持级牌 + 该门 ≥3 张 + 100% 必抢 | 所有档共享 |
| 2 | **反主** | 新主花色 ≥5 张就反 | 所有档共享 |
| 3 | **加固** | 直接调规则判定 `canGuard` | 所有档共享 |
| 4 | **埋底（扣 8 张）** | 按牌力扣最弱 8 张 | 所有档共享 |
| 5 | **首出（含甩牌）** | 单张/对子/连对，**不甩牌** | 分档 |
| 6 | **跟牌** | 只有「最小」「最大」2 个候选 | 分档 |
| 7 | **毙牌判断** | 靠打分里的 `canIWin` 事后判断，候选里没有 | 分档 |
| 8 | **垫牌选择** | 从其他花色补最小的 | 分档 |
| 9 | **提示**（人类用） | **取第一个合法候选**（= 最小的牌），无评估 | 分档 |
| 10 | **AI 思考时长** | 固定 `aiSpeedMs`（0/300/800） | 全局 |
| 11 | **记牌器** | 纯展示，无推断 | 人类辅助 |
| 12 | **难度自适应** | 无 | 可选 |

> 9 是个被忽略的大问题：提示给的牌**不是最好的牌**，只是「最小的合法牌」。
> 玩家按提示出牌会一直吃亏 —— 这也是「AI 弱智」体感的一部分。

## 2. 分层架构

```
                    ┌──────────────────────────────────────┐
   输入              │ 局面快照（state + ctx + 三家手牌）      │
                    └───────────────┬──────────────────────┘
                                    ↓
   L1 候选生成   ┌───────────────────────────────────────────┐
   （意图驱动）   │ 抢分 / 保分 / 清门 / 逼牌 / 递牌 / 兑现     │
                 │ + 毙牌 / 甩牌 / 拆牌变体                    │
                 └───────────────┬───────────────────────────┘
                                 ↓
   L2 评估       ┌───────────────────────────────────────────┐
   （双层）       │ ΔHQ（剩余手牌质量） + TrickEV（墩期望）      │
                 │ + ControlShift + TeamValue                 │
                 └───────────────┬───────────────────────────┘
                                 ↓
   L3 搜索       ┌───────────────────────────────────────────┐
   （可选）       │ 关键决策点做 1~2 层确定性 rollout           │
                 └───────────────┬───────────────────────────┘
                                 ↓
   L4 输出       ┌───────────────────────────────────────────┐
                 │ 出牌 / 提示（带标签与理由）                 │
                 └───────────────────────────────────────────┘
```

**降级点**（四档的差异全在这三处）：

| 层 | 弱 | 中 | 强 | 超强 |
|---|---|---|---|---|
| L1 候选 | 随机 1 个合法 | 意图候选（6 种） | 同 + 毙牌/拆牌变体 | 同 + 甩牌组合 |
| L2 评估 | 无（纯随机） | 线性特征（现行 L1） | + ΔHQ | + 概率对手模型 + 阶段权重 |
| L3 搜索 | 无 | 无 | 无 | 关键点 1~2 层 rollout |

## 3. 四档配置矩阵（含算力预算）

| | **弱** | **中** | **强** | **超强** |
|---|---|---|---|---|
| **定位** | 新手陪练 | 普通玩家 | 熟手 | 高手/挑战 |
| **单次决策预算** | < 1ms | < 3ms | < 10ms | < 50ms |
| **候选数** | 1（随机合法） | 12~18 | 18~25 | 25~40 |
| **评估项** | 无 | 省牌/吃分/队友 | + ΔHQ + 前瞻 | + 概率模型 + 阶段 |
| **前瞻** | 无 | 无 | 硬判定（现 L2/L3） | 概率化 |
| **搜索** | 无 | 无 | 无 | 关键点 rollout |
| **埋底** | 按牌力扣最弱 8 张 | 扣绝一门 | 扣绝 + 保分 | + 末墩预判 |
| **亮主** | 见级牌必抢 | 张数门槛 | 质量评分 | 同 |
| **提示** | 最小合法牌 | 最优候选 | 同 | 同 + 理由 |

**为什么「弱」要保留现在的随机**：新手需要可预测的对手。
但**弱档也要合法**（不能出违规牌），这点不变。

## 4. 逐触点设计

### 4.1 抢庄 / 亮主（#1）

```
分数 = 该门张数 × 1.0
     + 该门绝对大牌数 × 2.0        // 全场没人能压的
     + 主牌张数 × 0.5
     + 手上分牌数 × 0.3            // 有分更想坐庄（底牌能藏分）
     − 该门最长连对缺口 × 0.5      // 结构越散越不想亮
门槛：≥ 5 分亮（弱档 ≥ 3 分，见级牌就抢）
```
反主：新主分数必须 **> 现主分数 + 3** 才反（避免无脑反）。
加固：分数 > 现主 + 5。

### 4.2 埋底（#4）

见 docs/27 §7 的伪代码。优先级：**制造缺门 > 保护分牌 > 保护结构 > 扣低牌力**，
硬约束是「底分最小」。超强档加「末墩牌型预判」（对手主牌多 ⇒ 少留分）。

### 4.3 首出（#5）

意图候选按 docs/27 §3 的顺序生成：**单张 → 对子 → 甩 → 连对**（先小结构后大结构）。
甩牌只在「该门有绝对大对」时生成，且必须逐组校验 `checkLead`。

### 4.4 跟牌 / 毙牌 / 垫牌（#6 #7 #8）

三种意图分开生成候选：

- **毙牌**：缺门时，用主牌毙（单张/对子/连对各一套）
- **跟牌**：同门跟，按结构从低到高给 3~4 个候选（不再是 2 个）
- **垫牌**：从其他门垫，分「垫分牌 / 垫非分牌 / 垫最低」三种

评估时用 `partnerLeading` 判断：**队友领先时垫分牌要加分**（docs/27 §4 F1）。

### 4.5 AI 思考时长（#10）

现在是固定档（0/300/800）。建议：
- 基础时长按档位（弱 300 / 中 500 / 强 700 / 超强 900）
- **局面越复杂越长**：墩内分 ≥ 10 或收官阶段，加 200~400ms
- 上限保护：不能让玩家等超过 1.2 秒

这样「AI 在想事情」的体感更真实，也能掩盖超强档的 50ms 计算。

### 4.6 难度自适应（#12，可选）

根据玩家最近 N 局的净胜分，微调 AI 的「保守度」（不是换档，而是调权重 ±10%）。
**风险**：容易做成「作弊感」。建议只做「降低」不做「提高」——
玩家一直输就悄悄放水，一直赢就恢复正常。

## 5. 提示功能专章

### 5.1 现状问题

`hint()` 取 `enumeratePlays` 的**第一个合法候选**。而候选是按「从小到大」排的，
所以提示永远是「最小的那张牌」。**它没有评估，只是在找一个能出的牌。**

### 5.2 提示和 AI 出牌的区别

| | AI 出牌 | 提示 |
|---|---|---|
| 目标 | 赢 | **让玩家理解并自己决定** |
| 输出 | 1 个选择 | 1~3 个选项 + 标签 + 理由 |
| 要求 | 越强越好 | 可解释、不越俎代庖 |

### 5.3 设计

```
提示 = 用「强档」的候选生成 + 评估，但输出前 3 个而不是第 1 个
     每个附一个标签和一句话理由
```

| 标签 | 触发条件 | 理由文案 |
|---|---|---|
| **最稳** | 评估分最高 | 「能赢下这墩，且不吃亏」 |
| **抢分** | 墩内分 ≥ 10 且能赢 | 「这墩有 15 分，压过去能拿到」 |
| **省牌** | 评估次优但牌力消耗低 | 「用最小的牌，留着大牌后面用」 |
| **让队友** | 队友已领先 | 「队友已经赢了，垫分牌就行」 |

交互：
- 按 `h` / 点「提示」→ 高亮第 1 个（最稳），并在操作条显示标签
- 再按一次 → 循环到第 2 个
- 「提示即选中」开关打开时，直接选中当前提示的牌

**为什么这样比现在好**：现在提示给「最小的牌」，玩家照着出会输；
新提示给「最稳的一手」并说明理由，玩家能学到东西，也不会觉得 AI 在糊弄。

### 5.4 算力

提示是**人类主动触发**的，不在 AI 出牌循环里，可以给 20~50ms 预算
（比超强档还宽松），因为它不阻塞任何动画。

## 6. 算力与性能要求

| 环节 | 要求 | 测量方式 |
|---|---|---|
| 单次出牌决策（超强） | < 50ms | 单测里跑 1000 次取 P95 |
| 单次出牌决策（强） | < 10ms | 同上 |
| `HQ` 单次计算 | < 2ms（含缓存命中） | 单测 |
| 提示 | < 50ms | 手动触发，不阻塞 |
| 一局总耗时 | 不因 AI 变慢 | e2e 里对比改前改后 |

**关键优化**（抄 DouDiZhu 的经验，见 docs/25 §2）：
- `HQ` 用哈希缓存（key = 手牌签名）
- 拆牌时固定提取顺序（先提最大面值），把 `P(N,M)` 降到 `O(N+M)`
- 候选评估里 `ΔHQ` 只算「去掉这手」后的 HQ，不重算整手

## 7. 验收标准

每一步都要过这三关：

1. **合法性**：四档在完整对局中零非法出牌（现有 e2e 已覆盖）
2. **单调性**：`L(n+1) vs L(n)` 净胜率 > 阈值（座位互换配对，600 次）
   - 现有基线：L1>L0 55%、L2>L1 50%（实测 59.2%）、L3>L2 52%（实测 57.7%）
   - 新目标：L2>L1 **> 62%**、L3>L2 **> 60%**
3. **自检**：同档对同档净胜率必须**恰好 0%**（测量正确性的保证）

**不允许为了让测试变绿而调低阈值** —— 跑不出来就如实报数值（沿用现有约定）。

## 8. 实施路线（6 批，每批独立可验证）

| 批 | 内容 | 验收 |
|---|---|---|
| **1** | 队友领先垫分牌加分（一行） | 标定 L2 vs L1 变化 |
| **2** | 意图驱动的候选生成（首出 + 跟牌 + 毙牌 + 垫牌） | 候选数 2→15+；标定 |
| **3** | `HQ` 手牌质量 + 哈希缓存 | 单测 + 性能 < 2ms |
| **4** | 接入 `ΔHQ`、概率化对手模型 | 标定 L3 vs L2 |
| **5** | 埋底新算法 + 亮主/反主评分 | 单测（底分下降）+ 标定 |
| **6** | 提示功能改造 + AI 思考时长 | 手动验证 + e2e |

**第 1 批最小、第 2 批收益最大**。第 5 批（埋底）独立于出牌，可以并行做。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 四档共用一套代码，改一处影响四档 | 每档的能力开关集中在一个 `AI_PROFILE` 表里，改动只看这张表 |
| 候选变多后权重难调 | 分批实施，每批只加一个变量，跑标定再进下一批 |
| 概率模型引入新偏差 | 保留硬判定作为对照组，标定里直接比 |
| 超强档 50ms 影响手感 | 用「思考时长」掩盖；实测 P95 超标就砍搜索 |
| 完美信息迟早要改 | `opponents` 读取收敛到 `readOpponents()` 一处 |
| 提示给错建议比不提示更糟 | 提示必须走「强档」评估；给不出的情况宁可只给「最小合法牌」并标注「保底」 |

## 10. 一句话总结

**一套管线（候选 → 评估 → 可选搜索）+ 一张四档配置表 + 12 个触点全覆盖。**
其中真正的新东西是三样：**意图驱动的候选**、**手牌质量 + 墩期望的双层评估**、
**概率化的对手模型**；提示则是把这套评估「降级成人能看懂的 3 个选项」。
