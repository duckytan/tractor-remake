# 声音系统设计方案（提案 · 待拍板）

> 版本：提案 v1 · 2026-10-24
> 前置：`docs/17-自适应BGM引擎分析.md`（外部参考实现的能力与参数全表）
> 状态：**未实施**。§8 有 5 个需要拍板的决策。

---

## 0. 一句话

自研、零素材、纯合成的声音层：**一条核心动机 + 场景参数化改编 + 与音乐同调的电子音效**，全部由对局状态驱动。

---

## 1. 目标与边界

**要做的**

- BGM：一条能听 10 分钟不烦的核心动机，随对局状态**连续变形**（不是切歌）
- 音效：即时反馈、**与当前调性同调**、连续触发也不重复
- 全部零素材（Web Audio 实时合成）、可离线、可静音

**不做的**

- 不引真实录音采样、不做语音播报、不做多语言
- 不引第三方音频库（保持运行时零依赖）
- 不做联机/多人音效同步

**铁律**

1. `core` 保持纯函数 —— 音频只在 `main.ts` 接线
2. 模块导入无副作用；**无 `AudioContext` 时全部静默 no-op**（否则 node 单测挂）
3. 必须用户手势后才能起播（iOS/Chrome 策略）
4. 停止 = `ctx.close()`（照抄参考实现的教训：`stop()` 只停调度，余音会叠）

## 2. 对局场景分析

### 2.1 对局的实际结构（已从代码核准）

| 阶段 | 时长/节奏 | 玩家在做什么 | 情绪 |
|---|---|---|---|
| `contract` 发牌 | 33 tick × **55ms**（约 1.8s），含抢主/亮主/反主/加固 | 看牌、抢着亮主 | 期待、悬念（抢主是戏剧点） |
| `bury` 埋底 | 庄家选 8 张，无时限 | 思考 | 安静、专注 |
| `play` 出牌 | **25 墩**，AI 每手 **420ms**，出牌飞行 280ms、收墩 340ms | 判断跟牌/甩牌 | 中性为主，局部紧张 |
| `settle` 结算 | 面板停留至点击 | 看结果 | 收束 |
| `over` 终局 | — | 看胜负 | 释放 |
| `replay` 回放 | 手动翻墩 | 复盘 | 怀旧、安静 |

**决定"紧张"的真实阈值**（`core/settle.ts`）：

- 闲家得分 **0** → 庄家升 3 级；**1–39** → 升 2；**40–79** → 升 1
- **≥80** → 闲家上台（80–119 只上台）；**120/160** → 再各升 1 级
- 所以 **40 / 80 / 120 / 160** 是四个"悬崖"，是音乐该起反应的四个点
- 另有两个天然戏剧点：**第 25 墩（最后一墩）**、**分差 ≤ 10 的最后几墩**

### 2.2 九个场景与 BGM 映射

| 编号 | 场景 | 触发条件 | 情绪目标 | BGM 处理 |
|---|---|---|---|---|
| **S1** | 定主 · 发牌 | `phase === 'contract'` | 期待 / 悬念 | 慢（62）、最疏；只有 pad + 每 2 拍一个拨弦；**抢主/反主成功时叠一段 1–2 小节音乐刺** |
| **S2** | 埋底 | `phase === 'bury'` | 思考 / 安静 | 与 S1 同基底，密度再降一档（只留 pad + 动机长音） |
| **S3** | 出牌 · 平稳 | `play`，tension < 0.4 | 中性 / 耐久 | 基准曲（76 BPM）：拨弦分解 + 钢琴动机 + 轻沙锤 |
| **S4** | 出牌 · 绷紧 | tension 0.4–0.75 | 绷紧但不打断思考 | 同曲**加密 + 降 1–2 度 + 亮度降 + 低音加重**（不换曲） |
| **S5** | 出牌 · 决胜 | tension > 0.75（最后 3 墩 / 分差 ≤10 / 闲家分 ≥120） | 冲刺 | S4 + 提速 8% + 加打击层 + 去掉长音 |
| **S6** | 本局结算 | `phase === 'settle'` | 收束 | 4 小节终止句，两版：庄家继续 / 闲家上台 |
| **S7** | 终局 · 胜 | `over` 且我方赢 | 明亮释放 | 大调终止 + 上行 5 音 |
| **S8** | 终局 · 负 | `over` 且我方输 | 落幕 | 小调下行 + 渐弱 + 混响拉长 |
| **S9** | 逐墩回放 | `replayAt !== null` | 怀旧 / 让位 | 只 pad + 极稀疏拨弦（要能听清"复盘"） |

> **实现上不建 9 个场景**：S1/S2/S9 共用一个 `calm` 基底，S3/S4/S5 是**同一个 `play` 基底 + 一个连续 `tension` 参数**，S6/S7/S8 是短终止句（不循环）。
> 这样音乐**永远不会因为分数跳动而硬切**——这正是参考实现最值钱的思想：**场景是参数集，不是曲目**。

### 2.3 连续紧张度（替代"切场景"）

```
tension = 0.50 * min(1, 闲家得分 / 160)        // 分数压力（160 封顶）
        + 0.30 * (1 - 剩余墩数 / 25)            // 越接近结尾越紧
        + 0.20 * min(1, 本墩已出分 / 40)        // 这一墩"值不值钱"
```

- 每帧向目标值 lerp 0.05（约 1 秒收敛），避免突变
- tension 映射到：`dens`（加花概率）、`bright`（低通）、`tp`（0 → -2 半音）、`bpm`（+0~8%）、`pad` 量
- **tension 只影响"演奏方式"，不改旋律本身** ⇒ 同一条动机听起来是"同一首曲子在变紧"

### 2.4 事件型"音乐刺"（不换场景）

以下时刻在 BGM 之上叠 1–2 小节的短句，用完即回（复用参考实现的 `lastEventBar` 机制）：

| 事件 | 音乐刺 |
|---|---|
| 亮主 | 上行 3 音琶音（I–III–V）+ 亮音色 |
| 反主 | 上行 4 音 + 升半音（戏剧性） |
| 加固 | 金属"锁"声 + 低音 thud（无调性） |
| 赢大墩（≥20 分） | 2 音上行 + 短衰减 |
| 升级 / 上台 | 5 音上行 + 打击 |
| 打王级终局 | 全奏 2 小节终止 |

## 3. 音乐设计（一条核心动机）

### 3.1 动机（草案，可直接试听调整）

**A 小调五声：A C D E G**（选五声的理由：同一批音在**大调与小调两套和声下都成立**，
所以"变紧/变亮"只换和弦不改旋律 —— 这是能"一条旋律走全场"的技术前提）

```
第 1 小节  A4(1)  C5(.5) D5(.5) E5(1.5)          ← 起句：上行，停在 E（悬）
第 2 小节  G5(1)  E5(.5) D5(.5) C5(2)            ← 落句：回 C
第 3 小节  A4(1)  C5(.5) D5(.5) E5(1)  G5(1)     ← 抬高：全曲最高点
第 4 小节  E5(2)  D5(1)  A4(1)                   ← 收束：留半拍空，无缝循环
```

- 8 小节版本 = 动机 + 变奏 + 动机再现（第 7 小节严格模进，学参考实现）
- 时长：76 BPM × 4 小节 ≈ **12.6 秒**一轮；8 小节 ≈ 25 秒

### 3.2 三个基底编排

| 基底 | BPM | 层配比 | 用途 |
|---|---|---|---|
| `calm` | 62 | pad 0.30 + 拨弦 0.45（每 2 拍）+ 动机长音化（时值 ×2） | S1 / S2 / S9 |
| `play` | 76 | 拨弦分解 0.85 + 钢琴动机 1.0 + 沙锤 0.15 + pad 0.18 | S3 / S4 / S5 |
| `settle` | 92 | 钢琴 1.0 + 明亮拨弦 0.6 + 短终止（4 小节后停） | S6 / S7 / S8 |

### 3.3 和声进行

| 用途 | 进行 |
|---|---|
| calm / play | **i – VI – III – VII**（Am – F – C – G） |
| settle 胜 | **I – V – vi – IV**（C – G – Am – F） |
| settle 负 | **i – VII – VI – V**（Am – G – F – E） |

> 注意：`E` 是 A 小调的属和弦，含 G#，与五声音阶的 G 冲突 —— 所以失败版把旋律的 G 降到 F 或改用 E 的挂留（Gsus4），实现时按"避免半音打架"处理。

### 3.4 音色（两个方案，待选）

| 方案 | 编制 | 优点 | 风险 |
|---|---|---|---|
| **A（推荐先做）** | 拨弦吉他（Karplus-Strong）+ 加法钢琴 + 长笛 + 沙锤 + pad | 参考实现已验证，成熟、暖、不刺耳 | 略"咖啡馆"，与牌桌气质有点距离 |
| **B（主题皮肤）** | 古筝式拨弦 + 木鱼/沙锤 + 笛 + 低音 pad | 更贴"牌桌/民间" | 需重新调音色，工作量 +1 档 |

**建议**：先做 A 把链路跑通，B 作为可切换的"音色主题"后加（架构上留 `theme` 参数即可）。

## 4. 音效设计

### 4.1 四条原则

1. **即时、不量化**：音效必须立刻响（它是操作反馈），**绝不跟拍子对齐**
2. **音高跟调**：音高从当前场景的 `root + scale` 取 ⇒ 场景一变，全部音效自动变调，且永远在调上
3. **轮转不重复**：同一事件连续触发时，音级按 scale 轮转（**确定性计数**，不用随机）
4. **密度抑制**：同一音效 60–120ms 内不重复；发牌这种高频事件**降频**

### 4.2 音效清单（12 个）

| 事件 | 触发 | 合成配方 | 音高 | 时长 |
|---|---|---|---|---|
| **发牌 tick** | 每 **4 张**一次（不是每张！55ms/张 ⇒ 逐张会像机关枪） | 噪声 burst → 带通 3kHz | 无调性 | 15ms |
| **选牌** | 点击手牌 | 方波 2kHz + 5ms 包络 | 当前调 **V 级** | 20ms |
| **取消选牌** | 再点一次 | 同音色，下降 2 度 | **III 级** | 20ms |
| **出牌 whoosh** | 出牌（**与 280ms 飞行动画同步**） | 噪声 → 带通扫频 800→3kHz + 40ms 包络 | **根音（低八度）** | 280ms |
| **赢墩** | 本墩结算且我方赢 | 2 音上行 + 短衰减 | **I → V** | 180ms |
| **输墩** | 本墩结算且对方赢 | 单音 + 低通闷（LP 1.2k） | **V → IV** | 150ms |
| **亮主** | `trumpDeclarer` 变化（首次） | 3 音琶音 + 亮音色（LP 8k） | **I–III–V** | 260ms |
| **反主** | `usedTrumps` 增长 | 4 音琶音 + 金属泛音 | **升半音**（戏剧性） | 320ms |
| **加固** | `trumpCount` 抬到 2 | 金属 click + 低频 thud（120Hz） | 无调性 + 低音 | 200ms |
| **埋底** | `finishBury` | 低频"放置"（120Hz + 短噪声） | **根音低八度** | 160ms |
| **升级/降级** | `settle` | 上行/下行 5 音 | 当前调音阶 | 400ms |
| **按钮 / 弹层** | 顶栏、面板 | 极轻 click | 无调性 | 12ms |

### 4.3 "变调"的具体机制

```
sfxPitch(event, scene, counter) = scene.root + scene.scale[轮转下标]
```

- **场景切 → root/scale 变 → 所有音效整体变调**（这就是你要的"根据场景变调"）
- **轮转**：同一事件第 1 次用 I、第 2 次 V、第 3 次 III、第 4 次回 I —— 连续出 4 张牌不会听到同一个音
- 戏剧点（亮主/反主/升级）**不走轮转**，固定用琶音，保证辨识度

### 4.4 场景 → 音效参数映射

| 场景 | root | scale | 亮度（LP） | 衰减 | 说明 |
|---|---|---|---|---|---|
| `calm` | A2 | 小五声 | 2.5 kHz | 0.35s | 闷、长、退到背景 |
| `play` | D3 | 大五声 | 5 kHz | 0.20s | 中性 |
| `play` + tension 高 | D3 −2 半音 | 小五声 | 8 kHz | 0.10s | 亮、短、刺一点 |
| `settle` | C3 | 大调 | 6 kHz | 0.25s | 明亮收束 |

> **最关键的一条耦合**：BGM 与 SFX **共用同一份 `root + scale`**。
> 只要 BGM 换调，音效自动跟着换 —— 两者永远不会"打架跑调"。

### 4.5 上下文变奏（进一步防"千篇一律"）

同一事件按上下文微调音色/力度：

| 上下文 | 变化 |
|---|---|
| 出牌者是庄家 | 音高降八度、力度 +20%（"分量"） |
| 出的牌带分（5/10/K） | 叠一个高八度的钟琴泛音 |
| 甩牌成功 | 加一个短促的"哗"（噪声扫频） |
| 最后一墩 | 音高升 5 度、衰减 ×0.6（收尾感） |
| 回放中 | 所有音效降 -6dB、去掉 whoosh（避免与"听牌"抢） |

## 5. 架构（怎么落进项目）

### 5.1 目录

```
src/audio/
  engine.ts    AudioContext 生命周期 / 总线 / 混响 / 压缩 / ducking / suspend-resume
  synth.ts     音色：拨弦(Karplus-Strong) / 加法钢琴 / 笛 / 沙锤 / pad / 噪声
  sfx.ts       音效表 + 触发 + 音级轮转 + 密度抑制
  music.ts     调度器（40ms 轮询 + 0.45s 前瞻 + 卡顿保护）+ 每小节编排
  scenes.ts    场景/基底/和弦/动机/参数表（纯数据）
  index.ts     门面：init / start / stop / setScene / setTension / playSfx / setVolume
```

### 5.2 触发点（不改 `core` / `app`）

`main.ts` 已有「前后帧 diff」模式（`captureFx` / `trackPlayFx`）—— **音频用同一套**：

```ts
trackAudio(prevState, nextState)   // 在 paint() 里跟 trackPlayFx 并排调用
```

| 声音 | 从哪个状态变化判断 |
|---|---|
| 发牌 tick | `revealed` +1（且每 4 张才响） |
| 出牌 whoosh | `trick.plays.length` +1 |
| 赢墩 / 输墩 | `history.length` +1（看 `winner` 属于哪队） |
| 亮主 / 反主 / 加固 | `trumpDeclarer` / `usedTrumps` / `trumpCount` 变化 |
| 埋底 | `phase` 从 `bury` → `play` |
| 结算 / 终局 | `phase` → `settle` / `over` |
| 场景与 tension | `phase` + `defenderScore` + `tricksDone`（纯函数 `sceneOf(s)` / `tensionOf(s)`） |

> 这样 `core`/`app` 一行都不用改，音频纯粹是"观察者"。

### 5.3 设置项（新增 3 个，进 `prefs`）

| 设置 | 默认 | 说明 |
|---|---|---|
| `soundOn` | **开** | 总开关；关掉后不创建 AudioContext（省电） |
| `bgmVolume` | 50 | 0–100 |
| `sfxVolume` | 70 | 0–100 |

- 顶栏加一个 🔊 按钮（一键静音）+ 设置面板「声音」分组两条滑条
- 首次手势起播：任意点击 → `ensureStarted()`（Android/iOS 都需要）

### 5.4 生命周期与性能

- `visibilitychange` → `ctx.suspend()` / `resume()`（**现在项目里没有这个处理**，顺带补上）
- 同时发声节点上限：BGM ≤ 24、SFX ≤ 6；超出丢弃最轻的
- 出音效时 BGM 侧链压 2–3dB、80ms 恢复（避免抢频段）
- 停止 = `ctx.close()`；下次启动重建（参考实现实测：音频图 7ms + 拨弦缓冲 57ms）

### 5.5 测试策略

| 层 | 怎么测 |
|---|---|
| **纯函数**（可单测） | `sceneOf(s)` / `tensionOf(s)` / `sfxParams(name, scene, counter)` / `musicParams(scene, tension)` |
| **音频节点** | 不可单测，只在浏览器验：e2e 加一条「点牌后 `AudioContext.state === 'running'`」 |
| **覆盖率** | `src/audio/` 纳入统计，靠纯函数撑过门槛（同 `ui/fxDiff` 的思路） |

## 7. 风险与取舍

| 风险 | 对策 |
|---|---|
| **听觉疲劳**（一局约 100 次出牌 + 33 次发牌） | 音效极短（12–280ms）、音量低于 BGM、轮转音高、密度抑制、发牌降频 |
| BGM 与 SFX 抢频段 | 侧链 ducking（出音效压 BGM 2–3dB / 80ms） |
| **动机不好听 ⇒ 全盘皆输** | 先只做 1 条动机，单独试听、可整条替换；旋律/和弦与代码解耦（纯数据表） |
| iOS 自动播放 | 手势后 `resume()`；`soundOn` 关时不创建 ctx |
| 移动端 CPU / 耗电 | 节点上限、页面隐藏 suspend、音色只用 3–4 种 |
| 音乐与动画速度混淆 | BGM 速度属音乐参数，**不跟 `animSpeed`**（两者独立） |

## 8. 待你拍板的 5 个决策

1. **音色风格**：A 西式（拨弦吉他 + 钢琴 + 笛，参考实现已验证）／ B 中式牌桌（古筝式拨弦 + 木鱼 + 笛）
2. **BGM 默认开还是关**（我建议开、音量 50%；音效默认开、70%）
3. **回放要不要 BGM**（我建议极简版：只 pad，音量再降 6dB）
4. **音效密度**：保守（只关键事件：出牌/赢墩/亮主/结算）／ 丰富（每个操作都有，含选牌、按钮）
5. **终局要不要胜负两版**（我建议要，成本很低——同一终止句换和声）
