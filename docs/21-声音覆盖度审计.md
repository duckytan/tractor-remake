# 声音覆盖度审计：演示页 vs 游戏真实需求

> 审计对象：`docs/demo/sound-demo.html`（v11）
> 审计方法：**从游戏源码枚举声音事件**，不靠想象。依据 `src/app/state.ts` 的 `Action` 联合类型
> （37 个动作）、`Phase` 枚举、`src/app/game.ts` 里的 `notice` 赋值点、`core/settle.ts` 的
> 结算分支，以及 `docs/18` §2.1 已核准的对局结构。
>
> 结论先说：**BGM 侧基本够用，事件音效侧缺口明显，框架侧（生命周期/设置/回放）完全没做。**

## 3. 缺口分级与建议

### P0 · 必须补（缺了会明显"不像成品"）

| 缺口 | 为什么是 P0 | 建议做法 |
|---|---|---|
| **甩牌被压回**（P4） | 规则惩罚事件，**玩家必须立刻知道"我甩的牌被压回来了"**，否则以为程序出错 | 下行小二度 + 短促噪声，比 `lose` 更"挫败"但更短（0.18s） |
| **非法出牌**（P5） | 同上，是操作反馈的底线 | 低频方波"哔"两声（0.08s ×2），音高固定不跟调（要"机械"感） |
| **终局胜负两版**（O1/O2） | 一局的情绪落点，只有一版等于没有高潮 | 胜：大调终止 + 上行五音 + 混响拉满；负：小调下行 + 渐弱 + 只留 pad |
| **结算区分"升几级"**（S2/S3/S4） | 玩家靠声音判断结果，一个 `levelup` 表达不了"升 3 级"和"闲家上台" | 用**音数**表达：升 1 级 = 1 个上行音，升 2 = 2 个，升 3 = 3 个；上台 = 换和弦色彩 |
| **回放场景**（R1–R4） | 回放时 BGM 照常跑会干扰"复盘" | `replayAt !== null` → 只留 pad + 音量 −6dB |

### P1 · 重要（提升质感）

| 缺口 | 建议做法 |
|---|---|
| **发牌 tick 降频**（C1） | 33 张 × 55ms ⇒ **每 4 张一次**（约 440ms 一次）。逐张响会像机关枪 |
| **我方 vs AI 出牌区分**（P2） | 我方：音高 +2 度、音量 +15%、pan 居中；AI：按座位 pan（左 −0.5 / 右 +0.5 / 对面 0）、音量 −20% |
| **自己摸到级牌**（C3） | 发牌暂停那一刻给一个"叮"（比 `select` 亮一档），提示玩家"该决定了" |
| **最后一墩**（P8） | 判定看「四家手牌将空」（**不是固定第 25 墩**，对子/拖拉机一墩耗多张）；开打时 BGM 去掉长音层 + 加低频心跳 |
| **得分悬崖**（P9） | 40/80/120/160 各一个"落石"音（低频 + 短混响），**这是全曲最有戏剧性的四个点** |
| **悔牌撤回**（P11） | 反相 whoosh（噪声扫频从高到低），和出牌的从低到高相反 |
| **选够 8 张**（B3） | 埋底选够时一个确认"嗒"，让玩家知道可以按了 |
| **抢庄**（C5） | 抢庄成功比普通亮主多一个上行三音（"抢到了"） |

### P2 · 细节（体验加分）

| 缺口 | 建议做法 |
|---|---|
| **座位声像**（SFX 全在中间） | 4 家出牌 pan 到各自方位；只做 L/R 两档也够（−0.45 / +0.45） |
| **切后台自动 suspend**（F2） | `visibilitychange` → `ctx.suspend()`，回来 `resume()` |
| **音量持久化**（F6） | 存 `localStorage`，和 `persist.ts` 的其他设置放一起 |
| **静音快捷键**（F7） | `M` 键切总静音，`Esc` 关闭设置时也静音 |
| **全局并发上限** | 现在只有 70ms 同事件抑制；一墩里 4 家连出会叠，加"同时最多 3 个事件音" |
| **无障碍** | 尊重 `prefers-reduced-motion` 的思路，给一个"减少音效"开关 |

### P3 · 架构（正式版必须做，演示不必）

| 项 | 说明 |
|---|---|
| 拆成 `src/audio/` | 演示是单文件；正式版按 `docs/18` §5.1 拆 6 个文件 |
| **不侵入 core/app** | 用 `main.ts` 已有的前后帧 diff（`captureFx` / `trackPlayFx`）作唯一观测点，`core`/`app` 一行不改 |
| 只用原生引擎 | Tone.js 349KB 只为对照，正式版删掉 |
| 移动端解锁 | 首次 `touchstart` 再 `ctx.resume()`（iOS 更严） |

## 4. 结论

### 能直接用的部分

- **BGM 引擎**：四主题 + 8 情绪预设 + 变奏 + 力度呼吸 + 分轨，这套**可以直接搬进 `src/audio/`**。
- **音色库**：12 种（钢琴 7 层泛音、FM 电钢、Karplus 吉他、长笛、马林巴、钢片琴、八音盒、颤音琴、竖琴），够用。
- **12 个基础音效**：发牌/选牌/出牌/赢墩/输墩/亮主/反主/加固/埋底/升级/按钮，骨架是完整的。

### 不能直接用的部分

- **它不是"游戏的完整声音层"**，是"BGM + 音效素材库 + 可听性验证台"。
- **28 个事件没有对应声音**，其中 5 个是 P0（甩牌失败、非法出牌、终局胜负、结算级数、回放）。
- **没有接线**：演示里音效是"点按钮"，正式版必须接到真实 dispatch 上。

### 建议的下一步

1. **先补 P0 的 5 项**（约 5 个音效 + 2 个 BGM 分支），演示里就能听到。
2. 补完后**做一次"完整一局"的模拟**：从发牌到终局，按真实时序触发，听有没有"哑点"。
3. P1 的发牌降频和座位声像，在接线时一起做（这两条不改代码结构，但影响很大）。
4. 接线时严格按 `docs/18` §5.2：`main.ts` 的 fx diff 是唯一观测点，`core`/`app` 不动。

### 5.3b 两套播放系统独立开关（v13）

用户要求：「音乐开关不打开，就无法播放音效，能不能做成两套播放系统，有独立的开关，互不干扰」。

**问题**：原来 `sfx()` 里写着 `if (!ctx || !playing) return;` —— `playing` 是 BGM 调度器的开关，
于是「不开 BGM 就没有音效」。这是把两件事耦合在了一个布尔量上。

**改法**：拆成两个独立状态，共用同一个 `AudioContext`。

| 状态 | 含义 | 谁读它 |
|---|---|---|
| `bgmOn` | BGM 调度器是否在跑 | `scheduler()`、`startBgm`/`stopBgm` |
| `sfxOn` | 音效是否允许触发 | `sfx()`、所有音效按钮 |

- `ensureAudio()` 懒创建音频图：谁先需要谁创建（BGM 或音效任一先触发）
- `syncAudioState()` 有一方在用就 `resume`，两边都关才 `suspend`
- `stopBgm()` **不关上下文**（音效可能还在用），只停调度器；已排出的音（≤0.45s 前瞻）自然收尾，比硬切干净

**为什么不真开两个 AudioContext**：浏览器对同时存在的上下文数量有限制（Chrome 约 6 个），
而且两个上下文的时间轴不同步。共用一个上下文 + 两条独立链路，**行为上就是两套系统**，
但成本更低、时序一致。

**实测**（用 `createOscillator` 计数，比听感更准）：

| 状态 | 点一下音效新建的振荡器 |
|---|---|
| 音效开 | 1 |
| 音效关 | **0** |
| BGM 开 + 音效关 | **0** |
