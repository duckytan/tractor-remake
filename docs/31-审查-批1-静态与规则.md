> 按 docs/30 v2 优先级矩阵，批 1 的 6 项各派一个 **sub agent 隔离审查**：

> 6 个 agent 全部只读，`git status src` 干净。

## 2. P1 问题（必修）

### P1-1｜重开游戏会静默丢掉 8 个设置（I5-01）

`newGame` 与 `over → nextRound` 走 `emptyBase()` 的默认值，而 `withExperience()` 只搬运 5 个体验项。

| 丢失字段 | 用户可见后果 |
|---|---|
| `musicTheme` | 切到「冬」再点「新游戏」→ 变回「春」 |
| `soundEnhanced` | 增强音效自动关 |
| `autoVariation` | 自动变奏恢复默认 |
| `volumeMaster/Bgm/Sfx` | 音量全部回 75/40/80 |
| `animSpeed` | 动画速度回默认 |
| `showCounter` | 记牌器自动关 |

更糟：`afterChange()` 随后把 state 里的**默认值回写 localStorage** —— **刷新也救不回**。

### P1-2｜两份 56 字段的初始化字面量（J1-2）—— 这是 P1-1 的根因

```
emptyState  src/app/state.ts:293   字段数=56
emptyBase   src/app/game.ts:473    字段数=56
键集完全一致、取值当前完全等价，只有书写顺序不同
```

生产用 `emptyBase`，但 4 个测试文件（dealing / declare / view / counter）用 `emptyState` 搭基线
⇒ **测试覆盖的是另一条构造路径**。改 `GameState` 默认值时改一处不会报错。

讽刺的是 `emptyBase` 自己的注释写着「以前这里手抄了一份字面量，加规则开关时必漏改」，
而它旁边就躺着第二份手抄。

### P1-3｜`AudioContext` 没有回收点（J1-7）

`AudioHandle` 8 个成员中 **`stop` / `dispose` / `playSfx` / `running` 生产从未调用**。
`dispose()` 只出现在文档注释里。文件头承诺的卸载路径是空的。

### P1-4｜声音试听面板整块 UI 没移植（J1-11）

`INST_LABEL` / `SFX_ORDER` / `SFX.label`（20+ 条文案）从未被读。
原型页 `docs/demo/sound-demo.html:1918` 里这个面板是存在的 ⇒ **移植时漏了 UI**。

### P1-5｜`src/ai/index.ts` 整个文件是孤岛（J1-12）

`docs/07 §2` 明令「外部只能从 index.ts 导入」，但所有消费方都直接 `@ai/enumerate` / `@ai/policy`。
barrel 编译进产物却永远不执行。**同样的约定在 core 生效、在 ai/app/ui 全部失效。**

### P1-6｜多个「本该调用却被内联重写」（J1-3~8）

| 规则函数 | 生产绕过次数 |
|---|---|
| `isSameTeam` | **8 处**手写 `teamOf(a) === teamOf(b)` |
| `cardValueOf` | 内联 `suit * 13 + rank` |
| `isHumanTurn` | 3 处手写取反 |
| `dealerTeam` | `render.ts` 用 `teamOf` 重新拼 |

不是 bug，但**规则一旦变就要改 N 处**。

## 4. 两处自我纠正（重要）

### 纠正 1：抠底 ×8 是**对的**，我上一轮判错了

docs/36 §H1-4 我写「smallnest 没有抠底，只能按社区 ⇒ 3 连对应 ×16」。

**错**：agent 5 查到 smallnest **有**抠底，就在 `TractorRules.cs:618-638`：

```csharp
int howmany = 2;
if (CP.HasTractors())        howmany = 8;   // 任何拖拉机都是 8，不看长度
else if (CP.GetPairs().Count > 0) howmany = 4;
else                         howmany = 2;
```

它自带的规则文档 `Help/Html/游戏规则/抠底规则.html` 更是逐字写着：
> 「以拖拉机抠底时底牌分数乘**八**。」

**我上一轮只 grep 了 `TractorRules.cs` 里的「底牌/bottom」，没找到 `Calculate8CardsScore`，就下了结论。**

按用户拍板的裁决优先级（**smallnest > 原版 > 社区**），**×8 是正确的，不该改**。

社区主流确实是 2^(n+1)，但那只是「社区」，优先级低于 smallnest。

### 纠正 2：`trick.winner` 的注释写错了

我在 v1.3.24 标注「这个字段从没被赋过值」—— **不准确**。
`game.ts:949` 会把上一墩赢家写进去。它比 `null` 更危险：值永远是「上一墩的赢家」，
任何人以后拿它做高亮都会显示一个**看似合理但错位**的赢家。

## 5. 交叉印证（隔离审查的价值）

| 现象 | 两个 agent 各自发现 | 合起来才看清 |
|---|---|---|
| 8 个设置字段丢失 | I5 从「字段读写统计」发现 | |
| 两份 56 字段初始化字面量 | J1 从「死代码扫描」发现 | **后者是前者的根因** |

单独看 I5，只能知道「字段丢了」；单独看 J1，只能知道「有两份重复字面量」。
两个 agent 互相看不到对方结论，却指向同一个根因 —— 这是隔离审查最有价值的地方。
