## 2. 按「根因」归并：42 项问题其实只有 8 个根

这是本次审查最重要的产出 —— 逐条修 42 个症状是错的，改 8 个根才对。

### 根因 ①：`loadState` 几乎不校验存档（**影响 6 项，最高性价比**）

| 条目 | 现象 |
|---|---|
| C4-01 | 只校验 3 个条件，43 字段裸奔 → 字段不全的存档首帧崩、白屏且无法自愈 |
| C4-02 | `phase` 非法/`null` 能载入 → 之后**所有 action 都是空操作**，只有 `newGame` 能救 |
| C4-03 | 手牌元素形状不校验 → 渲染路径抛 `牌值越界` |
| C3-01 | 缺 `pendingConfig` → 载入不报错，**换局后 `config` 变 `undefined`，下次 `ctxOf` 崩** |
| G-1（入口侧） | 数字字段可被塞成 HTML 字符串 → 拼进 `innerHTML` 后**执行脚本** |
| G-3 | 篡改牌值 → `pageerror: PowerTable.get: 牌值越界 undefined` |

**一处修复**：`loadState` 加「字段级 schema 校验」—— 数字字段 `typeof === 'number' && Number.isFinite`，枚举字段必须在白名单内，数组长度与元素形状校验，任一不符就**整份丢弃回落 `emptyState()`**（`loadPrefs` 已经是这么做的，照着抄即可，见 `docs/33` §4 的 C3 通过项）。

---

### 根因 ②：`render()` 每次状态变化整棵重建 DOM（**影响 5 项**）

| 条目 | 现象 |
|---|---|
| D-1 | 单次操作同步 P50 **17.6ms** > 一帧预算 16.7ms；4× 节流下 P50 92.8ms、14 次长任务 |
| D-3 | 一次「四色」点击 = 71 次 `innerHTML` / 72KB / 1079 节点（骨架 + 逐槽填充） |
| D-4 | 单次操作 46~76 次 `getBoundingClientRect`，全局 2146 次 / 628ms |
| **E-2** | 键盘选牌后**焦点掉到 `BODY`**，再按 Enter 不能取消选中 |
| E-7 | 横屏 844×390 首屏滑条被裁在面板下沿（部分点击打到遮罩） |

**修复顺序**（不要一次重构）：
1. **选牌不重建**（最高频、收益最大、改动最小）：`selected` 变化只切 `.card.is-sel` 类 → 同时解决 E-2 的焦点丢失。
2. 骨架只在首次挂载 / 阶段切换时重建，同阶段内只更新槽位。
3. 弹层打开时冻结牌桌 DOM。
4. 同一帧的 `rect` 读取集中到「读阶段」并缓存。

---

### 根因 ③：全局 `Space` 键劫持（影响 2 项）

`src/main.ts:365-367` 无条件 `preventDefault()` + `playSelected()`，不判断焦点。

| 条目 | 现象 |
|---|---|
| E-1 | 焦点在顶栏按钮 / 设置开关上按 Space **完全无效**（Enter 正常） |
| E-5 相关 | 键盘用户因此只能靠 Tab+Enter，而 Tab 序列长（手牌 25 张），体验极差 |

**修复**：`ev.target` 是 `button` / `[role=switch]` / `[role=tab]` / `input` / `select` / `a[href]` 时直接 return。

---

### 根因 ④：AI 首出评分的「王牌定价」错了（影响 3 项）

`powerCost/(cards.length*80)` 让大王只值 **0.75**，而 L3 的 `exactOver = 1.15` + `followUp = 0.35`。

| 条目 | 现象 |
|---|---|
| B-1 [P0] | L3 首出王 **11.8%**（L2 仅 1.6%，24 局完全一致） |
| B-3 [P1] | L1 首出「手里最小牌」**53.2%**（首出评分实际只有省牌一项在起作用） |
| B-4 [P1] | L3 该毙不毙 12 处 vs L2 1 处（`controlLoss` 压过了「赢 10 分」） |

**修复**：给王/级牌单独加「留存价值」项（如 `-0.35 * isJoker`），并把 `powerCost` 改成按牌力分位计价。
**必须重跑座位互换配对标定**（`docs/23` 的方法），否则可能只是把 11.8% 挪到别处。

### 根因 ⑤：AI 能力缺口 —— 不会甩牌（影响 2 项）

| 条目 | 现象 |
|---|---|
| B-2 [P0] | `enumerateLeads` 只产单张/对子/连对，**无多组混出分支**；人类甩 5 张，AI 一张张出 |
| B-7 [P2] | `enumerateFollows` 对 `suitSlot === -1` 直接 `return []`；`decide()` 兜底分支（`policy.ts:393-404`）在 `slot === -1` 时比较器恒返回 1 且不校验结构 → **定时炸弹** |

**修复**：`enumerateLeads` 加「同槽多组」分支（按组组合 2~3 组，用 `checkLead` + 真实对手手牌校验），**同时**把兜底分支改成「逐个 `checkPlay` 试，取第一个合法」。

---

### 根因 ⑥：状态机缺「防御性兜底」（影响 5 项）

| 条目 | 现象 |
|---|---|
| C6-01 [P1] | 某人 0 张手牌且轮到他 → `aiStep` **无限空转**，`phase` 永远停在 `play` |
| C6-02 [P1] | 存档少 1 张牌 → 打 800 步也不结算 |
| C1-01 [P2] | `checkPlay` 的 `opponents` 缺省 `[]` ⇒ **甩牌校验恒放行** |
| C1-03 [P2] | NaN 载荷静默写入非法值（`setVolume` / `setAiSpeed` / `replayStep`） |
| C6-03 [P2] | 同一座位在一墩里出两次牌 → 凑满 4 张后**静默结算出非法赢家** |

**修复**：① 出牌前校验「该座位手牌非空」；② 每墩结算后校验「四家出牌数 == 1 且座位互异」；③ 数值 action 参数做 `Number.isFinite` 校验；④ `opponents` 缺省改为「必传」并让 TS 强制。

### 根因 ⑦：悔牌快照含全部 56 字段（影响 2 项）

| C5-01 [P2] | 「出牌 → 改设置 → 悔牌」把四色/音量/主题/尺寸/AI 档位/规则一起退回，且 `afterChange()` **写回 localStorage** ⇒ 用户刚改的设置被永久抹掉 |

**修复**：快照只存「对局字段」，排除 `PREF_FIELDS`（v1.3.28 刚建立的清单可直接复用）；`canUndo` 加 `replayAt === null` 条件。

### 一处审查结论需要纠正

`docs/37` 的 **E-5「`.switch` 没有 `:focus-visible`」是误判** ——
`styles.css:948` 本来就有该规则。E4 脚本用「鼠标点击后 programmatic focus」，
Chromium 在这种情况不会匹配 `:focus-visible`。用真实 Tab 复验后确认规则生效，
所以 F3 只补了 `.btn` 的焦点框（浏览器默认 `auto 1px` 在深绿顶栏上几乎看不见）。

### 两处判据本身有假阳性（已修，教训记入 `scripts/dump-ai-round.ts` 注释）

- **B3「该毙不毙」**：原来只要「缺门 + 有主牌 + 分≥10 + 出非主牌」就算失误，
  没验证「毙了是否真能赢」。手里只剩小主牌、对手还有更大主时，「不毙」是**正确**判断。
  补上「存在能赢的毙牌候选」后，L3 的 6 处「聪明弃牌」不再被误判。
- **失误率用「墩」做分母**：甩牌/对子会让一墩吃多张牌，墩数在 19~25 之间浮动，
  同样的失误数会算出不同比率。改用**每局失误数**（L2 1.06 / L3 0.85）。
